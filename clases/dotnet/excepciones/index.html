Manejo Total de Excepciones en .NET

Aprende a controlar errores en tiempo de ejecución, resguardar la lógica de negocio, crear excepciones personalizadas y entender cada término clave utilizado en el ecosistema C# y ASP.NET Core MVC.

1. Diccionario de Términos Términos Básicos y Avanzados

Para dominar las excepciones en C#, primero debemos hablar el mismo idioma técnico:

Excepción (Exception)
Un objeto especial en C# que se crea automáticamente cuando el flujo normal del programa falla en tiempo de ejecución.
throw
Instrucción que interrumpe intencionalmente el programa y "lanza" una excepción cuando se detecta un error o dato no válido.
try
Bloque de código que "sometes a prueba". Si ocurre un error dentro de él, no tumba la aplicación, sino que lo transfiere al bloque catch.
catch
Bloque que intercepta ("atrapa") la excepción lanzada por el bloque try para procesarla o mostrar un mensaje.
finally
Bloque especial que SIEMPRE se ejecuta, haya ocurrido un error o no. Ideal para liberar recursos (cerrar archivos o conexiones).
Stack Trace
Rastro de llamadas que muestra la ruta exacta de métodos y líneas de código por las que viajó el error hasta explotar.
InnerException
Propiedad de una excepción que guarda el error original que provocó la excepción actual (útil en excepciones compuestas).
Rethrow (throw;)
Volver a lanzar la excepción dentro de un catch manteniendo intacto el Stack Trace original.

2. El Ciclo de Vida: try - catch - finally

Esta es la estructura completa con múltiples bloques catch ordenados de lo más específico a lo más general:

using System;

public class CalculadoraServicio
{
    public decimal ProcesarPago(string montoTexto, string tarjeta)
    {
        try
        {
            // 1. Intentamos convertir el texto a número (Puede lanzar FormatException)
            decimal monto = decimal.Parse(montoTexto);

            // 2. Validamos la regla de negocio (Lanzamos ArgumentOutOfRangeException)
            if (monto <= 0)
            {
                throw new ArgumentOutOfRangeException(nameof(montoTexto), "El monto debe ser mayor a cero.");
            }

            return monto;
        }
        catch (FormatException ex)
        {
            // Atrapa solo errores de formato numérico
            Console.WriteLine($"Error de conversión: {ex.Message}");
            return 0;
        }
        catch (ArgumentOutOfRangeException ex)
        {
            // Atrapa errores de rangos o límites inválidos
            Console.WriteLine($"Regla de negocio violada: {ex.Message}");
            return 0;
        }
        catch (Exception ex)
        {
            // Atrapa CUALQUIER otro error no previsto anteriormente
            Console.WriteLine($"Error crítico no esperado: {ex.Message}");
            throw; // Re-lanzamos preservando la pila de llamadas
        }
        finally
        {
            // ESTO SE EJECUTA SIEMPRE (haya o no haya error)
            Console.WriteLine("Proceso de pago finalizado. Liberando memoria...");
        }
    }
}

3. Catálogo de Excepciones Frecuentes en .NET

Excepción ¿Cuándo ocurre o cuándo usarla?
ArgumentNullException Cuando un método requiere un valor obligatorio y recibe null.
ArgumentException Cuando un argumento es válido en tipo, pero no cumple las reglas del método.
InvalidOperationException Lanzada cuando el estado actual de un objeto impide ejecutar una acción.
NullReferenceException Lanzada automáticamente por .NET al intentar acceder a propiedades de algo que es null.
KeyNotFoundException Al intentar buscar un elemento en un Diccionario usando una clave inexistente.

4. Excepciones Personalizadas (Custom Exceptions)

Para un sistema empresarial profesional, es recomendable crear tus propias excepciones de dominio heredando de la clase base Exception: 

// 1. Definimos nuestra propia clase de excepción
public class SaldoInsuficienteException : Exception
{
    public decimal SaldoActual { get; }

    public SaldoInsuficienteException(decimal saldoActual) 
        : base($"Operación rechazada. Saldo actual insuficiente (${saldoActual}).")
    {
        SaldoActual = saldoActual;
    }
}

// 2. Uso en el dominio / POO
public class CuentaBancaria
{
    public decimal Saldo { get; private set; } = 100;

    public void Retirar(decimal cantidad)
    {
        if (cantidad > Saldo)
        {
            // Lanzamos nuestra propia excepción
            throw new SaldoInsuficienteException(Saldo);
        }

        Saldo -= cantidad;
    }
}

5. Aplicación Práctica en ASP.NET Core MVC

A continuación verás cómo se orquesta una excepción personalizada dentro del flujo Controlador-Vista: 

using Microsoft.AspNetCore.Mvc;

public class CuentasController : Controller
{
    private readonly CuentaBancaria _cuenta = new CuentaBancaria();

    [HttpPost]
    public IActionResult RetirarDinero(decimal monto)
    {
        try
        {
            _cuenta.Retirar(monto);
            // Si no hay excepciones, redirigimos con éxito
            return RedirectToAction("Exito");
        }
        catch (SaldoInsuficienteException ex)
        {
            // Atrapamos el error personalizado y pasamos la información a la Vista
            ViewBag.ErrorMessage = ex.Message;
            ViewBag.SaldoDisponible = ex.SaldoActual;
            
            return View("ErrorPago"); // Devuelve la vista con el error controlado
        }
        catch (Exception)
        {
            // Manejo genérico para errores desconocidos
            ViewBag.ErrorMessage = "Ocurrió un error inesperado en el servidor.";
            return View("Error");
        }
    }
}
