Modelo TCP/IP: Guía Visual y Didáctica

Arquitectura de red, contexto histórico y guía de clase paso a paso (2 Horas Académicas)

Bloque 1 (20 min)

1. ¿Por qué surgió el Modelo TCP/IP?

A finales de la década de 1960, la agencia DARPA del Departamento de Defensa de EE. UU. creó ARPANET. En esa época existían dos problemas críticos:

  • Incompatibilidad de Hardware: Cada fabricante (IBM, DEC, HP) utilizaba sus propios protocolos cerrados. Una computadora IBM no podía enviar datos a una DEC.
  • Redes Centralizadas Vulnerables: Las redes telefónicas tradicionales funcionaban por conmutación de circuitos. Si un nodo o cable central fallaba, toda la comunicación colapsaba.

La Solución TCP/IP: Crear un protocolo abierto de conmutación de paquetes donde los datos se dividen en fragmentos independientes capaces de viajar por distintas rutas y reconstruirse en el destino.

Capa 4 — Datos

Aplicación

Proporciona las interfaces y servicios de red directamente a las aplicaciones del usuario final.

HTTP (80) HTTPS (443) MySQL (3306) DNS (53) SSH (22)

Profundización para el aula:

En esta capa la información se denomina Datos puros. Es lo que genera el software (el código HTML de una web, una consulta SQL a MySQL o una petición web).

Capa 3 — Segmentos / Datagramas

Transporte

Gestiona la comunicación punto a punto entre procesos utilizando Puertos lógicos.

TCP (Orientado a conexión) UDP (Sin conexión)

Profundización para el aula:

  • TCP: Garantiza que los datos lleguen sin errores y ordenados mediante el Three-Way Handshake (SYN, SYN-ACK, ACK). Utilizado para páginas web, correo y bases de datos.
  • UDP: Envía datos sin verificar la entrega; prioriza la velocidad. Usado en streaming de video, llamadas VoIP y juegos online.
Capa 2 — Paquetes

Internet

Responsable del direccionamiento lógico (Direcciones IP) y del enrutamiento de datos a través de routers.

IPv4 IPv6 ICMP (Ping) ARP

Profundización para el aula:

Aquí se encapsula el segmento agregándole un Header IP con la Dirección IP de Origen y la Dirección IP de Destino. Los routers trabajan en esta capa decidiendo el mejor camino para los paquetes.

Capa 1 — Tramas / Bits

Acceso a la Red

Define el paso de tramas mediante direccionamiento físico (Dirección MAC) y su conversión a impulsos eléctricos o de luz.

Ethernet (802.3) Wi-Fi (802.11) Dirección MAC

Profundización para el aula:

Es la capa más cercana al hardware. Transforma los paquetes en Tramas que viajan por tarjetas de red, switches, cables UTP o señales de radiofrecuencia.

Bloque 3 (30 min)

2. Práctica de Diagnóstico en Consola (Paso a Paso)

Haz que los estudiantes abran la terminal (CMD o PowerShell) en sus computadoras del laboratorio y ejecuten los siguientes comandos para ver la pila TCP/IP en acción:

:: 1. Verificar conectividad básica y pruebas ICMP (Capa de Internet) ping 127.0.0.1 ping google.com :: 2. Inspeccionar la tabla ARP para ver Direcciones IP asociadas a Direcciones MAC físicas (Capa 1 y 2) arp -a :: 3. Ver conexiones TCP activas y puertos locales abiertos (Capa de Transporte) netstat -an :: 4. Rastreo de ruta salto a salto a través de routers (Capa de Internet) tracert google.com
Bloque 4 (15 min)

3. Resumen de Encapsulamiento de Datos

Explicación del viaje del mensaje al descender por las capas:

  • Capa 4 (Aplicación): [ Datos ]
  • Capa 3 (Transporte): [ Header TCP/UDP | Datos ] = Segmento
  • Capa 2 (Internet): [ Header IP | Header TCP | Datos ] = Paquete
  • Capa 1 (Acceso a Red): [ Header Ethernet | Header IP | Header TCP | Datos | Trailer ] = Trama / Bits
