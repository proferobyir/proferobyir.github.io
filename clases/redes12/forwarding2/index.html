Laboratorio de Redes: Firewall & NAT

Aprende conceptos fundamentales de seguridad de capa 3/4, reglas del Firewall de Windows y redirección de puertos (Port Forwarding / Virtual Servers) con simulación en tiempo real.

🛡️️
Firewall de Windows (Capas 3 y 4)
Un Firewall inspecciona el tráfico de red según reglas de seguridad. El Firewall de Windows actúa en las capas de **Red (Capa 3)** y **Transporte (Capa 4)** del modelo OSI:
  • Capa 3 (IP): Filtra según direcciones IP de origen y destino.
  • Capa 4 (Transporte): Inspecciona puertos y protocolos (TCP/UDP). Es un firewall con inspección de estado (Stateful).
🔌
Puertos y Protocolos
Los puertos son puntos finales de comunicación (0 a 65535).
FTP: 21 TCP HTTP: 80 / 8080 TCP HTTPS: 443 TCP RDP: 3389 TCP DNS: 53 UDP

TCP: Orientado a conexión (garantiza entrega).
UDP: Rápido sin conexión previa.

⇄
Reglas Inbound vs Outbound

Entrada (Inbound): Controla el tráfico que *se origina afuera* e intenta entrar a un servicio de tu PC. Por defecto se bloquea todo lo no solicitado.

Salida (Outbound): Controla el tráfico que tu PC inicia hacia Internet. Por defecto se permite todo.

🌐
Port Forwarding & CGNAT
El router mapea la IP WAN pública/simulada y un puerto externo hacia la IP LAN privada del servidor interno.
Hairpin NAT / NAT Loopback: Permite que un cliente dentro de la LAN acceda a un servidor local usando la IP WAN del router, haciendo que el tráfico haga un "bucle" dentro del router.

[SISTEMA]: Listo para iniciar simulación. Configure los parámetros y presione "Simular Envío".
1 Identificar IPs y Definir la Topología
▼
Abre la consola de comandos (CMD) en el equipo que actuará como servidor e identifica su IP privada local:
ipconfig
Anota la dirección IPv4 (Ejemplo: 192.168.1.20) y la Puerta de enlace predeterminada (Ejemplo: 192.168.1.1).
2 Configurar Reglas de Entrada en el Firewall de Windows
▼
  1. Presiona Win + R, escribe wf.msc y presiona Enter.
  2. Haz clic secundario en Reglas de entrada → Nueva regla...
  3. Selecciona Puerto → Clic en Siguiente.
  4. Elige TCP e introduce el puerto local correspondiente (Ejemplo: 8080 para Apache, 21 para FTP o 3389 para RDP).
  5. Selecciona Permitir la conexión.
  6. Aplica la regla para los perfiles de red Privado y Dominio.
  7. Asigna un nombre descriptivo (Ejemplo: "Permitir Servidor Web Apache 8080") y haz clic en Finalizar.
3 Configurar Port Forwarding / Virtual Server en el Router
▼
  1. Abre el navegador e ingresa a la IP del Router (ej. http://192.168.1.1).
  2. Busca la sección llamada Forwarding, Virtual Servers o Port Forwarding.
  3. Añade un nuevo mapeo:
    • Service / Name: ApacheWeb
    • External Port: 8080
    • Internal IP: 192.168.1.20 (IP del servidor)
    • Internal Port: 80
    • Protocol: TCP
  4. Guarda los cambios y habilita la regla.
4 Verificación y Diagnóstico de Fallas (Troubleshooting)
▼

Prueba 1: Desde otro equipo de la LAN o desde la interfaz WAN simulada, ejecuta un test de puerto vía PowerShell:

Test-NetConnection -ComputerName 10.0.0.1 -Port 8080

Posibles causas de falla:

  • TcpTestSucceeded: False → El Firewall local está bloqueando el puerto o la IP de la regla de redirección en el router está mal escrita.
  • Acceso denegado o Timeout → El servicio (Apache/FileZilla) no está iniciado o escuchando en la interfaz de red adecuada.
