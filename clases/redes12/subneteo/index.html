1. Clasificación de Redes IPv4 (Clases A, B y C)

Las direcciones IPv4 se dividen tradicionalmente en clases según el tamaño de la organización a la que van destinadas. Cada clase define cuántos bits se utilizan para identificar la red y cuántos para los hosts (dispositivos).

Clase Rango de IPs (Primer Octeto) Máscara por Defecto Uso Recomendado
Clase A 1.0.0.0 a 126.0.0.0 255.0.0.0 (/8) Grandes corporaciones, multinacionales y proveedores de servicios de internet (ISP).
Clase B 128.0.0.0 a 191.255.0.0 255.255.0.0 (/16) Medianas y grandes empresas, universidades e instituciones gubernamentales.
Clase C 192.0.0.0 a 223.255.255.0 255.255.255.0 (/24) Redes pequeñas, redes domésticas, oficinas locales (SOHO) y pequeñas empresas.

2. Configuración Didáctica de 3 Subredes Paso a Paso

Para dividir una red en subredes (por ejemplo, partiendo de una red base Clase C 192.168.1.0/24) y obtener al menos 3 subredes operativas, debemos tomar prestados bits de la porción de host.

  1. Identificar la necesidad: Requerimos 3 subredes. Aplicamos la fórmula $2^n \ge \text{Subredes}$ (donde $n$ es la cantidad de bits a tomar prestados). Con $n = 2$ bits ($2^2 = 4$), obtenemos exactamente 4 subredes (suficientes para cubrir las 3 solicitadas).
  2. Nueva máscara de subred: La máscara original pasa de /24 a /26 (255.255.255.192).
  3. Cálculo del salto de red: Como el último octeto tiene 2 bits de red ($128 + 64 = 192$), el incremento (block size) entre cada subred se calcula como $256 - 192 = 64$.

Fórmula para calcular la cantidad de hosts utilizables por cada subred:

Hosts útiles = 2^(8 - n) - 2 → 2^(8 - 2) - 2 = 2^6 - 2 = 64 - 2 = 62 hosts por subred.

Fórmula para calcular el octeto final de las subredes (incrementos de 64):

  • Subred 0: 192.168.1.0 (Red) / 192.168.1.1 al 192.168.1.62 (Hosts) / 192.168.1.63 (Broadcast)
  • Subred 1: 192.168.1.64 (Red) / 192.168.1.65 al 192.168.1.126 (Hosts) / 192.168.1.127 (Broadcast)
  • Subred 2: 192.168.1.128 (Red) / 192.168.1.129 al 192.168.1.190 (Hosts) / 192.168.1.191 (Broadcast)

3. Consideraciones de Seguridad: Subneteo vs. VLANs

El subneteo organiza lógicamente las direcciones IP y permite el direccionamiento eficiente del tráfico a través de la Capa 3 (Red) del modelo OSI mediante routers o pasarelas.

Nota de Arquitectura de Red: Un subneteo no reemplaza la seguridad de una VLAN. Aunque dos subredes diferentes estén separadas lógicamente por direcciones IP, si se encuentran configuradas en el mismo switch físico sin segmentación de Capa 2 (VLAN), los dispositivos podrán comunicarse o verse mediante ataques de descubrimiento y envenenamiento de tablas ARP a menos que se apliquen listas de control de acceso (ACLs) estrictas o pasarelas de enrutamiento con cortafuegos. La VLAN aísla el tráfico a nivel de enlace de datos (Capa 2), mientras que el subneteo organiza el espacio de direcciones IP.
