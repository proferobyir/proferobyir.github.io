Redes de Computadoras: VLANs y Puertos Trunk

Material completo, fundamentos, encapsulamiento 802.1Q, Native VLAN y Práctica en Packet Tracer

1. ¿Qué es una VLAN?

Una VLAN (Virtual Local Area Network o Red de Área Local Virtual) es un método que permite segmentar una red física en múltiples redes lógicas independientes dentro de un mismo dispositivo de red (como un Switch).

En términos sencillos: permite que dispositivos conectados al mismo equipo físico actúen como si estuvieran en redes separadas, o que dispositivos en switches diferentes estén en la misma red lógica sin importar su ubicación física.

2. Importancia de las VLANs

En las redes tradicionales, todos los equipos conectados a un switch comparten el mismo dominio de difusión (broadcast domain). Si un equipo envía un mensaje masivo (como una solicitud ARP o DHCP broadcast), todos los demás lo reciben, lo que satura la CPU de los equipos y reduce el ancho de banda útil a medida que la red crece.

La importancia de las VLANs radica en que:

  • Rompen los dominios de difusión: Cada VLAN es un dominio de difusión único y aislado. El broadcast de la VLAN 10 jamás llega a la VLAN 20.
  • Aportan flexibilidad: Permiten agrupar usuarios por departamento o función (ej. Finanzas, TI, Ventas) y no por su ubicación física o puerto físico asignado.
  • Optimizan la administración: Facilitan la aplicación de políticas de seguridad y QoS centralizadas.

3. ¿Para qué se utilizan?

Las VLANs se aplican en diversos escenarios del mundo real:

  • Separación por departamentos: Evita que personal de ventas acceda a tráfico confidencial de Recursos Humanos o Contabilidad.
  • Aislamiento de tráfico de voz y datos: Se suele crear una VLAN exclusiva para telefonía IP (VoIP) para priorizar el tráfico y garantizar calidad de llamada (QoS).
  • Redes de invitados: Ofrece acceso a Internet a visitantes aislándolo estrictamente de los recursos internos de la empresa.
  • Seguridad en IoT: Aislar dispositivos inteligentes (cámaras de seguridad, sensores biométricos) para que una vulnerabilidad en ellos no comprometa servidores críticos.

4. Puertos de Switch: Access vs. Trunk

Para extender las VLANs a través de múltiples switches o conectar un switch a un router, necesitamos entender cómo fluye la información etiquetada.

4.1 Puertos de Acceso (Access Ports)

Pertenecen a una única VLAN. Conectan dispositivos finales como PCs, impresoras, servidores IP o cámaras. Todo tráfico que entra sin etiquetar (untagged) es asignado automáticamente por el switch a la VLAN configurada en ese puerto.

4.2 Puertos Troncales (Trunk Ports)

Transportan tráfico de múltiples VLANs a través de un solo enlace físico (por ejemplo, el enlace inter-switch entre Switch A y Switch B). Para que el switch receptor sepa a qué VLAN pertenece cada trama, se utiliza un estándar de etiquetado.

4.3 Encapsulamiento: IEEE 802.1Q (Dot1Q)

Es el estándar industrial abierto (en desuso ISL de Cisco, hoy universalmente 802.1Q). Inserta una etiqueta (tag) de 4 bytes (32 bits) dentro de la trama Ethernet original justo después de la MAC de origen.

Campo 802.1Q Tag Tamaño Descripción
TPID (Tag Protocol Identifier) 16 bits (0x8100) Indica que la trama lleva una etiqueta 802.1Q.
TCI - PCO (Priority Code Point) 3 bits Clasificación de CoS (QoS) de 0 a 7.
TCI - CFI / DEI 1 bit Formato de identificador / indicador de caída elegible.
TCI - VID (VLAN ID) 12 bits Identificador de la VLAN (valores del 0 al 4095; utilizables 1 a 4094).

4.4 Native VLAN (VLAN Nativa)

Definida para enlaces trunk 802.1Q. Cualquier trama que llegue a un puerto trunk sin etiqueta se asume por defecto que pertenece a la Native VLAN (por defecto VLAN 1 en Cisco). Nota de seguridad: Se recomienda cambiar la Native VLAN a una inútil/asignada (ej. VLAN 999) para mitigar ataques de salto de VLAN (VLAN Hopping / Native VLAN mismatch).

5. Beneficios y Contras

Beneficios (Pros)

  • Mayor Seguridad: Tráfico sensible confinado a su VLAN.
  • Reducción de Costes: Reutilización de infraestructura física existente.
  • Mejor Rendimiento: Menor propagación de broadcast innecesario.
  • Gestión Simplificada: Movilidad de usuarios sin recablear.

Contras (Desventajas)

  • Complejidad de Configuración: Mayor curva de diseño y troubleshooting.
  • Riesgo de Seguridad: Ataques de VLAN Hopping si el trunk no está bien asegurado.
  • Dependencia de Enrutamiento: Requiere Router/L3 Switch para comunicación Inter-VLAN.
  • Punto Único de Fallo: Caída masiva si el núcleo de conmutación falla sin redundancia.

6. Ejercicio Práctico: Configuración paso a paso en Cisco Packet Tracer 8.2.1

Paso 1: Preparar la Topología en Packet Tracer
1. Abre Cisco Packet Tracer 8.2.1.
2. En el panel inferior (Network Devices > Switches), selecciona y arrastra al área de trabajo un Switch 2960.
3. Haz clic sobre el Switch recién agregado.
4. En la ventana que se abre, selecciona la pestaña CLI (Command Line Interface).
5. Haz clic en la terminal negra y presiona Enter para iniciar (verás el prompt Switch>).

Paso 2: Comandos CLI para crear 3 VLANs y asignar puertos

Copiaremos y entenderemos la siguiente configuración en nuestra terminal de Packet Tracer:

                
                # Acceder al modo privilegiado y luego al de configuración global
                Switch> enable
                Switch# configure terminal
                Switch(config)# hostname SW-CORE

                # 1. Crear las 3 VLANs y asignarles un nombre
                SW-CORE(config)# vlan 10
                SW-CORE(config-vlan)# name FINANZAS
                SW-CORE(config-vlan)# vlan 20
                SW-CORE(config-vlan)# name DESARROLLO
                SW-CORE(config-vlan)# vlan 30
                SW-CORE(config-vlan)# name INVITADOS
                SW-CORE(config-vlan)# exit

                # 2. Asignar los puertos a sus respectivas VLANs (Puertos de Acceso)
                SW-CORE(config)# interface fastethernet 0/1
                SW-CORE(config-if)# switchport mode access
                SW-CORE(config-if)# switchport access vlan
                    10
                SW-CORE(config-if)# exit

                SW-CORE(config)# interface fastethernet 0/2 
                SW-CORE(config-if)# switchport mode access 
                SW-CORE(config-if)# switchport access vlan
                    20 
                SW-CORE(config-if)# exit 

                SW-CORE(config)# interface fastethernet 0/3 
                SW-CORE(config-if)# switchport mode access 
                SW-CORE(config-if)# switchport access vlan
                    30 
                SW-CORE(config-if)# exit

Paso 3: Configurar puerto Trunk y Native VLAN

Para interconectar este switch con otro dispositivo, configuramos GigabitEthernet0/1 como Trunk:

# Crear la VLAN 99 para usarla como Nativa (Buena práctica de seguridad) SW-CORE(config)# vlan 99 SW-CORE(config-vlan)# name NATIVE_SEGURO SW-CORE(config-vlan)# exit # Configurar GigabitEthernet 0/1 SW-CORE(config)# interface gigabitethernet 0/1 # (Nota: En el Switch 2960 de Packet Tracer, Dot1Q es el único protocolo soportado, por lo que no requiere el comando de encapsulación previo). SW-CORE(config-if)# switchport mode trunk SW-CORE(config-if)# switchport trunk native vlan 99 SW-CORE(config-if)# switchport trunk allowed vlan 10,20,30,99 SW-CORE(config-if)# end

Paso 4: Verificación de la configuración

Utiliza los siguientes comandos en modo privilegiado para asegurarte de que tus VLANs y Trunk funcionan:

SW-CORE# show vlan brief SW-CORE# show interfaces trunk

Verificación esperada en el simulador:

VLAN Name Status Ports
1 default active Fa0/4, Fa0/5...
10 FINANZAS active Fa0/1
20 DESARROLLO active Fa0/2
30 INVITADOS active Fa0/3
99 NATIVE_SEGURO active Gi0/1 (native)
