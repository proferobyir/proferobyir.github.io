0. ¿Qué es un PostBack en ASP.NET Web Forms?

Un postback (literalmente "reenvío hacia atrás") ocurre cuando el usuario interactúa en el navegador con un control de servidor (por ejemplo, al hacer clic en un <asp:Button> o cambiar una selección con AutoPostBack="true") y el navegador envía los datos del formulario <form runat="server"> de vuelta hacia la misma página en el servidor para que C# procese el evento y devuelva el HTML actualizado.

¿Qué sucede en cada postback?

  1. Primera visita (no es postback): Entras a Default.aspx. El servidor crea una instancia de la página, ejecuta Page_Load con IsPostBack == false y envía el HTML al navegador.
  2. Acción del usuario (se dispara un postback): Pulsas el botón Guardar. El navegador envía los valores de los campos hacia el servidor.
  3. Nueva instancia en el servidor: ASP.NET crea una nueva instancia de la clase de la página para atender esa petición, ejecuta Page_Load (ahora con IsPostBack == true) y luego ejecuta el evento del control (como btnGuardar_Click).
  4. Respuesta: El servidor genera el nuevo HTML y lo devuelve al navegador.
¿Por qué importa esto? Como cada petición crea una nueva instancia de la página en el servidor, las variables normales declaradas en la clase de la página se reinician en cada postback. Por eso usamos if (!IsPostBack) para inicializar datos solo la primera vez y usamos Session para conservar información entre postbacks.
Uso de !IsPostBack en Page_Load 
protected void Page_Load(object sender, EventArgs e)
{
    // Solo se ejecuta cuando la página carga por primera vez (no en postbacks)
    if (!IsPostBack)
    {
        lblMensaje.Text = "Bienvenido. Carga inicial completada.";
    }
}

1. Estructura base y nuestra clase pública de ejemplo

Trabajaremos con una clase pública Producto dentro del namespace WebApplication1, utilizando campos públicos y constructores sencillos.

Producto.cs 
using System;

namespace WebApplication1
{
    public class Producto
    {
        public string Codigo;
        public string Nombre;
        public double Precio;

        public Producto()
        {
        }

        public Producto(string codigo, string nombre, double precio)
        {
            Codigo = codigo;
            Nombre = nombre;
            Precio = precio;
        }
    }
}
Nota de clase: En C# 5 dentro de Visual Studio 2012, mantener los campos como public permite acceder a ellos desde el código detrás (.aspx.cs) y mediante Eval("NombreCampo") dentro de las plantillas de controles repetitivos en .aspx.

1.1 Qué son las variables de Session, cómo crearlas y eliminarlas

Dado que cada postback crea una nueva instancia de la página, una variable de Session (Session["clave"]) guarda datos en memoria del servidor asociados a la sesión del usuario mientras esté activa, permitiendo conservar listas como List<Producto> entre postbacks y páginas .aspx.

Crear, leer y actualizar variables de Session

Crear, leer y actualizar Session en C# 
// Crear variables de Session
Session["usuario_activo"] = "Carlos Pérez";
Session["productos"] = new List<Producto>();

// Leer y hacer casting (verificando null)
if (Session["productos"] != null)
{
    List<Producto> listaActual = (List<Producto>)Session["productos"];
}

Eliminar variables de Session

  • Session.Remove("clave"): elimina una sola variable específica por su clave.
  • Session.Clear(): elimina todas las variables de la sesión actual manteniendo la sesión abierta.
  • Session.Abandon(): finaliza por completo la sesión actual (habitual al cerrar sesión).
Session.Remove, Session.Clear y Session.Abandon 
Session.Remove("productos"); // Elimina solo "productos"
Session.Clear();              // Elimina todas las claves de la sesión
Session.Abandon();            // Finaliza toda la sesión

2. Cómo incluir CSS en ASP.NET Web Forms

Puedes aplicar estilos en .aspx mediante CSS embebido, archivos externos con ResolveUrl("~/...") o asignando CssClass desde C#.

CSS embebido, enlace externo y CssClass desde C# 
<!-- En <head runat="server"> -->
<link href='<%= ResolveUrl("~/Estilos/site.css") %>' rel="stylesheet" type="text/css" />

<!-- En C# (.aspx.cs) -->
protected void Page_Load(object sender, EventArgs e)
{
    txtCodigo.CssClass = "form-control";
    btnGuardar.CssClass = "btn btn-primary";
}

2.1 Cómo incluir Bootstrap compilado versión 5.3 de forma offline

Copia los archivos compilados locales de Bootstrap 5.3 (por ejemplo Content/bootstrap.min.css y Scripts/bootstrap.bundle.min.js) dentro de tu proyecto y enlázalos con ResolveUrl("~/...").

Inclusión de Bootstrap 5.3 Offline en .aspx 
<head runat="server">
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Web Forms con Bootstrap 5.3 Offline</title>
    <link href='<%= ResolveUrl("~/Content/bootstrap.min.css") %>' rel="stylesheet" type="text/css" />
</head>
<body>
    <form id="form1" runat="server" class="container py-4">
        <!-- Controles ASP.NET con clases Bootstrap 5.3 -->
    </form>
    <script src='<%= ResolveUrl("~/Scripts/bootstrap.bundle.min.js") %>' type="text/javascript"></script>
</body>

3. Cómo incluir y usar JavaScript en ASP.NET Web Forms

Usa ClientIDMode="Static" en los controles de servidor cuando necesites leerlos fácilmente desde JavaScript con document.getElementById, o dispara scripts desde C# tras un postback con ScriptManager.RegisterStartupScript.

ClientIDMode="Static" y función JS 
<asp:TextBox ID="txtNombre" runat="server" ClientIDMode="Static" />
<button type="button" onclick="mostrarLongitud()">Contar letras</button>

<script type="text/javascript">
    function mostrarLongitud() {
        var campo = document.getElementById("txtNombre");
        alert("Caracteres escritos: " + campo.value.length);
    }
</script>

4. Controles repetitivos de ASP.NET y qué hace <%# Eval %>

ASP.NET Web Forms cuenta con controles repetitivos basados en plantillas que recorren automáticamente una colección (como List<Producto>) cuando llamas a .DataBind() desde C#.

¿Qué hace <%# Eval("...") %>?

La sintaxis <%# ... %> es una expresión de enlace de datos. Al ejecutarse DataBind() en el control repetitivo, Eval("NombreCampo") toma el objeto actual de la lista y obtiene el valor del campo público indicado (por ejemplo Codigo, Nombre o Precio).

  • <%# Eval("Nombre") %>: imprime el valor del campo Nombre del elemento actual.
  • <%# Eval("Precio", "{0:0.00}") %>: imprime el campo Precio formateado a dos decimales.

¿Qué hace cada control repetitivo?

  • <asp:Repeater>: Pinta exactamente el HTML que escribas dentro de sus plantillas sin agregar etiquetas extra. Sus plantillas principales son:
    • <HeaderTemplate>: se renderiza una sola vez al inicio (por ejemplo, apertura de <table> y encabezados).
    • <ItemTemplate>: se repite una vez por cada elemento de la lista.
    • <AlternatingItemTemplate>: opcional; aplica diseño alterno en filas pares/impares.
    • <SeparatorTemplate>: opcional; coloca un separador entre elementos consecutivos.
    • <FooterTemplate>: se renderiza una sola vez al final (por ejemplo, cierre </table>).
  • <asp:DataList>: Organiza los elementos repetidos (por defecto en una tabla HTML) y permite configurar RepeatColumns (cantidad de columnas por fila) y RepeatDirection (Horizontal o Vertical).
  • <asp:ListView>: Usa <LayoutTemplate> con un marcador itemPlaceholder para definir el contenedor, <ItemTemplate> para cada fila/tarjeta y <EmptyDataTemplate> para mostrar un mensaje automático cuando la lista está vacía.

Ejemplo completo con <asp:Repeater> y <%# Eval(...) %>

Default.aspx (<asp:Repeater> con HeaderTemplate, ItemTemplate y FooterTemplate) 
<%@ Page Language="C#" AutoEventWireup="true" CodeBehind="Default.aspx.cs" Inherits="WebApplication1.Default" %>

<!DOCTYPE html>
<html xmlns="http://www.w3.org/1999/xhtml">
<head runat="server">
    <title>Repeater y Eval en ASP.NET</title>
    <link href='<%= ResolveUrl("~/Content/bootstrap.min.css") %>' rel="stylesheet" type="text/css" />
</head>
<body>
    <form id="form1" runat="server" class="container py-4">
        <h3 class="mb-3">Listado con &lt;asp:Repeater&gt;</h3>

        <asp:Repeater ID="rptProductos" runat="server">
            <HeaderTemplate>
                <table class="table table-bordered table-striped">
                    <thead>
                        <tr>
                            <th>Código</th>
                            <th>Nombre</th>
                            <th>Precio</th>
                        </tr>
                    </thead>
                    <tbody>
            </HeaderTemplate>
            <ItemTemplate>
                        <tr>
                            <td><%# Eval("Codigo") %></td>
                            <td><%# Eval("Nombre") %></td>
                            <td>$<%# Eval("Precio", "{0:0.00}") %></td>
                        </tr>
            </ItemTemplate>
            <FooterTemplate>
                    </tbody>
                </table>
            </FooterTemplate>
        </asp:Repeater>
    </form>
</body>
</html>
Default.aspx.cs (enlazando la lista con DataSource y DataBind) 
using System;
using System.Collections.Generic;
using System.Web.UI;

namespace WebApplication1
{
    public partial class Default : System.Web.UI.Page
    {
        protected void Page_Load(object sender, EventArgs e)
        {
            if (!IsPostBack)
            {
                List<Producto> lista = new List<Producto>();
                lista.Add(new Producto("P01", "Teclado USB", 15.0));
                lista.Add(new Producto("P02", "Mouse Óptico", 8.5));

                Session["productos"] = lista;

                rptProductos.DataSource = lista;
                rptProductos.DataBind();
            }
        }
    }
}

5. Two-Way Data Binding (Flujo de ida y vuelta)

En Web Forms, el two-way data binding consiste en cargar valores hacia los controles de edición (ida) y, al enviar el formulario mediante un postback, capturar los cambios del usuario para actualizar el objeto y la lista en Session y volver a enlazar el control repetitivo (vuelta).

Ida y Vuelta + refrescar <asp:Repeater> 
// IDA: cargar datos hacia los controles
protected void btnCargar_Click(object sender, EventArgs e)
{
    if (Session["productos"] == null) return;

    List<Producto> lista = (List<Producto>)Session["productos"];
    foreach (Producto p in lista)
    {
        if (p.Codigo == txtCodigo.Text.Trim())
        {
            txtNombre.Text = p.Nombre;
            txtPrecio.Text = p.Precio.ToString();
            break;
        }
    }
}

// VUELTA: guardar cambios en la lista y refrescar el Repeater
protected void btnActualizar_Click(object sender, EventArgs e)
{
    if (Session["productos"] == null) return;

    List<Producto> lista = (List<Producto>)Session["productos"];
    foreach (Producto p in lista)
    {
        if (p.Codigo == txtCodigo.Text.Trim())
        {
            p.Nombre = txtNombre.Text.Trim();
            double nuevoPrecio = 0;
            if (double.TryParse(txtPrecio.Text.Trim(), out nuevoPrecio))
            {
                p.Precio = nuevoPrecio;
            }
            break;
        }
    }

    Session["productos"] = lista;
    rptProductos.DataSource = lista;
    rptProductos.DataBind();
}

6. Ejemplos con <asp:DataList>, <asp:ListView> y OnItemCommand

Ejemplo 1: <asp:DataList> con varias columnas (RepeatColumns)

<asp:DataList> distribuye los elementos en una tabla según RepeatColumns y RepeatDirection, usando <%# Eval(...) %> dentro de <ItemTemplate>.

<asp:DataList> en 2 columnas 
<asp:DataList ID="dlProductos" runat="server" RepeatColumns="2" RepeatDirection="Horizontal" CellPadding="8">
    <ItemTemplate>
        <div class="border p-2">
            <strong><%# Eval("Nombre") %></strong><br />
            <span>Código: <%# Eval("Codigo") %></span><br />
            <span>Precio: $<%# Eval("Precio", "{0:0.00}") %></span>
        </div>
    </ItemTemplate>
</asp:DataList>

Ejemplo 2: <asp:ListView> con LayoutTemplate, itemPlaceholder y EmptyDataTemplate

<asp:ListView> separa la estructura del contenedor (<LayoutTemplate>) de cada elemento (<ItemTemplate>) y permite mostrar <EmptyDataTemplate> cuando no hay registros.

<asp:ListView> con plantilla vacía 
<asp:ListView ID="lvProductos" runat="server">
    <LayoutTemplate>
        <table class="table table-bordered">
            <thead>
                <tr>
                    <th>Código</th>
                    <th>Nombre</th>
                    <th>Precio</th>
                </tr>
            </thead>
            <tbody>
                <tr id="itemPlaceholder" runat="server"></tr>
            </tbody>
        </table>
    </LayoutTemplate>
    <ItemTemplate>
        <tr>
            <td><%# Eval("Codigo") %></td>
            <td><%# Eval("Nombre") %></td>
            <td>$<%# Eval("Precio", "{0:0.00}") %></td>
        </tr>
    </ItemTemplate>
    <EmptyDataTemplate>
        <div class="alert alert-secondary">No hay productos para mostrar.</div>
    </EmptyDataTemplate>
</asp:ListView>

Ejemplo 3: Botón por fila en <asp:Repeater> con OnItemCommand

Al colocar un botón dentro de <ItemTemplate> con CommandName y CommandArgument='<%# Eval("Codigo") %>', el evento OnItemCommand recibe qué fila disparó la acción al producirse el postback.

OnItemCommand en <asp:Repeater> 
<asp:Repeater ID="rptAcciones" runat="server" OnItemCommand="rptAcciones_ItemCommand">
    <HeaderTemplate>
        <table class="table table-bordered">
            <tr>
                <th>Código</th>
                <th>Nombre</th>
                <th>Acción</th>
            </tr>
    </HeaderTemplate>
    <ItemTemplate>
            <tr>
                <td><%# Eval("Codigo") %></td>
                <td><%# Eval("Nombre") %></td>
                <td>
                    <asp:Button ID="btnQuitar" runat="server"
                        Text="Quitar"
                        CssClass="btn btn-sm btn-danger"
                        CommandName="Eliminar"
                        CommandArgument='<%# Eval("Codigo") %>' />
                </td>
            </tr>
    </ItemTemplate>
    <FooterTemplate>
        </table>
    </FooterTemplate>
</asp:Repeater>

7. Checklist rápido de errores comunes en clase

  • Olvidar DataBind(): Asignar .DataSource no actualiza la vista hasta llamar a .DataBind().
  • Nombre exacto en Eval("..."): Debe coincidir con el nombre del campo público de la clase.
  • Consistencia en la clave de Session: Usar siempre la misma clave (por ejemplo "productos").
  • Proteger con !IsPostBack: Evita sobrescribir datos iniciales en cada postback.
