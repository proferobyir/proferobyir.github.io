1. Estructura base y nuestra clase pública de ejemplo

Para que todos los ejemplos de este manual funcionen de forma coherente, trabajaremos con una clase pública Producto dentro del namespace WebApplication1, utilizando campos públicos y constructores sencillos.

Producto.cs 
using System;

namespace WebApplication1
{
    public class Producto
    {
        public string Codigo;
        public string Nombre;
        public double Precio;

        public Producto()
        {
        }

        public Producto(string codigo, string nombre, double precio)
        {
            Codigo = codigo;
            Nombre = nombre;
            Precio = precio;
        }
    }
}
Nota de clase: En C# 5 dentro de Visual Studio 2012, declarar los campos como public permite leerlos y modificarlos directamente (p.Nombre, p.Precio) tanto en el código detrás (.aspx.cs) como en la vista (.aspx).

1.1 Qué son las variables de Session, cómo crearlas y eliminarlas

En ASP.NET Web Forms, cada vez que ocurre una recarga o un postback (por ejemplo, al pulsar un botón), la clase de la página se vuelve a instanciar y las variables locales o de instancia normales se reinician.

Una variable de Session (Session["clave"]) es un espacio de memoria en el servidor asociado a un visitante/navegador mientras dura su sesión activa. Permite conservar datos (textos, números, objetos o listas como List<Producto>) entre postbacks y entre distintas páginas .aspx del mismo sitio.

¿Cómo crear o actualizar una variable de Session?

Se crea asignándole un valor mediante una clave de tipo string. Si la clave no existe, se crea; si ya existe, se sobrescribe su valor. Como Session almacena referencias de tipo object, al recuperarla debes hacer casting al tipo correspondiente.

Crear, leer y actualizar Session en C# 
// 1. Crear variables de Session
Session["usuario_activo"] = "Carlos Pérez";
Session["intentos"] = 0;

List<Producto> carrito = new List<Producto>();
Session["productos"] = carrito;

// 2. Leer variables de Session (verificando null primero)
if (Session["usuario_activo"] != null)
{
    string nombreUsuario = (string)Session["usuario_activo"];
}

if (Session["productos"] != null)
{
    List<Producto> listaActual = (List<Producto>)Session["productos"];
}

¿Cómo eliminar variables de Session?

Dependiendo de lo que necesites limpiar, existen tres formas habituales:

  • Session.Remove("clave"): elimina una sola variable específica por su nombre de clave.
  • Session.Clear(): elimina todas las variables guardadas en la sesión actual, pero mantiene el objeto de sesión activo.
  • Session.Abandon(): finaliza y destruye por completo la sesión actual del usuario (se usa típicamente al cerrar sesión / logout).
Eliminar una variable, limpiar todas o cerrar sesión 
// Eliminar solo la variable "productos"
Session.Remove("productos");

// Vaciar todas las variables de la sesión actual
Session.Clear();

// Destruir toda la sesión (por ejemplo, al salir del sistema)
Session.Abandon();

SessionDemo.aspx.cs 
using System;
using System.Collections.Generic;
using System.Web.UI;

namespace WebApplication1
{
    public partial class SessionDemo : System.Web.UI.Page
    {
        protected void Page_Load(object sender, EventArgs e)
        {
        }

        protected void btnAgregar_Click(object sender, EventArgs e)
        {
            List<Producto> lista;

            if (Session["productos"] == null)
            {
                lista = new List<Producto>();
            }
            else
            {
                lista = (List<Producto>)Session["productos"];
            }

            string cod = txtCodigo.Text.Trim();
            string nom = txtNombre.Text.Trim();
            double precio = 0;
            double.TryParse(txtPrecio.Text.Trim(), out precio);

            Producto nuevo = new Producto(cod, nom, precio);
            lista.Add(nuevo);

            // Guardar o actualizar la variable de Session
            Session["productos"] = lista;
            Session["ultimo_codigo"] = cod;

            lblMensaje.Text = "Producto guardado en Session[\"productos\"].";
        }

        protected void btnEliminarLista_Click(object sender, EventArgs e)
        {
            // Elimina únicamente la variable "productos"
            Session.Remove("productos");
            lblMensaje.Text = "Se eliminó Session[\"productos\"] con Session.Remove().";
        }

        protected void btnLimpiarTodo_Click(object sender, EventArgs e)
        {
            // Elimina todas las variables de Session actuales
            Session.Clear();
            lblMensaje.Text = "Se limpiaron todas las variables de Session con Session.Clear().";
        }
    }
}

2. Cómo incluir CSS en ASP.NET Web Forms

En un archivo .aspx puedes aplicar estilos mediante reglas embebidas, hojas de estilo externas o asignando clases desde C#.

Paso 1: CSS embebido dentro de <head>

Es práctico para pruebas rápidas o una sola página de laboratorio.

CSS embebido en .aspx 
<head runat="server">
    <meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
    <title>Catálogo en Web Forms</title>
    <style type="text/css">
        .tarjeta {
            border: 1px solid #333333;
            padding: 10px;
            margin-bottom: 8px;
            font-family: Arial, sans-serif;
        }

        .destacado {
            background-color: #f4f4f4;
            font-weight: bold;
        }
    </style>
</head>

Paso 2: Archivo CSS externo con ResolveUrl

Crea una carpeta Estilos en el proyecto y agrega site.css. Luego enlázala con ResolveUrl("~/...") para mantener rutas válidas.

Estilos/site.css 
.contenedor {
    max-width: 700px;
    margin: 20px auto;
    font-family: Arial, sans-serif;
}

.fila-item {
    border-bottom: 1px solid #cccccc;
    padding: 6px 0;
}
Enlace en .aspx 
<link href='<%= ResolveUrl("~/Estilos/site.css") %>' rel="stylesheet" type="text/css" />

Paso 3: Aplicar clase CSS desde C# con CssClass

En controles de servidor de ASP.NET (TextBox, Button, Panel, Label), puedes asignar clases desde el código detrás.

Asignación desde C# 
protected void Page_Load(object sender, EventArgs e)
{
    txtCodigo.CssClass = "tarjeta";
    btnGuardar.CssClass = "tarjeta destacado";
}

2.1 Cómo incluir Bootstrap compilado versión 5.3 de forma offline

Para trabajar en laboratorios sin internet o evitar depender de redes externas (CDN), descarga el paquete compilado de Bootstrap 5.3 (Compiled CSS and JS) y copia los archivos locales dentro de tu proyecto de Visual Studio.

Paso 1: Estructura de carpetas local recomendada

Dentro de tu proyecto WebApplication1, crea carpetas locales con los archivos compilados:

Estructura de archivos locales 
WebApplication1/
├── Content/
│   ├── bootstrap.min.css
│   └── bootstrap.min.css.map
├── Scripts/
│   ├── bootstrap.bundle.min.js
│   └── bootstrap.bundle.min.js.map
└── Default.aspx
Importante: Usa bootstrap.bundle.min.js (que ya incluye Popper) y evita enlazar archivos .map directamente en etiquetas <link> o <script>; el navegador los solicita automáticamente solo si abre las herramientas de desarrollador.

Paso 2: Vincular Bootstrap 5.3 offline en el archivo .aspx

Usa ResolveUrl("~/...") para referenciar los archivos compilados locales en <head> y al cierre de <body>.

Inclusión de Bootstrap 5.3 Offline en .aspx

        </div>

        <div class="mb-3">
            <asp:Label runat="server" AssociatedControlID="txtPrecio" CssClass="form-label" Text="Precio:" />

3. Cómo incluir y usar JavaScript en ASP.NET Web Forms

Al trabajar con controles que tienen runat="server", ASP.NET genera un ID en el HTML final. Usar ClientIDMode="Static" facilita localizar el elemento desde JavaScript con document.getElementById.

Paso 1: Archivo JavaScript externo

Scripts/validaciones.js 
function confirmarLimpieza() {
    return confirm("¿Deseas limpiar los campos del formulario?");
}
Inclusión en .aspx 
<script src='<%= ResolveUrl("~/Scripts/validaciones.js") %>' type="text/javascript"></script>

Paso 2: Leer un TextBox de servidor desde JavaScript

ClientIDMode="Static" en .aspx 
<asp:TextBox ID="txtNombre" runat="server" ClientIDMode="Static" />
<button type="button" onclick="mostrarLongitud()">Contar letras</button>

<script type="text/javascript">
    function mostrarLongitud() {
        var campo = document.getElementById("txtNombre");
        alert("Caracteres escritos: " + campo.value.length);
    }
</script>

Paso 3: Disparar JavaScript desde C# tras un evento

RegisterStartupScript en .aspx.cs 
protected void btnGuardar_Click(object sender, EventArgs e)
{
    string script = "alert('Registro guardado correctamente.');";
    ScriptManager.RegisterStartupScript(this, this.GetType(), "MsgGuardado", script, true);
}

4. Data Binding en ASP.NET Web Forms (paso a paso)

El data binding consiste en llevar datos desde una estructura en C# (como List<Producto>) hacia la interfaz web para visualizarlos o enlazarlos.

Enfoque A: Recorrer una List<Producto> en el .aspx con <% ... %> y <%= ... %>

Este enfoque es directo y claro para mostrar campos públicos de objetos almacenados en Session.

Default.aspx.cs 
using System;
using System.Collections.Generic;
using System.Web.UI;

namespace WebApplication1
{
    public partial class Default : System.Web.UI.Page
    {
        protected void Page_Load(object sender, EventArgs e)
        {
            if (!IsPostBack)
            {
                List<Producto> lista = new List<Producto>();
                lista.Add(new Producto("P01", "Teclado USB", 15.0));
                lista.Add(new Producto("P02", "Mouse Óptico", 8.5));
                lista.Add(new Producto("P03", "Cable HDMI", 6.0));

                Session["productos"] = lista;
            }
        }
    }
}

5. Two-Way Data Binding (Flujo de ida y vuelta)

El two-way data binding implica cargar datos hacia los controles de la vista (ida) y, tras la edición del usuario y el postback, capturar los cambios para actualizar el objeto y la lista en memoria (vuelta).

Editar.aspx.cs 
using System;
using System.Collections.Generic;
using System.Web.UI;

namespace WebApplication1
{
    public partial class Editar : System.Web.UI.Page
    {
        protected void Page_Load(object sender, EventArgs e)
        {
            if (!IsPostBack && Session["productos"] == null)
            {
                List<Producto> inicial = new List<Producto>();
                inicial.Add(new Producto("P01", "Teclado USB", 15.0));
                inicial.Add(new Producto("P02", "Mouse Óptico", 8.5));
                Session["productos"] = inicial;
            }
        }

        // IDA: de la lista hacia los TextBox
        protected void btnCargar_Click(object sender, EventArgs e)
        {
            List<Producto> lista = (List<Producto>)Session["productos"];

            foreach (Producto p in lista)
            {
                if (p.Codigo == "P01")
                {
                    txtCodigo.Text = p.Codigo;
                    txtNombre.Text = p.Nombre;
                    txtPrecio.Text = p.Precio.ToString();
                    lblEstado.Text = "Producto P01 cargado en el formulario.";
                    break;
                }
            }
        }

        // VUELTA: de los TextBox hacia el objeto y la lista
        protected void btnActualizar_Click(object sender, EventArgs e)
        {
            if (Session["productos"] == null)
            {
                return;
            }

            List<Producto> lista = (List<Producto>)Session["productos"];
            string codBuscado = txtCodigo.Text.Trim();

            foreach (Producto p in lista)
            {
                if (p.Codigo == codBuscado)
                {
                    p.Nombre = txtNombre.Text.Trim();

                    double nuevoPrecio = 0;
                    if (double.TryParse(txtPrecio.Text.Trim(), out nuevoPrecio))
                    {
                        p.Precio = nuevoPrecio;
                    }

                    lblEstado.Text = "Cambios guardados en la lista.";
                    break;
                }
            }

            Session["productos"] = lista;
        }
    }
}

7. Checklist rápido de errores comunes en clase

  • Mayúsculas y minúsculas en Session: Usar "productos" en un archivo y "Productos" en otro provoca que no se encuentre la clave.
  • Falta de !IsPostBack: Inicializar o vaciar la lista en Page_Load sin comprobar if (!IsPostBack) borra datos en cada clic de botón.
  • No actualizar Session tras modificar: Al agregar o editar elementos en una lista guardada en Session, mantén la referencia actualizada en la clave correspondiente.
  • Nombre completo o Import en .aspx: Dentro de bloques <% ... %>, usa nombres completos como System.Collections.Generic.List<WebApplication1.Producto> o declara la directiva <%@ Import Namespace="..." %>.
