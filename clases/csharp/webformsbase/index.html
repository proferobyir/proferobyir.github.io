Importante Requisitos y advertencia sobre Visual Studio 2012 y .NET 4.5

Este manual está escrito para Visual Studio 2012 con .NET Framework 4.5, que usa C# 5. Eso significa que hay características modernas de C# que NO puedes usar porque no compilan.

Característica ¿Funciona en 4.5? Qué usar en su lugar
$"Hola {nombre}" (interpolación) ❌ No (necesita C# 6) "Hola " + nombre
nameof(x) ❌ No Escribir el nombre a mano: "x"
?. (null-conditional) ❌ No if (x != null) x.Algo
var ✅ Sí —
LINQ (FirstOrDefault, Where) ✅ Sí —
string.IsNullOrWhiteSpace ✅ Sí —

Visual Studio 2012 y .NET 4.5: VS 2012 es la versión "nativa" para .NET 4.5. El desplegable de framework debería mostrar 4.5 sin problemas. Si por alguna razón no aparece (instalación incompleta del Multi-Targeting Pack), selecciona .NET Framework 4: el código de este manual funciona igual.

¿"Nuevo Proyecto" o "Nuevo Sitio Web"? En VS 2012 puedes crear dos tipos:

A. Nuevo Proyecto → Aplicación web ASP.NET (Web Application): genera archivo .csproj y usa CodeBehind en la directiva Page. Es la opción recomendada para este manual.

B. Nuevo Sitio Web → Sitio web ASP.NET vacío (Web Site): usa CodeFile en lugar de CodeBehind. Funciona igual, pero el código de ejemplo de este manual usa CodeBehind.

Regla para los estudiantes: si algo no compila y el error menciona $ o nameof, es porque están usando sintaxis de C# 6+ en un proyecto 4.5. Solución: concatenar con +.

Antes La idea central: Web Forms vs. PHP

En PHP tú escribes HTML y dentro metes <?php echo $algo; ?>. En Web Forms el HTML que ves en el archivo .aspx no es el HTML final. El servidor lee ese archivo, ejecuta el código C# que tú escribiste aparte (el "code-behind"), y genera HTML nuevo para el navegador.

Analogía: el archivo .aspx es un molde; el archivo .aspx.cs son las instrucciones que dicen qué poner dentro del molde antes de entregarlo al navegador.

Diferencias clave (para tu cabeza de PHP)

Concepto En PHP En ASP.NET Web Forms
¿Dónde va el HTML? En archivos .php mezclado con lógica. En archivos .aspx (solo interfaz).
¿Dónde va la lógica? No aplica (usas PHP). En el archivo .aspx.cs (code-behind).
¿Cómo muestro datos? echo $variable; Desde C#: lblMensaje.Text = "Hola";
¿Cómo capturo un clic? <form method="post"> y revisas $_POST. El botón tiene OnClick="btn_Click". Escribes un método C# para ese evento.
Estado de la página Se pierde en cada recarga (salvo sesiones). ASP.NET maneja el "ViewState" automáticamente para que los controles recuerden sus valores.

Idea para tus estudiantes: en Web Forms no "imprimes" HTML suelto. Llenas las propiedades de controles (textbox, label, botón) y el framework se encarga de generar el HTML final.

Paso 1 Crear el proyecto en Visual Studio 2012

Vamos a crear una Aplicación web ASP.NET (.NET Framework 4.5) con plantilla Web Forms.

  1. Abre Visual Studio 2012.
  2. Menú Archivo → Nuevo → Proyecto.
  3. En el panel izquierdo, despliega Visual C# y selecciona Web.
  4. En el centro, elige Aplicación web ASP.NET.
  5. En la parte superior de la ventana, en el desplegable de framework, selecciona .NET Framework 4.5.
  6. Ponle nombre: MiPrimeraApp.
  7. Clic en Aceptar.
  8. En el diálogo de plantillas, elige Web Forms (o Vacío si quieres empezar de cero y agregar un Web Form después con Proyecto → Agregar nuevo elemento → Formulario Web Forms).
  9. Clic en Aceptar.

Si el desplegable no muestra 4.5: selecciona .NET Framework 4. El código del manual funciona exactamente igual. La diferencia entre 4 y 4.5 no afecta nada de lo que enseñamos hoy.

Archivos que importan ahora

Archivo Qué es (para tu cabeza de PHP)
Default.aspx Tu "archivo PHP" pero solo con HTML y controles.
Default.aspx.cs Tu "lógica PHP" pero en C#.
Web.config Tu configuración (como .htaccess pero más ordenado).

No toques nada más. Ignora Site.Master, Global.asax y las carpetas raras. No las necesitas para empezar.

Paso 2 Tu primer "Hola Mundo" (el momento "ajá")

Abre Default.aspx. Verás HTML normal. Borra todo y escribe esto:

<%@ Page Language="C#" AutoEventWireup="true" CodeBehind="Default.aspx.cs" Inherits="MiPrimeraApp.Default" %>

<!DOCTYPE html>
<html>
<head runat="server">
    <title>Mi primera app</title>
</head>
<body>
    <form id="form1" runat="server">
        <div>
            <asp:TextBox ID="txtNombre" runat="server"></asp:TextBox>
            <asp:Button ID="btnSaludar" runat="server" Text="Saludar" OnClick="btnSaludar_Click" />
            <br /><br />
            <asp:Label ID="lblResultado" runat="server"></asp:Label>
        </div>
    </form>
</body>
</html>

Nota sobre la primera línea: si creaste el proyecto como Aplicación web ASP.NET (Proyecto), la directiva dirá CodeBehind. Si lo creaste como Sitio web ASP.NET, dirá CodeFile. En este manual usamos CodeBehind. Si ves CodeFile, no lo cambies: funciona igual.

Explicación de cada etiqueta (lo que dirías en voz alta)

<%@ Page ... %>: la directiva de página. Le dice a ASP.NET qué lenguaje usamos (Language="C#"), qué archivo tiene la lógica (CodeBehind="Default.aspx.cs") y cuál es el nombre completo de la clase (Inherits="MiPrimeraApp.Default"). Debe coincidir exactamente con el namespace y la clase del archivo .cs, o tendrás errores.

<form id="form1" runat="server">: el formulario que envuelve todo. En PHP tú escribes <form method="post">; aquí runat="server" hace que ASP.NET maneje el POST automáticamente. Sin este runat="server", los controles no funcionan.

<asp:TextBox ID="txtNombre" runat="server">: un control de servidor. Se convierte en un <input type="text"> en el navegador. El ID es el nombre con el que lo llamas desde C# (como el name de un input en PHP, pero más poderoso).

<asp:Button ID="btnSaludar" Text="Saludar" OnClick="btnSaludar_Click" />: el botón. Text es el texto visible. OnClick="btnSaludar_Click" le dice a ASP.NET qué método C# ejecutar cuando el usuario haga clic. Esto reemplaza tu if(isset($_POST['btn'])).

<asp:Label ID="lblResultado" runat="server">: un espacio reservado para texto. Se convierte en un <span>. Tú lo llenas desde C# con lblResultado.Text = "...";. Es tu "echo" pero dentro de un control.

Las tres cosas nuevas que deben memorizar:

1. runat="server": le dice a ASP.NET "procesa esto tú, no lo mandes directo".

2. ID="...": el nombre con el que llamas al control desde C#.

3. OnClick="...": el método C# que se ejecuta al hacer clic.

Paso 3 El archivo de lógica (.aspx.cs)

Abre Default.aspx.cs. Verás algo así:

using System;

namespace MiPrimeraApp
{
    public partial class Default : System.Web.UI.Page
    {
        protected void Page_Load(object sender, EventArgs e)
        {
            // Esto se ejecuta CADA VEZ que carga la página
        }

        protected void btnSaludar_Click(object sender, EventArgs e)
        {
            // Esto se ejecuta SOLO cuando el usuario hace clic en el botón
        }
    }
}

Explicación de cada parte

namespace MiPrimeraApp: el espacio de nombres. Agrupa las clases del proyecto. Debe coincidir con el Inherits del .aspx.

public partial class Default : System.Web.UI.Page: tu página es una clase. partial significa que está partida en dos archivos (el .aspx y el .aspx.cs). Hereda de Page, que es la clase base de toda página Web Forms.

Page_Load(object sender, EventArgs e): el evento que se ejecuta al cargar la página. Es como el <?php que se ejecuta al inicio de cada petición. Aquí NO va la lógica del botón.

btnSaludar_Click(object sender, EventArgs e): el método que se ejecuta al hacer clic en el botón. El nombre debe coincidir con el OnClick del .aspx. sender es el botón que disparó el evento; e son datos extra (normalmente no los usas).

Tu primer código funcional (¡sin interpolación!)

Dentro de btnSaludar_Click, escribe:

string nombre = txtNombre.Text;
lblResultado.Text = "Hola, " + nombre + ". ¡Esto es ASP.NET!";

Ojo con C# 5 (4.5): NO uses $"Hola, {nombre}". Eso es C# 6 y no compila en 4.5. Usa concatenación con +, como en el ejemplo.

txtNombre.Text: lees el texto que el usuario escribió. Es como leer $_POST['txtNombre'] pero sin formulario POST explícito: ASP.NET ya lo hizo por ti.

lblResultado.Text = "...": es como hacer echo pero dentro de un control específico. No imprimes HTML suelto; llenas un espacio reservado.

Presiona F5. Escribe tu nombre, haz clic. Funciona.

Paso 4 La regla de oro: Page_Load vs. Click

Tus estudiantes van a querer hacer esto (venir de PHP):

protected void Page_Load(object sender, EventArgs e)
{
    // MAL: esto se ejecuta en CADA clic
    lblResultado.Text = "Hola, " + txtNombre.Text;
}

Por qué está mal: Page_Load se ejecuta en cada petición, incluso antes de que el botón haga su trabajo. Si pones código ahí, el label se llena antes del clic y luego el clic lo pisa (o peor, se ejecuta con datos viejos).

La regla de oro para el pizarrón:

Page_Load → para preparar cosas la primera vez (cargar una lista, mostrar un mensaje de bienvenida).

btn_Click → para responder a un clic.

Cómo evitar que Page_Load se ejecute en cada clic

Se usa IsPostBack:

protected void Page_Load(object sender, EventArgs e)
{
    if (!IsPostBack)
    {
        // Esto SOLO se ejecuta la primera vez que se carga la página
        // NO se ejecuta cuando el usuario hace clic
    }
}

IsPostBack: significa "¿el usuario ya interactuó con la página?". Si es false, es la primera vez. El signo ! significa "NO". Entonces if (!IsPostBack) se lee: "si NO es una recarga por interacción, haz esto".

Paso 5 Session: el equivalente a $_SESSION

En PHP harías $_SESSION['usuario'] = $usuario;. En Web Forms es casi idéntico:

Session["UsuarioActual"] = "admin";                // Guardar
string user = Session["UsuarioActual"].ToString();  // Leer
Session.Clear();                                    // Borrar todo

Cómo proteger una página (que no entre sin login)

protected void Page_Load(object sender, EventArgs e)
{
    if (Session["UsuarioActual"] == null)
    {
        Response.Redirect("Login.aspx"); // Como header("Location: ...") en PHP
        return;
    }
}

Nada más. No hay magia negra. Si la sesión está vacía, redirige al login. Si no, deja pasar.

Session["clave"]: guarda datos por usuario mientras navega. Es exactamente $_SESSION['clave'] en PHP.

Response.Redirect("archivo.aspx"): redirige al navegador a otra página. Es header("Location: archivo.php") en PHP. Ojo: después de un Redirect el código sigue ejecutándose un poco; por eso se pone return; después.

Paso 6 List y Repeater: el equivalente a foreach

En PHP harías foreach($productos as $p). En C# usas List<T> y un control llamado Repeater (que es como un foreach que pinta HTML).

En el .aspx

<asp:Repeater ID="rptProductos" runat="server">
    <ItemTemplate>
        <div>
            <h3><%# Eval("Nombre") %></h3>
            <p>Precio: $<%# Eval("Precio") %></p>
        </div>
    </ItemTemplate>
</asp:Repeater>

En el .cs

// Simulamos datos (mañana serán de MySQL)
List<Producto> lista = new List<Producto>();
lista.Add(new Producto { Nombre = "Teclado", Precio = 45 });
lista.Add(new Producto { Nombre = "Mouse", Precio = 18 });

rptProductos.DataSource = lista;
rptProductos.DataBind();

List<Producto>: una lista tipada de objetos Producto. Es como un array de PHP pero donde cada elemento es un objeto con propiedades.

<ItemTemplate>: la plantilla que se repite por cada elemento de la lista. Dentro usas <%# Eval("Nombre") %> para acceder a las propiedades.

Eval("Nombre"): es como $p['Nombre'] dentro del bucle. Toma la propiedad del objeto actual.

DataSource = lista: le dices al Repeater de dónde sacar los datos.

DataBind(): "ahora sí, pinta". Sin esta línea, el Repeater no dibuja nada.

Analogía: Repeater es un foreach que escribe HTML. Le das una lista con DataSource, le dices DataBind() (que significa "ahora sí, pinta"), y él recorre la lista.

Paso 7 Qué NO enseñar el primer día

No enseñes Por qué
Conexión a MySQL Primero que entiendan que los datos pueden venir de una List en memoria. La BD es solo otro origen de esa lista.
Dictionary Es útil pero no es esencial para el primer día. Confunde. Déjalo para cuando dominen List.
Clases Usuario y Producto complejas Puedes usar List<string> o incluso arrays paralelos el primer día. Las clases son un tema aparte de POO.
Web.config con cadenas de conexión Mañana no hay base de datos. No lo menciones.
