List<T> y LINQ en C# 5.0

Guía completa, directa y visual para dominar colecciones dinámicas.

Visual Studio 2012 / .NET 4.5 Compatible

1. ¿Qué es una List<T>?

Olvídate de los arreglos estáticos de tamaño fijo. Una List<T> es una mochila inteligente que crece y se encoge automáticamente a medida que agregas o eliminas elementos. A diferencia de los arrays tradicionales, no necesitas declarar un tamaño fijo al momento de crearla.

La T significa Tipo. Puedes crear listas de enteros (List<int>), de textos (List<string>) o de objetos personalizados como List<Persona>. Esto se conoce como programación genérica, y permite que el compilador verifique los tipos en tiempo de compilación, evitando errores en tiempo de ejecución. 
// Crear e inicializar en una sola línea (C# 5.0)
List<string> heroes = new List<string> { "Batman", "Flash", "Superman" };

// También puedes crear una lista vacía y agregar elementos después
List<int> numeros = new List<int>();
numeros.Add(10);
numeros.Add(20);
numeros.Add(30);

Diferencia entre Array y List<T>

Característica Array List<T>
Tamaño Fijo al declarar Dinámico, crece automáticamente
Métodos de búsqueda Limitados Amplia variedad (Add, Remove, Find, Sort, etc.)
LINQ Compatible Compatible y más natural
Rendimiento Ligeramente más rápido en acceso por índice Muy bueno, con overhead mínimo

Capacidad vs. Cantidad

Una List<T> tiene dos propiedades importantes que suelen confundirse:

  • Count: número de elementos actualmente almacenados.
  • Capacity: número de elementos que la lista puede contener antes de necesitar redimensionarse internamente. Cuando se supera, la capacidad se duplica automáticamente.
List<int> lista = new List<int>();
Console.WriteLine(lista.Capacity); // 0
lista.Add(1);
Console.WriteLine(lista.Capacity); // 4 (se redimensiona automáticamente)
Console.WriteLine(lista.Count);    // 1

2. El Arsenal de Métodos Esenciales

Operaciones básicas para manipular tu lista en el día a día:

  • .Add(item): Agrega un elemento al final de la lista.
  • .AddRange(IEnumerable<T>): Agrega todos los elementos de otra colección al final.
  • .Insert(index, item): Inserta un elemento en una posición exacta, desplazando los siguientes.
  • .InsertRange(index, coleccion): Inserta una colección completa en una posición específica.
  • .Remove(item): Borra la primera coincidencia de un valor. Devuelve true si lo encontró.
  • .RemoveAt(index): Borra el elemento ubicado en una posición específica.
  • .RemoveAll(predicado): Elimina todos los elementos que cumplan una condición.
  • .Clear(): Elimina todos los elementos de la lista.
  • .Count: Devuelve la cantidad actual de elementos (vital para bucles).
  • .Contains(item): Devuelve true si el elemento existe en la lista.
  • .IndexOf(item): Devuelve el índice de la primera coincidencia, o -1 si no existe.
  • .Sort(): Ordena alfabéticamente o de menor a mayor de inmediato.
  • .Reverse(): Invierte el orden de los elementos.
  • .ToArray(): Convierte la lista en un array.
  • .Find(predicado): Devuelve el primer elemento que cumpla la condición.
  • .FindAll(predicado): Devuelve una nueva lista con todos los que cumplan la condición.
  • .Exists(predicado): Devuelve true si algún elemento cumple la condición.
  • .ForEach(accion): Ejecuta una acción sobre cada elemento.

Ejemplo práctico de métodos básicos

List<string> frutas = new List<string> { "Manzana", "Pera", "Uva" };

frutas.Add("Naranja");              // Agrega al final
frutas.Insert(1, "Plátano");           // Inserta en posición 1
frutas.Remove("Pera");                // Elimina "Pera"
frutas.RemoveAt(0);                   // Elimina el primero

if (frutas.Contains("Uva"))
    Console.WriteLine("La lista contiene Uva");

int indice = frutas.IndexOf("Naranja");
Console.WriteLine("Naranja está en el índice: " + indice);

frutas.Sort();                       // Ordena alfabéticamente
frutas.Reverse();                    // Invierte el orden
Importante: Remove solo elimina la primera coincidencia. Si necesitas eliminar todas las coincidencias, usa RemoveAll con un predicado.

3. Superpoderes LINQ (De Básico a Avanzado)

LINQ (Language Integrated Query) permite hacer consultas expresivas sobre tus listas sin escribir bucles complejos. Es una de las características más poderosas de C# y se integra perfectamente con List<T>.

Antes de empezar: para usar LINQ necesitas la directiva using System.Linq; al inicio del archivo. Sin ella, ninguno de los métodos de esta sección estará disponible.

Anatomía de una consulta LINQ

Toda consulta LINQ con sintaxis de métodos sigue este patrón general:

coleccion.Metodo1(criterio).Metodo2(transformacion).Metodo3()

Vamos a desglosar cada parte:

  • coleccion: la fuente de datos. Puede ser una List<T>, un array, un Dictionary, o cualquier objeto que implemente IEnumerable<T>.
  • .Metodo1: el primer operador LINQ. Cada operador se invoca con un punto (.) porque es un método de extensión sobre IEnumerable<T>.
  • (criterio): el argumento del operador. Casi siempre es una expresión lambda que define qué hacer con cada elemento.
  • Encadenamiento: el resultado de un operador se convierte en la entrada del siguiente. Esto se llama fluent syntax o sintaxis fluida.

¿Qué es una expresión lambda?

Una expresión lambda es una función anónima y compacta. Su sintaxis es:

parametro => expresion
  • parametro: el nombre que le das a cada elemento de la colección mientras LINQ la recorre. Puedes llamarlo como quieras (x, p, nombre, item...).
  • =>: se lee "va hacia" o "tal que". Separa el parámetro de la lógica.
  • expresion: el resultado que se devuelve para cada elemento. Puede ser un booleano (para filtrar), un valor transformado (para proyectar) o una clave (para ordenar/agrupar). 
// Esta lambda: p => p > 60
// Se lee: "para cada p, devuelve true si p es mayor que 60"

Filtro Rápido (.Where) y Proyección (.Select)

List<int> puntuaciones = new List<int> { 45, 85, 90, 30, 100 };

// Filtrar elementos mayores a 60
var aprobados = puntuaciones.Where(p => p > 60).ToList();

// Proyección: transformar cada elemento
var cuadrados = puntuaciones.Select(p => p * p).ToList();

// Encadenar Where y Select
var resultado = puntuaciones
    .Where(p => p >= 50)
    .Select(p => "Puntuación: " + p)
    .ToList();

Desglose paso a paso

  • puntuaciones: la lista origen (List<int>).
  • .Where(p => p > 60):
    • Where = operador de filtrado. Recorre cada elemento y solo deja pasar los que cumplen la condición.
    • p = nombre temporal del elemento actual (podría ser x o numero).
    • => = separador de la lambda.
    • p > 60 = condición booleana. Si es true, el elemento pasa; si es false, se descarta.
  • .ToList(): materializa el resultado. Sin este método, aprobados sería una consulta diferida (no ejecutada todavía). ToList() fuerza la ejecución y devuelve una nueva List<int>.
  • var: el compilador infiere el tipo. En este caso, aprobados es List<int>.
  • .Select(p => p * p):
    • Select = operador de proyección. Transforma cada elemento en otra cosa.
    • p * p = la transformación aplicada. Cada número se convierte en su cuadrado.
  • Encadenamiento: .Where(...).Select(...) primero filtra y luego transforma. El orden importa: si inviertes el orden, transformarías elementos que luego descartarías (más trabajo innecesario).

Ordenamiento con OrderBy y ThenBy

List<string> nombres = new List<string> { "Carlos", "Ana", "Luis", "Beatriz" };

var ordenados = nombres.OrderBy(n => n).ToList();          // Ascendente
var descendente = nombres.OrderByDescending(n => n).ToList(); // Descendente

// Ordenar por múltiples criterios
var porLongitudYLuegoAlfabetico = nombres
    .OrderBy(n => n.Length)
    .ThenBy(n => n)
    .ToList();

Desglose paso a paso

  • .OrderBy(n => n):
    • OrderBy = operador de ordenamiento ascendente.
    • n => n = la clave de ordenamiento. Aquí la clave es el propio elemento (orden alfabético).
    • Podrías usar n => n.Length para ordenar por longitud, o n => n[0] para ordenar por la primera letra.
  • .OrderByDescending(n => n): igual que OrderBy, pero invierte el orden (de Z a A, o de mayor a menor).
  • .ThenBy(n => n): segundo criterio de orden. Solo se usa después de OrderBy o OrderByDescending. Si dos elementos empatan en el primer criterio, se ordenan por este segundo.
  • Ejemplo mental: con OrderBy(n => n.Length).ThenBy(n => n), primero se agrupan por longitud y dentro de cada grupo se ordenan alfabéticamente. "Ana" (3) va antes que "Luis" (4), y "Luis" antes que "Carlos" (6).

Agrupación con GroupBy

List<string> palabras = new List<string> { "sol", "luna", "mar", "cielo", "pan" };

var grupos = palabras.GroupBy(p => p.Length);

foreach (var grupo in grupos)
{
    Console.WriteLine("Palabras de " + grupo.Key + " letras:");
    foreach (var palabra in grupo)
        Console.WriteLine("  - " + palabra);
}

Desglose paso a paso

  • .GroupBy(p => p.Length):
    • GroupBy = operador de agrupación.
    • p => p.Length = la clave de agrupación. Todos los elementos que devuelvan la misma clave caen en el mismo grupo.
    • El resultado es una secuencia de objetos IGrouping<int, string>: cada uno tiene una Key (la clave común) y es a la vez una colección de los elementos de ese grupo.
  • foreach (var grupo in grupos): recorre cada grupo.
  • grupo.Key: la clave compartida por todos los elementos del grupo. En este ejemplo, la longitud de las palabras (3, 4, 5).
  • foreach (var palabra in grupo): el grupo en sí es iterable, así que puedes recorrer sus elementos individuales.
  • Resultado esperado: grupo Key=3 → "sol", "mar", "pan"; grupo Key=4 → "luna"; grupo Key=5 → "cielo".

Agregaciones: Sum, Average, Min, Max, Count

List<int> ventas = new List<int> { 120, 340, 560, 80, 900 };

int total = ventas.Sum();
double promedio = ventas.Average();
int minimo = ventas.Min();
int maximo = ventas.Max();
int cantidad = ventas.Count();
int mayoresA200 = ventas.Count(v => v > 200);

Desglose paso a paso

  • .Sum(): recorre toda la colección y suma todos los elementos. Devuelve un único valor. No recibe parámetros si sumas los valores tal cual.
  • .Average(): suma todos los elementos y divide entre la cantidad. Devuelve double para preservar decimales.
  • .Min() / .Max(): devuelven el menor o mayor elemento según el comparador por defecto del tipo.
  • .Count(): sin argumentos, devuelve la cantidad total de elementos. Es equivalente a la propiedad Count de la lista, pero funciona también sobre cualquier IEnumerable<T>.
  • .Count(v => v > 200): con una lambda, cuenta solo los elementos que cumplen la condición. Es equivalente a .Where(v => v > 200).Count(), pero más eficiente porque no crea una colección intermedia.

Búsqueda con First, FirstOrDefault, Single

List<string> ciudades = new List<string> { "Bogotá", "Lima", "Santiago", "Quito" };

string primera = ciudades.First();                       // Lanza excepción si está vacía
string primeraConS = ciudades.First(c => c.StartsWith("S"));
string oDefault = ciudades.FirstOrDefault(c => c == "Madrid"); // null si no existe
string unica = ciudades.Single(c => c == "Lima");           // Lanza si hay 0 o más de 1

Desglose paso a paso

  • .First(): devuelve el primer elemento de la secuencia. Si la colección está vacía, lanza InvalidOperationException.
  • .First(c => c.StartsWith("S")): devuelve el primer elemento que cumpla la condición. c.StartsWith("S") es el método de string que verifica si empieza con "S".
  • .FirstOrDefault(...): igual que First, pero si no encuentra nada devuelve el valor predeterminado del tipo (null para string, 0 para int, etc.) en lugar de lanzar excepción.
  • .Single(c => c == "Lima"): espera exactamente un elemento que cumpla la condición. Si hay 0 o más de 1, lanza excepción. Es útil cuando sabes que el resultado debe ser único.
  • .SingleOrDefault(...): como Single, pero devuelve el valor predeterminado si no encuentra ninguno (aunque sigue lanzando si hay más de uno).

Nivel Avanzado: El Método .Zip()

El método .Zip() es una joya oculta de LINQ. Te permite fusionar dos listas elemento por elemento aplicando una regla de combinación, creando una secuencia nueva. La longitud del resultado será la de la lista más corta. 

List<string> nombres = new List<string> { "Ana", "Luis", "Carlos" };
List<int> edades = new List<int> { 20, 25, 30 };

// Fusionamos ambas listas en una sola lista de textos combinados
List<string> resultado = nombres.Zip(edades, (nombre, edad) => 
    nombre + " tiene " + edad + " años"
).ToList();

// Resultado en consola:
// "Ana tiene 20 años"
// "Luis tiene 25 años"
// "Carlos tiene 30 años"

Desglose paso a paso

  • nombres.Zip(edades, ...): Zip se invoca sobre la primera secuencia (nombres) y recibe como primer argumento la segunda secuencia (edades).
  • (nombre, edad) => ...: la lambda de combinación recibe dos parámetros (uno de cada lista) porque está fusionando dos secuencias. El primer parámetro (nombre) viene de nombres; el segundo (edad) viene de edades.
  • nombre + " tiene " + edad + " años": la regla de combinación. Se concatena el nombre con la edad para formar una nueva cadena.
  • Emparejamiento: el primer elemento de nombres se empareja con el primero de edades, el segundo con el segundo, y así sucesivamente. Si una lista es más corta, los elementos sobrantes de la otra se ignoran.
  • .ToList(): materializa la secuencia fusionada en una nueva List<string>.

Otras operaciones LINQ útiles

  • .Any(predicado): devuelve true si algún elemento cumple la condición. Sin argumentos, devuelve true si la colección tiene al menos un elemento.
    Ejemplo: lista.Any(x => x > 100) → ¿hay algún valor mayor a 100?
  • .All(predicado): devuelve true solo si todos los elementos cumplen la condición.
    Ejemplo: lista.All(x => x > 0) → ¿todos son positivos?
  • .Distinct(): elimina elementos duplicados comparando por igualdad.
    Ejemplo: {1, 2, 2, 3}.Distinct() → {1, 2, 3}.
  • .Skip(n): omite los primeros n elementos y devuelve el resto.
    Ejemplo: lista.Skip(2) → salta los dos primeros.
  • .Take(n): devuelve solo los primeros n elementos.
    Ejemplo: lista.Take(3) → los tres primeros. Combinado con Skip sirve para paginación: lista.Skip(pagina * 10).Take(10).
  • .Concat(otraLista): concatena dos secuencias sin eliminar duplicados.
    Ejemplo: {1, 2}.Concat({2, 3}) → {1, 2, 2, 3}.
  • .Union(otraLista): une dos secuencias eliminando duplicados.
    Ejemplo: {1, 2}.Union({2, 3}) → {1, 2, 3}.
  • .Intersect(otraLista): devuelve solo los elementos comunes a ambas.
    Ejemplo: {1, 2, 3}.Intersect({2, 3, 4}) → {2, 3}.
  • .Except(otraLista): devuelve los elementos de la primera que no están en la segunda.
    Ejemplo: {1, 2, 3}.Except({2, 3}) → {1}.
  • .ToDictionary(clave, valor): convierte la lista en un Dictionary<TKey, TValue> usando dos lambdas: una para la clave y otra para el valor.
    Ejemplo: personas.ToDictionary(p => p.Id, p => p.Nombre).
  • .ToList() / .ToArray(): materializan la consulta en una colección concreta. Sin ellos, la consulta permanece como un IEnumerable<T> diferido.
Ejecución diferida vs. materialización: LINQ usa ejecución diferida. La consulta no se ejecuta hasta que se itera (por ejemplo, con un foreach) o se materializa con ToList(), ToArray(), Count(), First(), etc. Esto permite encadenar muchas operaciones sin recorrer la colección varias veces. Pero cuidado: si modificas la lista original antes de iterar el resultado, los cambios se reflejarán en la consulta.

Ejemplo comparativo: diferido vs. materializado

List<int> nums = new List<int> { 1, 2, 3 };

// Consulta diferida: todavía no se ejecuta
var consulta = nums.Where(n => n > 1);

// Modificamos la lista original
nums.Add(4);

// Ahora se ejecuta, y el 4 también aparece
foreach (var n in consulta)
    Console.WriteLine(n); // 2, 3, 4

// Si hubiéramos hecho ToList() antes de modificar, solo veríamos 2 y 3

4. Código Completo para Probar

Copia y pega este programa de consola en tu Visual Studio 2012 para ver todo en acción. Incluye ejemplos de listas, métodos esenciales y consultas LINQ:

using System;
using System.Collections.Generic;
using System.Linq;

namespace DemoListas
{
    class Program
    {
        static void Main(string[] args)
        {
            // 1. Crear e inicializar una lista
            List<string> lenguajes = new List<string> { "C#", "PHP", "JavaScript" };
            
            // 2. Agregar, insertar y ordenar
            lenguajes.Add("Python");
            lenguajes.Insert(0, "Java");
            lenguajes.Sort();

            Console.WriteLine("--- LISTA ORDENADA ---");
            foreach (string lang in lenguajes)
            {
                Console.WriteLine(lang);
            }

            // 3. Consultas LINQ
            Console.WriteLine("\n--- LENGUAJES CON MÁS DE 3 LETRAS ---");
            var largos = lenguajes.Where(l => l.Length > 3).ToList();
            largos.ForEach(l => Console.WriteLine(l));

            // 4. Zip: fusionar dos listas
            List<string> nombres = new List<string> { "Ana", "Luis", "Carlos" };
            List<int> edades = new List<int> { 20, 25, 30 };

            Console.WriteLine("\n--- FUSIÓN CON ZIP ---");
            var fusion = nombres.Zip(edades, (n, e) => n + " tiene " + e + " años").ToList();
            fusion.ForEach(f => Console.WriteLine(f));

            // 5. Agregaciones
            List<int> ventas = new List<int> { 120, 340, 560, 80, 900 };
            Console.WriteLine("\n--- AGREGACIONES ---");
            Console.WriteLine("Suma: " + ventas.Sum());
            Console.WriteLine("Promedio: " + ventas.Average());
            Console.WriteLine("Máximo: " + ventas.Max());
            Console.WriteLine("Mínimo: " + ventas.Min());

            Console.ReadKey();
        }
    }
}

5. Buenas Prácticas y Errores Comunes

Buenas prácticas

  • Inicializa las listas con una capacidad estimada si conoces el tamaño aproximado: new List<int>(100). Esto evita redimensionamientos innecesarios.
  • Usa var solo cuando el tipo sea evidente por el contexto.
  • Prefiere LINQ para consultas declarativas y bucles foreach cuando necesites efectos secundarios.
  • Usa FirstOrDefault en lugar de First cuando no estés seguro de que exista el elemento.
  • Recuerda que LINQ es de ejecución diferida: si modificas la lista original antes de iterar el resultado, los cambios se reflejarán.

Errores comunes

  • IndexOutOfRangeException: intentar acceder a un índice que no existe. Verifica siempre Count antes de usar lista[i].
  • InvalidOperationException con First/Single: cuando la secuencia está vacía o hay más de un elemento. Usa FirstOrDefault o SingleOrDefault.
  • Modificar la lista mientras se itera: lanza excepción. Usa for inverso o crea una copia con ToList().
  • Confundir Count con Capacity: Count es la cantidad real de elementos; Capacity es el espacio reservado.
  • Olvidar el using System.Linq;: sin él, los métodos LINQ no están disponibles.
Recuerda: List<T> implementa IEnumerable<T>, ICollection<T> e IList<T>. Esto la hace compatible con LINQ, con bucles foreach y con la mayoría de APIs de .NET que esperan colecciones genéricas.
