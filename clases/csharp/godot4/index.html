Módulo 0: Fundamentos Absolutos de Programación Orientada a Objetos (POO)

Antes de mover nodos en Godot, es imprescindible entender qué es la Programación Orientada a Objetos en C#.

Analógia Docente: Piensa en una Clase como el plano arquitectónico de una casa, y en un Objeto como la casa real construida a partir de ese plano.

1. Clases, Atributos y Métodos

  • Variables/Atributos: Las características o datos de la clase (ej. Vida, Velocidad, Nombre).
  • Métodos/Funciones: Las acciones que la clase puede realizar (ej. Caminar, Saltar, Atacar).
using System;

// Declaración del plano (Clase)
public class PersonajeBase
{
    // Atributos (Estado del objeto)
    public string Nombre = "Sin Nombre";
    public int Vida = 100;

    // Método Constructor: Se ejecuta al crear el objeto
    public PersonajeBase(string nombreInicial)
    {
        Nombre = nombreInicial;
    }

    // Método (Comportamiento)
    public void RecibirDanio(int cantidad)
    {
        Vida -= cantidad;
        Console.WriteLine($"{Nombre} recibió {cantidad} de daño. Vida restante: {Vida}");
    }
}

2. Herencia y Polimorfismo

La Herencia permite que una clase hija adquiera automáticamente todas las propiedades y métodos de una clase padre.

// Enemigo hereda todos los miembros de PersonajeBase
public class Enemigo : PersonajeBase
{
    public int DanioAtaque = 15;

    // Constructor que llama al constructor padre
    public Enemigo(string nombre) : base(nombre) { }

    public void Atacar()
    {
        Console.WriteLine($"{Nombre} ataca causando {DanioAtaque} puntos de daño.");
    }
}

Módulo 1: Adaptación de C# al Entorno de Godot 4

En Godot, cada script hereda de un tipo de nodo específico del motor. Para integrarse correctamente con el sistema interno de C# .NET en Godot 4, se deben cumplir tres reglas:

  • Heredar de un tipo de nodo existente (ej. Node2D, CharacterBody2D).
  • Usar el modificador partial en la clase.
  • Utilizar GD.Print() para mostrar mensajes en la consola del editor.

Ejemplo de Script Integrado

using Godot;
using System;

namespace TutorialJuego;

public partial class MiPrimerNodo : Node2D
{
    // Export permite modificar la variable desde el Inspector del Editor
    [Export] public float VelocidadBase { get; set; } = 200.0f;
    [Export] public string NombreJugador = "Héroe";

    private int _puntosVida = 100;

    // Equivalente al Constructor: Se ejecuta cuando el nodo entra a la escena
    public override void _Ready()
    {
        GD.Print($"Cargando a {NombreJugador} en el mapa...");
    }

    // Ciclo principal del juego: Se ejecuta en cada frame de renderizado
    public override void _Process(double delta)
    {
        Rotation += 1.0f * (float)delta;
    }
}

Módulo 2: Arquitectura del Árbol de Escenas (Scene Tree)

Godot no utiliza clases aisladas; compone el juego mediante Nodos organizados en forma de árbol. Una Escena es un conjunto jerárquico de nodos guardado como archivo .tscn.

EscenaPrincipal (Node2D) ├── Jugador (CharacterBody2D) <-- Adjunto: Jugador.cs │ ├── Sprite2D │ └── CollisionShape2D └── Generador (Node2D) <-- Adjunto: Generador.cs

Instanciación Dinámica de Escenas

Permite instanciar copias de una escena programáticamente (ej. proyectiles, enemigos o coleccionables):

using Godot;

public partial class Generador : Node2D
{
    [Export] public PackedScene EscenaProyectil;

    public void Disparar(Vector2 posicionInicial)
    {
        if (EscenaProyectil != null)
        {
            // 1. Instanciar el objeto desde el plano (PackedScene)
            Node2D nuevoProyectil = EscenaProyectil.Instantiate<Node2D>();
            
            // 2. Configurar posición
            nuevoProyectil.Position = posicionInicial;
            
            // 3. Agregarlo como hijo al árbol de la escena activa
            AddChild(nuevoProyectil);
        }
    }
}

Módulo 3: Movimiento y Física Cinemática (CharacterBody2D)

El nodo CharacterBody2D proporciona la lógica necesaria para personajes controlados por teclado o gamepad mediante física cinemática.

Configuración del Input Map

Configurar en Proyecto → Configuración del Proyecto → Mapa de Entradas:

  • mover_derecha → Tecla D / Flecha Derecha
  • mover_izquierda → Tecla A / Flecha Izquierda
  • saltar → Tecla Espacio

Código del Jugador

using Godot;

public partial class Jugador : CharacterBody2D
{
    [Export] public float Speed = 300.0f;
    [Export] public float JumpVelocity = -400.0f;

    // Gravedad por defecto del motor
    public float Gravity = ProjectSettings.GetSetting("physics/2d/default_gravity").AsSingle();

    public override void _PhysicsProcess(double delta)
    {
        Vector2 velocity = Velocity;

        // Aplicar gravedad si el personaje está en el aire
        if (!IsOnFloor())
        {
            velocity.Y += Gravity * (float)delta;
        }

        // Control de Salto
        if (Input.IsActionJustPressed("saltar") && IsOnFloor())
        {
            velocity.Y = JumpVelocity;
        }

        // Control de Movimiento Lateral
        Vector2 direction = Input.GetVector("mover_izquierda", "mover_derecha", "ui_up", "ui_down");
        if (direction != Vector2.Zero)
        {
            velocity.X = direction.X * Speed;
        }
        else
        {
            velocity.X = Mathf.MoveToward(Velocity.X, 0, Speed);
        }

        Velocity = velocity;
        
        // Aplica la velocidad respetando colisiones
        MoveAndSlide();
    }
}

Módulo 4: Detección de Colisiones y Señales (Area2D)

Las Señales permiten aplicar el patrón de diseño Observador para notificar eventos sin acoplar código. El nodo Area2D detecta entrada y salida de cuerpos sin aplicar fricción física.

Objeto Recolectable (Moneda)

using Godot;

public partial class Moneda : Area2D
{
    [Export] public int ValorPuntos = 10;

    public override void _Ready()
    {
        // Suscribir método a la señal BodyEntered nativa
        BodyEntered += OnBodyEntered;
    }

    private void OnBodyEntered(Node2D body)
    {
        // Validar si el objeto colisionado es el Jugador (Polimorfismo / Pattern Matching)
        if (body is Jugador jugador)
        {
            GD.Print($"Moneda recolectada. +{ValorPuntos} pts.");
            
            // Eliminar el nodo de forma segura
            QueueFree();
        }
    }
}

Módulo 5: Construcción de Escenarios con TileMapLayer

En Godot 4.3+, la creación de escenarios optimizados mediante baldosas se realiza a través del nodo TileMapLayer.

Fase Acción en el Editor de Godot
1. Nodo Base Añadir un nodo TileMapLayer a la escena. En el inspector, asignar un nuevo TileSet.
2. Textura En la pestaña inferior TileSet, arrastrar el archivo de imagen (Atlas/SpriteSheet).
3. Física En el Inspector del TileSet, desplegar Physics Layers y añadir un nuevo elemento.
4. Colisión En el panel TileSet, seleccionar la herramienta Physics y trazar el rectángulo de colisión sobre los bloques sólidos.
5. Pintado Cambiar a la pestaña TileMap y diseñar el nivel directamente en el visor 2D.

Módulo 6: Resumen Docente y Buenas Prácticas

  • _Process vs _PhysicsProcess: Usar _Process para UI, cámaras y elementos visuales. Usar _PhysicsProcess estrictamente para movimiento de cuerpos físicos.
  • QueueFree(): No usar eliminación directa de memoria. QueueFree() elimina el nodo de forma segura al finalizar el frame actual.
  • Tipado en C#: Aprovechar la comprobación de tipos explícita (if (nodo is Clase)) para evitar errores de referencias nulas en tiempo de ejecución.
