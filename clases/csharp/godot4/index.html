Módulo 0: Fundamentos de POO y Modificadores de Acceso

Antes de mover nodos en Godot, es vital entender qué es una Clase, un Objeto y cómo funciona el Encapsulamiento mediante los modificadores de acceso (public, private, etc.).

Analogía Docente: Piensa en una Clase como el plano arquitectónico de una casa, y en un Objeto como la casa real construida a partir de ese plano.

1. ¿Por qué usamos `public`, `private` y `protected`? (Encapsulamiento)

El encapsulamiento consiste en proteger los datos internos de un objeto para evitar que otros componentes del sistema modifiquen valores sin validación.

Modificador Visibilidad / Alcance ¿Cuándo usarlo?
public Acceso total desde cualquier otra clase o archivo del proyecto. Para métodos o propiedades que otros componentes o el mismo motor (Godot) necesitan invocar/leer obligatoriamente.
private Acceso restringido únicamente dentro de la misma clase donde se declaró. Para variables internas, contadores de estado o métodos auxiliares que nadie más debe tocar directamente.
protected Acceso permitido en la clase actual y en sus clases hijas (herencia). Para variables o métodos que quieres compartir entre clases derivadas pero ocultar al exterior.
Regla de Oro en Godot 4: Toda clase adjunta a un nodo de Godot debe ser public. De lo contrario, el motor de Godot (escrito internamente en C++) no tendrá permisos de acceso para instanciar la clase, vincularla al nodo o ejecutar sus métodos principales como _Ready() y _Process().

2. Ejemplo Práctico de Encapsulamiento en C#

using System;

// La clase es pública para que pueda ser utilizada en cualquier parte del sistema
public class JugadorBase
{
    // PUBLIC: Nombre es visible y modificable libremente desde fuera
    public string Nombre = "Héroe";

    // PRIVATE: La vida está protegida. Ninguna otra clase puede hacer "jugador._vida = -50;"
    private int _vida = 100;

    // PROTECTED: Las clases hijas (como Mago o Guerrero) podrán leer o cambiar este valor
    protected float FuerzaAtaque = 10.0f;

    // PUBLIC: Método de acceso seguro para modificar la vida interna controladamente
    public void RecibirDanio(int cantidad)
    {
        if (cantidad < 0) return; // Validación para evitar errores
        _vida -= cantidad;
        if (_vida < 0) _vida = 0;
        
        Console.WriteLine($"{Nombre} recibió {cantidad} de daño. Vida restante: {_vida}");
    }

    // PUBLIC: Permite leer la vida sin dar permiso de modificarla directamente
    public int ObtenerVida()
    {
        return _vida;
    }
}

3. Herencia y Polimorfismo

La Herencia permite que una clase hija adquiera automáticamente los atributos y métodos de la clase padre mediante el operador :.

// Enemigo hereda de JugadorBase (adquiere Nombre, _vida y FuerzaAtaque)
public class Enemigo : JugadorBase
{
    public void PrepararAtaqueEspecial()
    {
        // Puede acceder a FuerzaAtaque por ser 'protected' en el padre
        Console.WriteLine($"{Nombre} ataca con potencia: {FuerzaAtaque * 2}");
    }
}

Módulo 1: Adaptación de C# al Entorno de Godot 4

En Godot, cada script hereda de un tipo de nodo específico del motor. Para integrarse correctamente con la arquitectura de Godot 4 en C#, se aplican las siguientes reglas:

  • public: Obligatorio para que el motor reconozca el script.
  • partial: Permite que Godot fusione el código C# que escribes con el código autogenerado internamente por el motor.
  • Heredar del nodo: Hereda las propiedades del nodo adjunto (ej. Node2D, CharacterBody2D).

Ejemplo de Script Integrado con Encapsulamiento Correcto

using Godot;
using System;

namespace TutorialJuego;

// PUBLIC: Accesible por el motor Godot. PARTIAL: Integración nativa de C#.
public partial class MiPrimerNodo : Node2D
{
    // [Export] expone una propiedad pública al Inspector visual de Godot
    [Export] public float VelocidadBase { get; set; } = 200.0f;
    [Export] public string NombreJugador = "Héroe";

    // PRIVATE: Control de estado exclusivo del script
    private int _puntosVida = 100;

    // Método del ciclo de vida: Se ejecuta una vez al entrar a la escena
    public override void _Ready()
    {
        GD.Print($"Cargando a {NombreJugador} en el mapa...");
    }

    // Ciclo principal: Se ejecuta en cada frame de renderizado
    public override void _Process(double delta)
    {
        Rotation += 1.0f * (float)delta;
    }
}

Módulo 2: Arquitectura del Árbol de Escenas (Scene Tree)

Godot organiza los elementos mediante Nodos en forma de árbol. Una Escena es un conjunto jerárquico de nodos guardado como archivo .tscn.

EscenaPrincipal (Node2D) ├── Jugador (CharacterBody2D) <-- Adjunto: Jugador.cs │ ├── Sprite2D │ └── CollisionShape2D └── Generador (Node2D) <-- Adjunto: Generador.cs

Instanciación Dinámica de Escenas

Permite crear copias de un objeto programáticamente en tiempo de ejecución:

using Godot;

public partial class Generador : Node2D
{
    [Export] public PackedScene EscenaProyectil;

    public void Disparar(Vector2 posicionInicial)
    {
        if (EscenaProyectil != null)
        {
            // 1. Instanciar el objeto desde la plantilla (PackedScene)
            Node2D nuevoProyectil = EscenaProyectil.Instantiate<Node2D>();
            
            // 2. Configurar posición
            nuevoProyectil.Position = posicionInicial;
            
            // 3. Agregarlo como hijo en la jerarquía activa
            AddChild(nuevoProyectil);
        }
    }
}

Módulo 3: Movimiento y Física Cinemática (CharacterBody2D)

El nodo CharacterBody2D maneja entidades con física controlada por código (movimiento de personaje, detección de suelo, gravedad y rampas).

Configuración del Input Map

Configurar en Proyecto → Configuración del Proyecto → Mapa de Entradas:

  • mover_derecha → Tecla D / Flecha Derecha
  • mover_izquierda → Tecla A / Flecha Izquierda
  • saltar → Tecla Espacio

Código del Jugador

using Godot;

public partial class Jugador : CharacterBody2D
{
    [Export] public float Speed = 300.0f;
    [Export] public float JumpVelocity = -400.0f;

    // Obtenemos la gravedad definida globalmente en el motor
    public float Gravity = ProjectSettings.GetSetting("physics/2d/default_gravity").AsSingle();

    public override void _PhysicsProcess(double delta)
    {
        Vector2 velocity = Velocity;

        // Aplicar gravedad si está en el aire
        if (!IsOnFloor())
        {
            velocity.Y += Gravity * (float)delta;
        }

        // Control de Salto
        if (Input.IsActionJustPressed("saltar") && IsOnFloor())
        {
            velocity.Y = JumpVelocity;
        }

        // Movimiento Lateral
        Vector2 direction = Input.GetVector("mover_izquierda", "mover_derecha", "ui_up", "ui_down");
        if (direction != Vector2.Zero)
        {
            velocity.X = direction.X * Speed;
        }
        else
        {
            velocity.X = Mathf.MoveToward(Velocity.X, 0, Speed);
        }

        Velocity = velocity;
        
        // Mueve el personaje respetando colisiones
        MoveAndSlide();
    }
}

Módulo 4: Detección de Colisiones y Señales (Area2D)

El nodo Area2D se usa para detectar solapamiento de áreas (monedas, trampas, portales) sin física de choque sólido.

Objeto Recolectable (Moneda)

using Godot;

public partial class Moneda : Area2D
{
    [Export] public int ValorPuntos = 10;

    public override void _Ready()
    {
        // Suscribir el método a la señal de colisión de área
        BodyEntered += OnBodyEntered;
    }

    private void OnBodyEntered(Node2D body)
    {
        // Validar si el objeto colisionado es de tipo Jugador
        if (body is Jugador jugador)
        {
            GD.Print($"Moneda recolectada. +{ValorPuntos} pts.");
            
            // Eliminar nodo de memoria de forma segura
            QueueFree();
        }
    }
}

Módulo 5: Construcción de Escenarios con TileMapLayer

En Godot 4.3+, la creación de escenarios optimizados por capas se maneja con TileMapLayer.

Fase Acción en el Editor de Godot
1. Nodo Base Añadir un nodo TileMapLayer a la escena. Crear un nuevo recurso TileSet en el inspector.
2. Textura En el panel inferior TileSet, arrastrar el sprite sheet / atlas de imágenes.
3. Capa de Física En el Inspector del TileSet, desplegar Physics Layers y añadir una capa.
4. Colisión En el panel TileSet, seleccionar la herramienta Physics y dibujar los polígonos sobre los bloques sólidos.
5. Pintado En el panel TileMap, elegir baldosas y pintar el escenario en el visor 2D.

Módulo 6: Resumen Docente y Buenas Prácticas

  • Modificadores: Mantén las variables privadas (private) por defecto y expón solo lo estrictamente necesario con public o [Export].
  • _Process vs _PhysicsProcess: _Process para UI y renderizado; _PhysicsProcess únicamente para cálculos de física y movimiento.
  • QueueFree(): Elimina nodos de memoria de forma asíncrona al terminar el frame actual para no romper la física activa.
