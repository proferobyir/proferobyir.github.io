Desarrollo de Interfaces XAML / WPF con C# 5 y MariaDB

Curso graduado: cada lección introduce una sola idea nueva y reutiliza todo lo anterior. Al final conectarás MariaDB a un DataGrid usando MySql.Data (conector oficial de Oracle para MySQL/MariaDB).

Visual Studio 2012 .NET Framework 4.5 C# 5 WPF + XAML MariaDB 10.x MySql.Data (Oracle)

¿Qué es XAML?

Extensible Application Markup Language: Lenguaje de marcado basado en XML para diseñar e inicializar interfaces de usuario de forma declarativa, separando el diseño estético de la lógica de C#.

¿Qué es WPF?

Windows Presentation Foundation: Framework gráfico basado en DirectX para Windows que permite crear interfaces modernas con gráficos vectoriales, soporte XAML y arquitectura avanzada.

¿Por qué MySql.Data con MariaDB?

MariaDB es compatible con el protocolo de MySQL, por lo que el conector oficial MySql.Data puede conectarse a servidores MariaDB. Oracle no da soporte oficial a MariaDB y algunas versiones recientes presentan incompatibilidades, pero para el laboratorio con VS2012 y MariaDB 10.x funciona correctamente.

Lección 1: ¿Qué es XAML? Mi primer botón

Principiante · 20 min

XAML define elementos gráficos de forma declarativa mediante XML. Cada etiqueta representa una instancia de una clase .NET. Hoy veremos una sola cosa: una ventana con un botón que muestra un mensaje al hacer clic. Y lo haremos de las dos formas que permite Visual Studio: arrastrando desde el Cuadro de herramientas y escribiendo XAML a mano.

Paso 1: Crear el proyecto

Abre Visual Studio 2012 → Archivo → Nuevo → Proyecto → Visual C# → Windows → Aplicación WPF. Nómbralo AppWpf y acepta. VS te crea automáticamente MainWindow.xaml (el diseño) y MainWindow.xaml.cs (el código C#). Esos dos archivos son los que editarás en todas las lecciones.

Paso 2: Conocer el entorno

Al abrir MainWindow.xaml, la pantalla se divide en tres zonas que debes identificar:

  • Cuadro de herramientas (Toolbox): normalmente a la izquierda. Si no lo ves, actívalo con Ver → Cuadro de herramientas (Ctrl+Alt+X). Ahí están todos los controles: Button, TextBox, Label, DataGrid, etc.
  • Diseñador visual (Design): la zona central con la ventana en blanco. Es una vista previa de cómo se verá tu interfaz.
  • Código XAML: debajo o al lado del diseñador. Puedes alternar entre Diseño, XAML y Dividido con los botones de la parte inferior del editor.
Distribución típica de VS2012 con un XAML abiertoConcepto

Paso 3: Arrastrar un botón desde el Cuadro de herramientas

Esta es la forma más intuitiva y la que usa todo el mundo al empezar:

  • En el Cuadro de herramientas, busca Button.
  • Haz clic y arrastra el Button sobre la ventana blanca del diseñador. Suelta donde quieras.
  • Verás que el botón aparece en el diseñador y automáticamente se agrega la etiqueta <Button ... /> en el código XAML de la derecha.
  • Selecciona el botón en el diseñador y, en la ventana Propiedades (abajo a la derecha, o F4), cambia Content a "Haz clic aquí". Verás que el XAML se actualiza solo.

El diseñador y el XAML son la misma cosa vista de dos formas. Arrastrar un botón escribe XAML por ti; escribir XAML hace aparecer el botón en el diseñador. No son dos archivos distintos: es el mismo archivo.

Paso 4: Escribir el XAML a mano (opcional pero recomendado)

A medida que avances en el curso, escribirás XAML directamente porque es más rápido y preciso que arrastrar. El XAML equivalente al botón que acabas de arrastrar es este:

MainWindow.xamlXAML
<Window x:Class="AppWpf.MainWindow"
        xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        Title="Mi Primera Interfaz"
        Height="250" Width="400">

    <Grid>
        <Button Content="Haz clic aquí"
                Width="140" Height="40"
                Click="btnSaludar_Click"/>
    </Grid>
</Window>
MainWindow.xaml.csC# Code-Behind
using System.Windows;

namespace AppWpf
{
    public partial class MainWindow : Window
    {
        public MainWindow()
        {
            InitializeComponent();
        }

        private void btnSaludar_Click(object sender, RoutedEventArgs e)
        {
            MessageBox.Show("¡Hola desde XAML en WPF!");
        }
    }
}

Conectar el botón al evento Click: cuando arrastras el botón y haces doble clic sobre él en el diseñador, Visual Studio genera automáticamente el método btnSaludar_Click en el code-behind. Si escribes el XAML a mano, debes escribir Click="btnSaludar_Click" y luego, en el code-behind, agregar el método con ese nombre exacto. El nombre debe coincidir o el código no compilará.

Paso 5: Ejecutar

Presiona F5 (o el botón verde Iniciar). Aparecerá la ventana con el botón. Haz clic y verás el MessageBox. Si aparece el mensaje, la lección está completa.

Ejercicio: cambia el Content del botón a tu nombre y el mensaje del MessageBox a "Hola, soy [tu nombre]". Prueba hacerlo de las dos formas: (1) arrastrando otro botón y cambiando sus propiedades en el panel Propiedades, y (2) escribiendo el XAML a mano. Verifica que ambas producen el mismo resultado.

Lección 2: Propiedades y eventos

Principiante · 20 min

En XAML, cada atributo (Width="140", Background="Blue") es una propiedad de la clase .NET subyacente. Y cada evento (Click="...") apunta a un método en el code-behind. Hoy aprenderás a modificar propiedades visuales y a responder a más de un evento.

  • Propiedades de layout: Width, Height, Margin, Padding.
  • Propiedades visuales: Background, Foreground, FontSize, FontWeight.
  • Eventos comunes: Click, MouseEnter, MouseLeave.
MainWindow.xamlXAML
<Grid>
    <Button x:Name="btnCambiar"
            Content="Pasa el mouse por aquí"
            Width="200" Height="50"
            Background="#007ACC"
            Foreground="White"
            FontSize="14"
            MouseEnter="btnCambiar_MouseEnter"
            MouseLeave="btnCambiar_MouseLeave"/>
</Grid>
MainWindow.xaml.csC#
using System.Windows;
using System.Windows.Media;

namespace AppWpf
{
    public partial class MainWindow : Window
    {
        public MainWindow() { InitializeComponent(); }

        private void btnCambiar_MouseEnter(object sender, System.Windows.Input.MouseEventArgs e)
        {
            btnCambiar.Background = Brushes.Green;
            btnCambiar.Content = "¡Estás dentro!";
        }

        private void btnCambiar_MouseLeave(object sender, System.Windows.Input.MouseEventArgs e)
        {
            btnCambiar.Background = Brushes.SteelBlue;
            btnCambiar.Content = "Pasa el mouse por aquí";
        }
    }
}

Conexión con la Lección 1: el x:Name es lo que permite que desde C# accedas al botón por su nombre (btnCambiar.Background). Sin x:Name, el control no existe para el code-behind.

Ejercicio: agrega un Click="btnCambiar_Click" al botón y en el método cambia el FontSize a 20 con btnCambiar.FontSize = 20;. Prueba qué pasa si olvidas declarar el x:Name.

Lección 3: Apilar controles con StackPanel

Principiante · 20 min

Hasta ahora todo vive dentro de un Grid sin filas ni columnas (lo cual no aprovecha nada). Hoy aprendes el panel más simple: StackPanel. Apila sus hijos uno debajo de otro (o uno al lado de otro si cambias la orientación). No hay coordenadas: el panel calcula todo.

¿Qué hace StackPanel?

Coloca sus hijos en una sola dirección. Por defecto Orientation="Vertical". Si pones "Horizontal", los alinea en fila. Es ideal para menús, listas de botones y formularios simples.

MainWindow.xamlXAML
<StackPanel Margin="20">
    <TextBlock Text="Mi primer formulario"
               FontSize="18"
               FontWeight="Bold"
               Margin="0,0,0,10"/>

    <Button Content="Botón 1" Margin="0,0,0,8"/>
    <Button Content="Botón 2" Margin="0,0,0,8"/>
    <Button Content="Botón 3"/>
</StackPanel>
Resultado visualConcepto

Conexión con la Lección 1: reemplazamos el Grid por StackPanel. Los botones ya no se superponen en el centro: se acomodan uno debajo de otro sin que tú indiques posiciones.

Ejercicio: cambia a <StackPanel Orientation="Horizontal" Margin="20"> y observa cómo los botones se ponen uno al lado de otro. Ese es todo el concepto de hoy.

Lección 4: Cuadrículas con Grid

Intermedio · 30 min

StackPanel apila en una sola dirección. Pero un formulario real necesita filas y columnas: eso es Grid. Es el panel más usado en WPF y el que controla la adaptabilidad de toda la ventana.

Reglas de dimensionamiento

  • Auto: la fila toma exactamente el tamaño de su contenido. Ideal para títulos y botones.
  • Valor fijo (ej. "120"): tamaño absoluto en píxeles. Se usa para barras laterales o encabezados.
  • * (estrella): ocupa todo el espacio restante repartiéndolo proporcionalmente. "2*" recibe el doble que "*".
MainWindow.xamlXAML
<Grid Margin="15">
    <Grid.RowDefinitions>
        <RowDefinition Height="Auto"/>   <!-- Título -->
        <RowDefinition Height="Auto"/>   <!-- Campos -->
        <RowDefinition Height="*"/>      <!-- Relleno -->
    </Grid.RowDefinitions>

    <Grid.ColumnDefinitions>
        <ColumnDefinition Width="Auto"/>  <!-- Etiquetas -->
        <ColumnDefinition Width="*"/>     <!-- Campos -->
    </Grid.ColumnDefinitions>

    <!-- Fila 0: título en las 2 columnas -->
    <TextBlock Grid.Row="0" Grid.ColumnSpan="2"
               Text="Registro de Usuario"
               FontSize="18" FontWeight="Bold"
               Margin="0,0,0,12"/>

    <!-- Fila 1: Label + TextBox en dos columnas -->
    <Label Grid.Row="1" Grid.Column="0" Content="Nombre:"/>
    <TextBox Grid.Row="1" Grid.Column="1" Margin="0,4,0,4"/>
</Grid>
ResultadoConcepto

Conexión con la Lección 3: dentro de cada celda podrías poner un StackPanel. De hecho, es lo más común: Grid para la estructura general y StackPanel para agrupar controles dentro de una celda.

Ejercicio: agrega una fila más con RowDefinition Height="Auto" y coloca un Label + TextBox para el email. Usa Grid.Row="2" en ambos.

Lección 5: Controles de entrada

Intermedio · 25 min

Ya sabes posicionar controles. Ahora toca los controles que reciben datos del usuario: TextBox, PasswordBox, ComboBox, CheckBox. Todos comparten la propiedad Text o Content que leerás en la próxima lección.

  • TextBox: texto de una línea. Propiedad clave: Text.
  • PasswordBox: oculta los caracteres. Propiedad: Password (no Text).
  • ComboBox: lista desplegable. Se llena con ComboBoxItem o desde C#.
  • CheckBox: casilla de verificación. Propiedad: IsChecked (bool?).
MainWindow.xamlXAML
<StackPanel Margin="20">
    <Label Content="Nombre:"/>
    <TextBox x:Name="txtNombre" Margin="0,0,0,10"/>

    <Label Content="Contraseña:"/>
    <PasswordBox x:Name="txtPassword" Margin="0,0,0,10"/>

    <Label Content="Rol:"/>
    <ComboBox x:Name="cmbRol" Margin="0,0,0,10">
        <ComboBoxItem Content="Administrador"/>
        <ComboBoxItem Content="Usuario"/>
        <ComboBoxItem Content="Invitado"/>
    </ComboBox>

    <CheckBox x:Name="chkAceptar"
              Content="Acepto los términos"/>
</StackPanel>
ResultadoConcepto

Conexión con la Lección 4: podrías poner estos mismos controles dentro de un Grid para alinear etiquetas y campos en dos columnas. Aquí usamos StackPanel porque es más simple para empezar.

Ejercicio: agrega un DatePicker debajo del CheckBox con x:Name="dtpFecha". Ese control lo usarás en la Lección 6.

Lección 6: Leer valores desde C#

Intermedio · 25 min

Aquí es donde todo cobra sentido: el usuario escribe en los controles y tú, desde C#, lees esos valores con x:Name.Propiedad. Esta es la forma manual de leer datos (la forma automática, el binding, viene en la Lección 7).

MainWindow.xamlXAML
<StackPanel Margin="20">
    <Label Content="Nombre:"/>
    <TextBox x:Name="txtNombre"/>

    <Button Content="Saludar"
            Click="btnSaludar_Click"
            Margin="0,10,0,0"/>
</StackPanel>
MainWindow.xaml.csC#
using System.Windows;

namespace AppWpf
{
    public partial class MainWindow : Window
    {
        public MainWindow() { InitializeComponent(); }

        private void btnSaludar_Click(object sender, RoutedEventArgs e)
        {
            string nombre = txtNombre.Text;

            if (nombre == "")
            {
                MessageBox.Show("Escribe un nombre primero.");
                return;
            }

            MessageBox.Show("Hola, " + nombre + "!");
        }
    }
}

Conexión con la Lección 5: cada control de entrada tiene una propiedad distinta que debes leer: TextBox.Text, PasswordBox.Password, ComboBox.SelectedValue o ComboBox.Text, CheckBox.IsChecked. Si confundes la propiedad, el código no compila.

Ejercicio: lee también la contraseña con txtPassword.Password y el rol con cmbRol.Text. Muestra todo en un solo MessageBox con \n para separar líneas.

Lección 7: Binding básico

Avanzado · 30 min

El binding conecta una propiedad XAML con una propiedad de un objeto C# sin escribir código imperativo. Es lo que hace que WPF se sienta "mágico": cambia el dato y la UI se actualiza sola. Hoy veremos el binding más simple: un TextBox que se refleja en un TextBlock.

Para que el binding funcione en ambos sentidos y se actualice mientras escribes, el objeto debe implementar INotifyPropertyChanged. Ese es el patrón que en la Lección 8 llevarás al DataGrid.

MainWindow.xamlXAML
<StackPanel Margin="20">
    <TextBox Text="{Binding Nombre, UpdateSourceTrigger=PropertyChanged}"
             Padding="5"/>

    <TextBlock Text="{Binding Nombre, StringFormat='Escribiste: {0}'}"
               Margin="0,10,0,0"
               Foreground="LightGreen"/>
</StackPanel>
MainWindow.xaml.csC#
using System.ComponentModel;
using System.Windows;

namespace AppWpf
{
    public partial class MainWindow : Window, INotifyPropertyChanged
    {
        private string _nombre = "";

        public string Nombre
        {
            get { return _nombre; }
            set
            {
                _nombre = value;
                if (PropertyChanged != null)
                    PropertyChanged(this, new PropertyChangedEventArgs("Nombre"));
            }
        }

        public event PropertyChangedEventHandler PropertyChanged;

        public MainWindow()
        {
            InitializeComponent();
            DataContext = this;
        }
    }
}
Binding en acciónConcepto

Conexión con la Lección 6: en la Lección 6 leías con txtNombre.Text. Aquí ya no lees manualmente: el binding lo hace por ti. La línea DataContext = this; es lo que le dice a la ventana "busca las propiedades en esta clase".

Ejercicio: agrega una segunda propiedad Email con su PropertyChanged y un segundo TextBox con Text="{Binding Email, UpdateSourceTrigger=PropertyChanged}". Verifica que el TextBlock se actualice solo.

Lección 8: Listas y DataGrid

Avanzado · 35 min

Un DataGrid es una tabla que muestra una lista de objetos. Para llenarlo, usas ObservableCollection<T>, que notifica a la UI cuando se agregan o quitan elementos. Esta es la base de la Lección 9 con MariaDB.

MainWindow.xamlXAML
<Grid Margin="10">
    <Grid.RowDefinitions>
        <RowDefinition Height="Auto"/>
        <RowDefinition Height="*"/>
    </Grid.RowDefinitions>

    <Button Content="Agregar usuario de ejemplo"
            Click="btnAgregar_Click"
            Padding="8"
            Margin="0,0,0,10"/>

    <DataGrid Grid.Row="1"
              x:Name="dgUsuarios"
              AutoGenerateColumns="True"/>
</Grid>
MainWindow.xaml.csC#
using System.Collections.ObjectModel;
using System.Windows;

namespace AppWpf
{
    public partial class MainWindow : Window
    {
        private ObservableCollection<Usuario> usuarios;

        public MainWindow()
        {
            InitializeComponent();
            usuarios = new ObservableCollection<Usuario>();
            dgUsuarios.ItemsSource = usuarios;
        }

        private void btnAgregar_Click(object sender, RoutedEventArgs e)
        {
            usuarios.Add(new Usuario
            {
                Id = usuarios.Count + 1,
                Nombre = "Usuario " + (usuarios.Count + 1),
                Email = "user" + (usuarios.Count + 1) + "@ejemplo.com"
            });
        }
    }

    public class Usuario
    {
        public int Id { get; set; }
        public string Nombre { get; set; }
        public string Email { get; set; }
    }
}
DataGrid con ObservableCollectionConcepto

Conexión con la Lección 7: el binding a una propiedad individual ya lo conoces. Aquí el DataGrid hace binding a una colección, y ObservableCollection notifica cuando la lista cambia (agregas un usuario y la tabla se actualiza sola).

Ejercicio: agrega un Button "Eliminar seleccionado" que llame a usuarios.Remove((Usuario)dgUsuarios.SelectedItem). Verifica que la fila desaparece sola de la tabla.

Lección 9: MariaDB + DataGrid con MySql.Data

Avanzado · 40 min

Última lección: conectar una ventana WPF a una base de datos MariaDB usando el conector oficial MySql.Data (Oracle). El código es idéntico al que usarías con MySQL, porque MariaDB habla el mismo protocolo. Solo cambia el origen de los datos.

Advertencia importante: Oracle no da soporte oficial a MariaDB. El conector MySql.Data funciona con MariaDB en la mayoría de los casos, pero versiones recientes de MariaDB (10.11+) han tenido problemas de compatibilidad con MySql.Data que Oracle no tiene intención de corregir. Para este laboratorio con VS2012 y MariaDB 10.x funciona correctamente.

Paso 1: Instalar MySql.Data en VS2012

En Visual Studio 2012, abre el Administrador de paquetes NuGet (clic derecho en el proyecto → Administrar paquetes NuGet). Busca MySql.Data e instala la versión más reciente compatible con .NET Framework 4.5. Si NuGet no está disponible en tu VS2012, descarga el instalador MSI de Connector/NET desde el sitio de MySQL y referencia manualmente MySql.Data.dll.

Paso 2: Crear la tabla en MariaDB

script.sqlMariaDB / MySQL
CREATE DATABASE instituto;

USE instituto;

CREATE TABLE usuarios (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    email VARCHAR(150) NOT NULL
);

INSERT INTO usuarios (nombre, email) VALUES
('Ana Torres', 'ana@ejemplo.com'),
('Luis Pérez', 'luis@ejemplo.com'),
('Carla Ruiz', 'carla@ejemplo.com');

Paso 3: El XAML (DataGrid)

MainWindow.xamlXAML
<Grid Margin="10">
    <Grid.RowDefinitions>
        <RowDefinition Height="Auto"/>
        <RowDefinition Height="*"/>
    </Grid.RowDefinitions>

    <Button Content="Cargar Usuarios desde MariaDB"
            Click="btnCargar_Click"
            Padding="8"
            Margin="0,0,0,10"/>

    <DataGrid Grid.Row="1"
              x:Name="dgUsuarios"
              AutoGenerateColumns="True"/>
</Grid>
MainWindow.xaml.csC# + MySql.Data
using System.Data;
using System.Windows;
using MySql.Data.MySqlClient;

namespace AppWpf
{
    public partial class MainWindow : Window
    {
        private string cadenaConexion =
            "Server=localhost;Database=instituto;Uid=root;Pwd=1234;";

        public MainWindow()
        {
            InitializeComponent();
        }

        private void btnCargar_Click(object sender, RoutedEventArgs e)
        {
            using (MySqlConnection conn = new MySqlConnection(cadenaConexion))
            {
                try
                {
                    conn.Open();
                    string query = "SELECT id, nombre, email FROM usuarios";
                    MySqlDataAdapter adapter = new MySqlDataAdapter(query, conn);
                    DataTable dt = new DataTable();
                    adapter.Fill(dt);

                    dgUsuarios.ItemsSource = dt.DefaultView;
                }
                catch (System.Exception ex)
                {
                    MessageBox.Show("Error: " + ex.Message);
                }
            }
        }
    }
}

Conexión con la Lección 8: el DataGrid ya lo conoces. Lo único nuevo aquí es que dt.DefaultView viene de una base de datos real en lugar de una lista en memoria. El binding del XAML no cambia en absoluto.

Nota sobre el conector: si al ejecutar obtienes un error como "Object cannot be cast from DBNull to other types" o problemas de autenticación inesperados, es un síntoma conocido de la incompatibilidad entre MySql.Data y versiones recientes de MariaDB. La solución más limpia es cambiar a MySqlConnector: solo reemplazas using MySql.Data.MySqlClient; por using MySqlConnector; y el resto del código funciona igual. Pero para el laboratorio con VS2012 y MariaDB 10.x, MySql.Data debería funcionar.

Ejercicio final: agrega un TextBox y un Button para insertar un usuario nuevo. Usa MySqlCommand con parámetros (@nombre, @email) para evitar inyección SQL. Luego recarga el DataGrid llamando al mismo método btnCargar_Click.
