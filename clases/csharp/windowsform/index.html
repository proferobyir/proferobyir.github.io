Fundamento 1 — Modificadores de acceso

¿Qué es un modificador de acceso?

Un modificador de acceso es una palabra que se escribe antes de una clase, un método o una propiedad para indicar quién puede verlo y usarlo. En C# hay cuatro principales: public, private, protected e internal (y protected internal como combinación).

Sirven para encapsular: mostrar solo lo necesario y ocultar los detalles internos. Así el código es más seguro y más fácil de mantener.

public — visible para todos

public class Estudiante
{
    public string Nombre { get; set; }
    public void Saludar() { Console.WriteLine("Hola"); }
}
  • Cualquier código, en cualquier proyecto, puede usar la clase, la propiedad o el método.
  • Se usa para lo que forma parte de la interfaz pública de tu clase: lo que otros necesitan para usarla.

private — visible solo dentro de la clase

public class Estudiante
{
    private int edad;              // solo accesible dentro de Estudiante
    private void Calcular() { }    // solo se llama desde dentro de Estudiante

    public void SetEdad(int e)
    {
        edad = e;                  // sí puede acceder porque está dentro
    }
}
  • Solo el código dentro de la misma clase puede acceder.
  • Es el modificador por defecto para miembros de una clase (si no escribes nada, es private).
  • Se usa para ocultar detalles internos y obligar a usar métodos públicos (encapsulamiento).

protected — visible en la clase y en sus clases derivadas

public class Persona
{
    protected string nombre;       // accesible en Persona y en Estudiante
}

public class Estudiante : Persona
{
    public void Mostrar()
    {
        Console.WriteLine(nombre); // sí puede: Estudiante hereda de Persona
    }
}
  • Solo la clase y las clases que heredan de ella pueden acceder.
  • Se usa cuando quieres que las subclases puedan usar un miembro, pero no el resto del mundo.

internal — visible dentro del mismo proyecto (ensamblado)

internal class Helper
{
    internal void Ayudar() { }
}
  • Cualquier clase dentro del mismo proyecto (mismo ensamblado) puede usarla.
  • Fuera del proyecto, no se ve.
  • Es útil para clases auxiliares que no deben exponerse fuera.

protected internal — unión de ambos

Visible desde el mismo ensamblado o desde clases derivadas (aunque estén en otro ensamblado).

Tabla comparativa

Modificador Misma clase Clases derivadas Mismo proyecto Otros proyectos
public ✅ ✅ ✅ ✅
private ✅ ❌ ❌ ❌
protected ✅ ✅ ❌ ❌
internal ✅ ❌ ✅ ❌
protected internal ✅ ✅ ✅ ❌

Por qué en Windows Forms los manejadores son private

private void btnMostrar_Click(object sender, EventArgs e)
{
    // ...
}
  • private porque solo el formulario necesita llamar a ese método (lo llama el evento del botón).
  • No tiene sentido que otro formulario llame a btnMostrar_Click directamente.
  • Si fuera public, expondrías un detalle interno innecesariamente.
Regla práctica: empieza con todo private y sube a public solo lo que realmente necesites exponer. Eso es encapsulamiento.

Fundamento 2 — static

¿Qué es static?

static no es un modificador de acceso. Es un modificador que indica que el miembro pertenece a la clase, no a una instancia. Es decir, no necesitas crear un objeto para usarlo.

static en campos y propiedades

public class Datos
{
    public static List<Estudiante> Estudiantes = new List<Estudiante>();
}
  • Datos.Estudiantes se usa directamente, sin new Datos().
  • La lista es única y compartida por todos los formularios.
  • Si fuera public List<Estudiante> Estudiantes (sin static), cada new Datos() tendría su propia lista, y los formularios no compartirían datos.

static en métodos

public static class Utilidades
{
    public static int Sumar(int a, int b)
    {
        return a + b;
    }
}

// Se llama así:
int r = Utilidades.Sumar(2, 3);
  • No se puede usar this dentro de un método static (no hay instancia).
  • Una clase static no se puede instanciar (new Utilidades() da error).
  • Todos sus miembros deben ser static.

static vs instancia: ejemplo comparativo

public class Contador
{
    public static int Total = 0;   // compartido por todos
    public int Individual = 0;     // cada objeto tiene el suyo

    public void Incrementar()
    {
        Total++;
        Individual++;
    }
}

// Uso:
Contador a = new Contador();
Contador b = new Contador();
a.Incrementar();
b.Incrementar();

Console.WriteLine(Contador.Total);     // 2  (compartido)
Console.WriteLine(a.Individual);       // 1  (solo de a)
Console.WriteLine(b.Individual);       // 1  (solo de b)
  • Total es static: hay una sola copia para toda la clase. Se accede como Contador.Total.
  • Individual no es static: cada objeto tiene su propia copia.

Por qué Datos es public static en el CRUD

public static class Datos
{
    public static List<Estudiante> Estudiantes = new List<Estudiante>();
}
  • public: todos los formularios del proyecto pueden verla.
  • static: la lista es única y compartida; no hay que crear un objeto Datos para usarla.

Combinación de modificadores

Los modificadores se combinan. Ejemplos:

public static class Datos { }          // clase pública y estática
private static int contador;          // campo privado y estático
public static void Sumar() { }        // método público y estático
protected static string nombre;       // campo protegido y estático

Resumen

  • public: todos lo ven.
  • private: solo la clase.
  • protected: la clase y sus hijas.
  • internal: el mismo proyecto.
  • static: pertenece a la clase, no a un objeto. No es un modificador de acceso, sino de pertenencia.
Para recordar: static responde a la pregunta "¿esto pertenece a la clase o a cada objeto?". Los modificadores de acceso responden a "¿quién puede verlo?". Son dos ejes distintos y se combinan.

Fundamento 3 — Parse, TryParse y LINQ

Parse

int.Parse(texto) convierte un texto a entero. Si el texto no es un número válido, lanza una excepción (FormatException). Si el texto es null, lanza ArgumentNullException. Si el texto está vacío (""), lanza FormatException. 

int a = int.Parse("123");   // OK, a = 123
int b = int.Parse("abc");   // FormatException
int c = int.Parse("");      // FormatException
int d = int.Parse(null);    // ArgumentNullException

Por eso, cuando uses Parse, valida antes que el texto no esté vacío y que sea numérico (con TryParse o con try/catch).

TryParse (no es LINQ)

int.TryParse(texto, out numero) intenta convertir el texto a entero sin lanzar excepción. Devuelve true si pudo convertir y false si no. El resultado se guarda en la variable que se pasa con out. 

int n;
bool ok = int.TryParse("123", out n);   // ok = true,  n = 123
bool ok2 = int.TryParse("abc", out n);  // ok2 = false, n = 0
bool ok3 = int.TryParse("", out n);     // ok3 = false, n = 0
bool ok4 = int.TryParse(null, out n);   // ok4 = false, n = 0

Es la forma más segura de convertir datos escritos por el usuario, porque no rompe el programa ante entradas inválidas.

Aclaración: TryParse no es LINQ. Es un método propio de los tipos numéricos (int, double, DateTime, etc.) para convertir texto a número de forma segura. Vive en la estructura int, dentro de System. No tiene nada que ver con consultas sobre colecciones.

LINQ (otra cosa completamente distinta)

LINQ (Language Integrated Query) es un conjunto de métodos para consultar, filtrar, ordenar y proyectar colecciones. Vive en System.Linq y trabaja sobre IEnumerable<T> (listas, arreglos, etc.). 

using System.Linq;   // necesario para usar LINQ

List<string> materias = new List<string>
{
    "Programación I", "Bases de Datos", "Redes I"
};

// Sintaxis de consulta (parecida a SQL)
var consulta = from m in materias
               where m.Contains("Programación")
               select m;

// Sintaxis de método (con lambdas)
var consulta2 = materias.Where(m => m.Contains("Programación"));

foreach (string item in consulta)
{
    Console.WriteLine(item); // Programación I
}

Métodos típicos de LINQ:

  • Where: filtra elementos según una condición.
  • Select: transforma cada elemento (proyección).
  • OrderBy / OrderByDescending: ordena.
  • First / FirstOrDefault: toma el primero.
  • Any / All: comprueba si alguno o todos cumplen una condición.
  • Count: cuenta elementos que cumplen una condición.
  • Sum, Average, Max, Min: agregaciones.

Diferencia clave entre TryParse y LINQ

Aspecto TryParse LINQ
¿Qué es? Método de conversión segura de texto a número Conjunto de métodos para consultar colecciones
¿Dónde vive? En int, double, DateTime... (System) En System.Linq
¿Sobre qué trabaja? Un texto (string) Colecciones (IEnumerable<T>)
¿Qué devuelve? bool (éxito o no) y el valor por out Una colección filtrada o un valor (según el método)
¿Lanza excepción? No (devuelve false) Depende del método (ej. First lanza si no hay elementos)
¿Se usa con using System.Linq;? No Sí
Para recordar: si tu código convierte un texto a número, piensa en Parse / TryParse. Si tu código filtra, ordena o transforma una lista, piensa en LINQ. Son herramientas distintas para problemas distintos.

Clase 1 — Introducción a Windows Forms

¿Qué es Windows Forms?

Windows Forms (WinForms) es una tecnología de .NET para crear aplicaciones de escritorio con interfaz gráfica. En Visual Studio 2012 se trabaja con el diseñador visual: arrastras controles (botones, cajas de texto, etiquetas) sobre un formulario y luego programas sus eventos en C#.

Un formulario (Form) es una ventana. Cada control es un objeto con propiedades (lo que se ve) y eventos (lo que hace). El código que escribes responde a esos eventos.

Crear el primer proyecto

  1. Abre Visual Studio 2012.
  2. Archivo → Nuevo → Proyecto.
  3. Elige Visual C# → Windows → Aplicación de Windows Forms.
  4. Escribe un nombre (ej. MiPrimeraApp) y pulsa Aceptar.

Se abrirá Form1.cs [Diseño]. En el Cuadro de herramientas (View → Toolbox) están todos los controles.

La ventana Propiedades

Al seleccionar un control, la ventana Propiedades (F4) muestra sus atributos. Cada propiedad es un valor que puedes cambiar en el diseñador y que también puedes leer o modificar desde código.

Propiedad Qué significa Ejemplo
Name Nombre interno del control. Es el identificador que usarás en el código para referirte a él. No se muestra al usuario. btnMostrar
Text Texto visible al usuario (lo que aparece en el botón, etiqueta o caja). "Mostrar"
Size Ancho y alto en píxeles (Width × Height). 100, 30
Location Posición del control dentro del formulario, en coordenadas (X, Y). X es la distancia desde el borde izquierdo; Y desde el borde superior. 20, 40
Enabled Si el control está activo (true) o deshabilitado/gris (false). Un control deshabilitado no recibe clics ni teclas. true / false
Visible Si el control se muestra (true) o se oculta (false). true / false
Font Tipo de letra, tamaño y estilo del texto. Segoe UI, 12pt, Negrita
BackColor Color de fondo del control. White, Control, etc.
ForeColor Color del texto. Black, Red, etc.
Convención de nombres: usa prefijos según el tipo: txt (TextBox), btn (Button), lbl (Label), cbo (ComboBox), chk (CheckBox), rdo (RadioButton), lst (ListBox), lv (ListView), num (NumericUpDown), grp (GroupBox), menu (MenuStrip). Esto facilita leer el código y evita confusiones cuando hay varios controles del mismo tipo.

Estructura de un formulario en código

using System;                    // trae tipos básicos (string, int, Exception...)
using System.Windows.Forms;      // trae Form, Button, MessageBox, etc.

namespace MiPrimeraApp           // espacio de nombres del proyecto
{
    public partial class Form1 : Form   // Form1 hereda de Form (es una ventana)
    {
        public Form1()
        {
            InitializeComponent(); // método generado por el diseñador:
                                   // crea y coloca todos los controles que arrastraste
        }

        private void btnMostrar_Click(object sender, EventArgs e)
        {
            // sender: el objeto que disparó el evento (aquí, el botón btnMostrar)
            // e: objeto con información adicional del evento (para Click no trae datos extra)
            MessageBox.Show("¡Hola desde Windows Forms!");
        }
    }
}

Explicación de cada parte:

  • using System; permite usar tipos como string, int, Exception sin escribir System.string.
  • using System.Windows.Forms; permite usar Form, Button, MessageBox, etc.
  • namespace MiPrimeraApp agrupa las clases del proyecto bajo un nombre para evitar choques con otros proyectos.
  • public partial class Form1 : Form declara una clase llamada Form1 que hereda de Form, es decir, es una ventana. partial significa que la clase está repartida en dos archivos: el que tú editas (Form1.cs) y el que genera el diseñador (Form1.Designer.cs).
  • public Form1() es el constructor: se ejecuta una sola vez al crear el formulario. InitializeComponent() crea los controles definidos en el diseñador.
  • private void btnMostrar_Click(...): private porque solo el formulario lo necesita (ver modificadores de acceso); void porque no devuelve valor; recibe sender y e (ver Clase 3).

Ejecutar la aplicación

Pulsa F5 (depurar) o Ctrl+F5 (ejecutar sin depurar). Se abrirá la ventana. Para detener, cierra la ventana o pulsa el cuadrado rojo de VS.

Cuidado: no escribas código dentro del método InitializeComponent(). Ese método lo genera el diseñador y se sobrescribe si mueves controles. Si lo modificas a mano, tus cambios se perderán.

Clase 2 — Controles básicos

Label, TextBox, Button y MessageBox

Control Para qué sirve Propiedades clave
Label Mostrar texto fijo (títulos, instrucciones, resultados). El usuario no lo puede editar. Text, Font, ForeColor, AutoSize
TextBox Entrada de texto por el usuario. Text, MaxLength, PasswordChar, ReadOnly, Multiline
Button Ejecutar una acción al hacer clic. Text, Enabled, DialogResult
MessageBox Mostrar mensajes modales (ventana que bloquea hasta que el usuario responde). No se arrastra: se invoca desde código. Se usa con MessageBox.Show(...)

Leer y escribir en controles

Cada control tiene una propiedad Text que contiene lo que muestra. Para leer lo que escribió el usuario, accedes a txtNombre.Text. Para escribir, le asignas un valor.

// Leer lo que escribió el usuario
string nombre = txtNombre.Text;

// Escribir en un Label
lblResultado.Text = "Hola " + nombre;

// Limpiar una caja de texto
txtNombre.Clear();   // equivale a txtNombre.Text = "";

// Asignar foco (colocar el cursor en esa caja)
txtNombre.Focus();

// Seleccionar todo el texto de la caja
txtNombre.SelectAll();

Explicación:

  • txtNombre.Text devuelve un string con el contenido actual.
  • lblResultado.Text = ... cambia el texto visible del Label.
  • Clear() es un método del TextBox que borra su contenido.
  • Focus() es un método que hace que el control reciba el teclado.

MessageBox.Show: todos sus parámetros

MessageBox.Show es un método estático (se llama desde la clase, no desde un objeto) que muestra un cuadro de diálogo y devuelve un valor DialogResult indicando qué botón pulsó el usuario.

// Forma más simple: solo el mensaje
MessageBox.Show("Operación realizada");

// Con título de la ventana
MessageBox.Show("Datos guardados", "Confirmación");

// Con ícono y botones, guardando el resultado
DialogResult r = MessageBox.Show(
    "¿Desea salir?",          // texto del mensaje
    "Pregunta",               // título de la ventana
    MessageBoxButtons.YesNo,  // botones que aparecen
    MessageBoxIcon.Question); // ícono que aparece

if (r == DialogResult.Yes)
{
    Application.Exit();
}

Parámetros de MessageBox.Show:

Parámetro Tipo Qué significa
texto string Mensaje que se muestra al usuario.
título (caption) string Texto de la barra de título de la ventana.
botones MessageBoxButtons Qué botones aparecen: OK, OKCancel, YesNo, YesNoCancel, AbortRetryIgnore, RetryCancel.
ícono MessageBoxIcon Ícono decorativo: Information, Warning, Error, Question, None.
botón por defecto MessageBoxDefaultButton Cuál botón está preseleccionado (opcional).

El valor devuelto es un DialogResult: Yes, No, OK, Cancel, Abort, Retry, Ignore, None. Se compara con if (r == DialogResult.Yes).

Ejemplo completo: saludo

Formulario con txtNombre, btnMostrar y lblSaludo.

private void btnMostrar_Click(object sender, EventArgs e)
{
    // string.IsNullOrEmpty devuelve true si el texto es null o ""
    if (string.IsNullOrEmpty(txtNombre.Text))
    {
        MessageBox.Show("Escriba un nombre", "Aviso",
            MessageBoxButtons.OK, MessageBoxIcon.Warning);
        return; // sale del método: no sigue ejecutando
    }
    lblSaludo.Text = "Hola, " + txtNombre.Text;
}

Explicación:

  • sender es el objeto que disparó el evento (el botón). No lo usamos aquí, pero es obligatorio en la firma.
  • EventArgs e contiene datos del evento. Para Click no trae información extra, pero debe estar.
  • return; corta la ejecución del método: si el nombre está vacío, no llega a la línea que asigna el saludo.
Tip: usa string.IsNullOrEmpty en lugar de txt.Text == "". Es más seguro porque también detecta el valor null (cuando la propiedad nunca fue asignada).

Clase 3 — Eventos

¿Qué es un evento?

Un evento es una acción que ocurre en el programa (clic, tecla, cambio de texto, carga del formulario). Tú escribes un manejador de eventos (un método) que se ejecuta cuando ocurre. Visual Studio conecta el evento del control con tu método.

Cómo crear un manejador

  1. Selecciona el control en el diseñador.
  2. En la ventana Propiedades, pulsa el ícono del rayo (Eventos).
  3. Doble clic en el evento (ej. Click) y VS crea el método con la firma correcta.

Firma del manejador y sus parámetros

private void btnAceptar_Click(object sender, EventArgs e)
{
    // sender: el objeto que disparó el evento.
    //         Si varios botones comparten el mismo manejador,
    //         puedes distinguirlos con: if (sender == btnAceptar) ...
    // e: objeto EventArgs con información adicional.
    //    Para Click no trae datos; para KeyPress trae la tecla;
    //    para MouseClick trae coordenadas del mouse.
}

Explicación de cada parámetro:

  • sender (tipo object): referencia al control que generó el evento. Como es object, si necesitas usarlo debes convertirlo: Button b = (Button)sender;.
  • e (tipo EventArgs o una subclase): contiene datos del evento. Por ejemplo, en KeyPress es KeyPressEventArgs y trae e.KeyChar (la tecla presionada) y e.Handled (para bloquear la tecla).

Eventos más usados

Evento Cuándo se dispara Control típico Datos en e
Click Al hacer clic con el mouse Button, Label Ninguno relevante
TextChanged Cada vez que cambia el texto TextBox Ninguno relevante
KeyPress Al presionar una tecla que genera un carácter TextBox e.KeyChar, e.Handled
KeyDown Al presionar cualquier tecla (incluye flechas, F1, etc.) TextBox, Form e.KeyCode, e.Handled
Load Al cargar el formulario, antes de mostrarse Form Ninguno relevante
FormClosing Antes de cerrar el formulario Form e.Cancel (para cancelar el cierre)
SelectedIndexChanged Al cambiar la selección ComboBox, ListBox Ninguno relevante

Ejemplo: TextChanged y KeyPress

// Mostrar en un Label lo que se escribe en tiempo real
private void txtNombre_TextChanged(object sender, EventArgs e)
{
    lblVista.Text = txtNombre.Text;
}

// Permitir solo dígitos en un TextBox
private void txtEdad_KeyPress(object sender, KeyPressEventArgs e)
{
    // e.KeyChar es el carácter de la tecla presionada.
    // char.IsDigit devuelve true si es 0-9.
    // (char)8 es el código ASCII de Backspace (borrar).
    if (!char.IsDigit(e.KeyChar) && e.KeyChar != (char)8)
    {
        e.Handled = true; // bloquea la tecla: no se escribe
    }
}

Explicación:

  • e.KeyChar es un char con la tecla presionada.
  • char.IsDigit(e.KeyChar) devuelve true si es un dígito del 0 al 9.
  • (char)8 es el código ASCII de Backspace; lo permitimos para que el usuario pueda borrar.
  • e.Handled = true indica que el evento ya fue manejado y que el carácter no debe escribirse en el TextBox.

Evento Load del formulario

private void Form1_Load(object sender, EventArgs e)
{
    // Se ejecuta al abrir el formulario, antes de que sea visible.
    // Ideal para inicializar valores, llenar ComboBox, etc.
    cboTurno.Items.Add("Mañana");
    cboTurno.Items.Add("Tarde");
    cboTurno.SelectedIndex = 0; // selecciona el primer elemento
}

Explicación:

  • Items.Add("...") agrega un elemento a la colección del ComboBox.
  • SelectedIndex = 0 selecciona el primer elemento (los índices empiezan en 0). -1 significa "ninguno seleccionado".

Compartir un manejador entre varios controles

private void BotonCompartido_Click(object sender, EventArgs e)
{
    // Convertimos sender a Button para acceder a sus propiedades
    Button b = (Button)sender;
    MessageBox.Show("Pulsaste: " + b.Text);
}

Para que varios botones usen este manejador, en el diseñador seleccionas cada botón, vas a Eventos → Click y eliges el mismo método. Así sender te dice cuál fue.

Cuidado: si dentro de TextChanged modificas el mismo TextBox, puedes provocar un bucle infinito (el evento se dispara otra vez). Modifica otro control, no el que dispara el evento.

Clase 4 — Validación de datos

¿Por qué validar?

El usuario puede dejar campos vacíos, escribir letras donde van números o seleccionar opciones inválidas. Validar evita errores en tiempo de ejecución y datos inconsistentes.

Validación con MessageBox (la más simple)

private void btnGuardar_Click(object sender, EventArgs e)
{
    // 1) Validar campo vacío
    if (string.IsNullOrEmpty(txtNombre.Text))
    {
        MessageBox.Show("El nombre es obligatorio");
        txtNombre.Focus(); // coloca el cursor en el campo
        return;            // sale del método: no sigue validando
    }

    // 2) Validar que sea número con TryParse
    int edad;
    if (!int.TryParse(txtEdad.Text, out edad))
    {
        MessageBox.Show("La edad debe ser un número");
        txtEdad.Focus();
        return;
    }

    // 3) Validar rango
    if (edad < 1 || edad > 120)
    {
        MessageBox.Show("La edad debe estar entre 1 y 120");
        return;
    }

    MessageBox.Show("Datos válidos");
}

Explicación de int.TryParse:

  • Primer parámetro (txtEdad.Text): el texto que se quiere convertir a entero.
  • Segundo parámetro (out edad): variable donde se guarda el resultado si la conversión tiene éxito. La palabra out indica que el método asigna ese valor.
  • Valor devuelto: true si pudo convertir, false si no. Por eso usamos if (!int.TryParse(...)): si no pudo convertir, mostramos error.
  • Si la conversión falla, edad queda en 0, pero no lanzamos excepción.
TryParse es un método propio de los tipos numéricos (int, double, DateTime, etc.) para convertir texto a número de forma segura, sin lanzar excepción. Vive en la estructura int, dentro de System. No tiene nada que ver con consultas.

LINQ, en cambio, es un conjunto de métodos para consultar, filtrar, ordenar y proyectar colecciones (Where, Select, OrderBy, from ... in ...). Vive en System.Linq y trabaja sobre IEnumerable<T>. Lo verás en la sección Parse, TryParse y LINQ.

Validación con ErrorProvider

ErrorProvider muestra un ícono rojo junto al control inválido. Se arrastra desde el Cuadro de herramientas.

private void btnValidar_Click(object sender, EventArgs e)
{
    errorProvider1.Clear(); // quita todos los errores previos
    bool ok = true;

    if (string.IsNullOrEmpty(txtNombre.Text))
    {
        // SetError(control, mensaje): muestra el ícono junto al control
        errorProvider1.SetError(txtNombre, "Campo obligatorio");
        ok = false;
    }

    if (!ok)
    {
        MessageBox.Show("Corrija los campos marcados");
    }
}

Explicación de SetError:

  • Primer parámetro: el control al que se le asocia el error.
  • Segundo parámetro: el mensaje que aparece al pasar el mouse sobre el ícono. Si pasas "", se quita el error.

errorProvider1.Clear() recorre todos los controles y borra los errores asociados. Úsalo al inicio de cada validación.

Validación con KeyPress (entrada controlada)

// Solo números en txtTelefono

{
    // Si no es dígito y no es Backspace, bloqueamos

Convertir datos: Parse, TryParse y Convert

Para convertir texto a número hay varias formas. Aquí usamos Parse y TryParse, que son los que viste en clase.

Método Qué hace Qué devuelve Si falla
int.Parse(s) Convierte texto a entero int Lanza FormatException (o ArgumentNullException si s es null)
int.TryParse(s, out n) Intenta convertir bool (éxito o no) Devuelve false, no lanza
double.Parse(s) Convierte a decimal double Lanza FormatException
Convert.ToInt32(s) Convierte con manejo de null y "" int null o "" → devuelve 0; texto no numérico → lanza excepción
Recomendación: para datos escritos por el usuario usa siempre TryParse. Es más seguro que Parse porque no rompe el programa si el usuario escribe mal. Si usas Parse, valida antes el vacío y envuélvelo en try/catch.

Usar Parse con validación previa (sin Convert)

Si en clase viste Parse, esta es la forma segura de usarlo: validar vacío y tipo antes de convertir.

private void btnConvertir_Click(object sender, EventArgs e)
{
    // 1) Validar vacío
    if (string.IsNullOrEmpty(txtAnio.Text))
    {
        MessageBox.Show("El año es obligatorio");
        return;
    }

    // 2) Validar que sea número (TryParse solo para comprobar)
    int anio;
    if (!int.TryParse(txtAnio.Text, out anio))
    {
        MessageBox.Show("El año debe ser un número");
        return;
    }

    // 3) Ahora sí, usar el valor
    lblResultado.Text = "Año registrado: " + anio;
}

Alternativa con Parse dentro de try/catch (si no quieres usar TryParse): 

private void btnConvertir_Click(object sender, EventArgs e)
{
    if (string.IsNullOrEmpty(txtAnio.Text))
    {
        MessageBox.Show("El año es obligatorio");
        return;
    }

    try
    {
        int anio = int.Parse(txtAnio.Text);
        lblResultado.Text = "Año registrado: " + anio;
    }
    catch (FormatException)
    {
        MessageBox.Show("El año debe ser un número válido");
    }
}

Clase 5 — Controles de selección

CheckBox

Permite marcar o desmarcar una opción. Se puede marcar varias a la vez.

// Checked: true si está marcado, false si no
if (chkTerminos.Checked)
{
    MessageBox.Show("Términos aceptados");
}

// Text: el texto visible del CheckBox
string opcion = chkTerminos.Text;

// Marcar/desmarcar por código
chkTerminos.Checked = true;

// CheckState: estado con tres valores (Checked, Unchecked, Indeterminate)
// Útil si el CheckBox tiene ThreeState = true

Explicación:

  • Checked: propiedad booleana con el estado de marcado.
  • CheckState: propiedad de tipo CheckState con tres valores posibles. Solo tiene sentido si ThreeState = true.
  • Text: lo que se ve al lado de la casilla.

RadioButton

Permite elegir una sola opción dentro de un grupo. Los RadioButton que están dentro del mismo contenedor (Form, GroupBox o Panel) son mutuamente excluyentes.

if (rdoManana.Checked)
    MessageBox.Show("Turno mañana");
else if (rdoTarde.Checked)
    MessageBox.Show("Turno tarde");
else
    MessageBox.Show("Seleccione un turno");

Explicación:

  • Checked indica si ese RadioButton está seleccionado. Como solo uno puede estarlo por grupo, con revisar los dos cubres todas las posibilidades.
  • Si ninguno está marcado, ambos Checked son false; por eso el else.
Tip: si tienes dos grupos de RadioButton en el mismo formulario, colócalos en GroupBox distintos. Si no, se comportarán como un solo grupo y seleccionar uno desmarcará el del otro grupo.

ComboBox

Lista desplegable. Puede ser de solo selección (DropDownList) o permitir escribir (DropDown).

// Agregar elementos por código
cboTaller.Items.Add("Programación");
cboTaller.Items.Add("Bases de Datos");
cboTaller.Items.Add("Redes");

// Seleccionar el primero
cboTaller.SelectedIndex = 0;

// Leer la selección
if (cboTaller.SelectedIndex == -1)
    MessageBox.Show("Seleccione un taller");
else
    MessageBox.Show("Elegiste: " + cboTaller.SelectedItem.ToString());

// Limpiar
cboTaller.Items.Clear();

Explicación de propiedades:

  • Items: colección de elementos. Add agrega, Clear borra todos.
  • SelectedIndex: índice del elemento seleccionado. 0 es el primero, -1 significa "ninguno".
  • SelectedItem: el objeto seleccionado (puede ser un string o un objeto).
  • Text: el texto que se muestra en la parte visible del ComboBox.
  • DropDownStyle: DropDownList (solo elegir de la lista) o DropDown (permite escribir).

Ejemplo integrador: inscripción

private void btnInscribir_Click(object sender, EventArgs e)
{
    if (string.IsNullOrEmpty(txtNombre.Text))
    { MessageBox.Show("Escriba su nombre"); return; }

    if (cboTaller.SelectedIndex == -1)
    { MessageBox.Show("Seleccione un taller"); return; }

    // Operador ternario: condición ? valorSiTrue : valorSiFalse
    string turno = rdoManana.Checked ? "Mañana" :
                   rdoTarde.Checked  ? "Tarde"  : "";

    if (turno == "")
    { MessageBox.Show("Seleccione un turno"); return; }

    if (!chkTerminos.Checked)
    { MessageBox.Show("Debe aceptar los términos"); return; }

    lblResumen.Text = "Inscrito: " + txtNombre.Text +
                      " — Taller: " + cboTaller.SelectedItem +
                      " — Turno: " + turno;
}

Explicación del ternario:

  • condición ? valorA : valorB: si la condición es true, devuelve valorA; si es false, valorB.
  • Aquí se lee: "si rdoManana.Checked es true, turno = 'Mañana'; si no, si rdoTarde.Checked es true, turno = 'Tarde'; si no, turno = ''".

Lista de elementos visibles. Ideal para mostrar registros simples.

Explicación de miembros:

  • Items: colección de elementos del ListBox. Tiene métodos Add, Remove, RemoveAt, Clear.

Muestra datos en columnas (modo Details). Útil para varios campos por registro.

{
    lvEstudiantes.View = View.Details;       // modo columnas
    lvEstudiantes.Columns.Add("Nombre", 150); // texto y ancho en píxeles
    lvEstudiantes.Columns.Add("Carrera", 120);

}

ListViewItem fila = new ListViewItem("María Pérez"); // primera columna
fila.SubItems.Add("Informática");                    // segunda columna
fila.SubItems.Add("18");                             // tercera columna
lvEstudiantes.Items.Add(fila);

// Leer seleccionado
if (lvEstudiantes.SelectedItems.Count > 0)

  • SubItems.Add: agrega el valor de las columnas siguientes.

Colecciones en memoria

// Lista simple de textos
List<string> nombres = new List<string>();
nombres.Add("María");    // agrega al final
nombres.Add("Juan");
nombres.Remove("Juan");  // elimina por valor
int total = nombres.Count; // cantidad de elementos

// Lista de objetos (recomendado)
public class Estudiante
{
    // Propiedades autoimplementadas: get y set públicos
    public string Nombre { get; set; }
    public string Carrera { get; set; }
    public int Edad { get; set; }
}

List<Estudiante> estudiantes = new List<Estudiante>();
estudiantes.Add(new Estudiante
{
    Nombre = "María",
    Carrera = "Informática",
    Edad = 18
});

// Recorrer con foreach
foreach (Estudiante est in estudiantes)
{
    Console.WriteLine(est.Nombre);
}

// Acceder por índice
Estudiante primero = estudiantes[0];
int cantidad = estudiantes.Count;

Explicación:

  • List<T> es una colección genérica: T es el tipo de elementos. List<string> guarda textos; List<Estudiante>, objetos.

  • Count: cantidad de elementos (propiedad, no método).
  • [0]: acceso por índice (empieza en 0).
  • { get; set; }: propiedades autoimplementadas. get devuelve el valor; set lo asigna.
Consejo: cuando uses objetos en un ListBox o ListView, sobrescribe ToString() en la clase para que se muestre algo legible en lugar del nombre de la clase.

Clase 7 — Navegación entre formularios

Crear un segundo formulario

Proyecto → Agregar Windows Form. Se llamará Form2 (o el nombre que elijas).

Abrir Form2 desde Form1

private void btnAbrir_Click(object sender, EventArgs e)
{
    Form2 f2 = new Form2(); // crea una instancia nueva del formulario
    f2.Show();              // abre sin bloquear Form1 (no modal)
    // f2.ShowDialog();     // abre como modal: bloquea Form1 hasta cerrar Form2
}

Explicación:

  • new Form2(): crea una instancia nueva. Cada vez que lo llamas, obtienes un formulario distinto con su propio estado.
  • Show(): muestra el formulario y devuelve el control inmediatamente. El usuario puede interactuar con ambos formularios.
  • ShowDialog(): muestra el formulario como modal. El código que sigue no se ejecuta hasta que se cierre. Devuelve un DialogResult.

Pasar datos de Form1 a Form2

// En Form2, declarar un campo público
public string NombreRecibido;

// En Form1, antes de mostrar
Form2 f2 = new Form2();
f2.NombreRecibido = txtNombre.Text; // asigna antes de Show
f2.Show();

// En Form2_Load, usar el dato
private void Form2_Load(object sender, EventArgs e)
{
    lblSaludo.Text = "Hola " + NombreRecibido;
}

Explicación:

  • El campo public string NombreRecibido es visible desde fuera de la clase. Form1 puede asignarlo antes de mostrar el formulario.
  • Se asigna antes de Show() para que cuando se dispare el evento Load de Form2, el dato ya esté disponible.

Recibir datos de vuelta (Form2 → Form1)

// En Form2
public string Resultado;

private void btnAceptar_Click(object sender, EventArgs e)
{
    Resultado = txtDato.Text;
    this.DialogResult = DialogResult.OK; // indica que se aceptó
    this.Close();                          // cierra Form2
}

// En Form1
private void btnPedir_Click(object sender, EventArgs e)
{
    Form2 f2 = new Form2();
    // ShowDialog devuelve el DialogResult que se asignó al cerrar
    if (f2.ShowDialog() == DialogResult.OK)
    {
        lblRecibido.Text = f2.Resultado;
    }
}

Explicación:

  • this se refiere al formulario actual (Form2).
  • DialogResult = DialogResult.OK indica que el usuario aceptó. Al cerrar con la X, el resultado sería Cancel.
  • ShowDialog() devuelve el DialogResult del formulario. Comparamos con DialogResult.OK para saber si el usuario aceptó.

Compartir datos entre varios formularios

La forma más simple es una clase estática que guarde la lista compartida (ver static).

public static class Datos
{
    // static: pertenece a la clase, no a una instancia.
    // Todos los formularios ven la MISMA lista.
    public static List<Estudiante> Estudiantes = new List<Estudiante>();
}

Cualquier formulario puede usar Datos.Estudiantes sin necesidad de pasarla. La lista se crea una sola vez y persiste mientras la aplicación esté abierta.

Cuidado: no uses new Form1() dentro de Form2 para volver al menú. Eso crea otra instancia y pierdes los datos. Usa this.Close() o this.Hide() y vuelve a mostrar la instancia existente.

Clase 9 — CRUD en memoria

¿Qué es CRUD?

Create (crear), Read (leer/listar), Update (actualizar/editar), Delete (eliminar). Es la base de cualquier sistema de gestión.

Modelo de datos

public class Libro
{
    // Propiedades autoimplementadas
    public string Titulo { get; set; }
    public string Autor { get; set; }
    public int Anio { get; set; }

    // ToString se llama automáticamente al mostrar el objeto en un ListBox
    public override string ToString()
    {
        return Titulo + " — " + Autor + " (" + Anio + ")";
    }
}

public static class Datos
{
    // Lista compartida por todos los formularios.
    // static: una sola copia para toda la aplicación (ver Fundamentos).
    public static List<Libro> Libros = new List<Libro>();
}

Crear (C)

private void btnAgregar_Click(object sender, EventArgs e)
{
    // Validar vacío
    if (string.IsNullOrEmpty(txtTitulo.Text))
    { MessageBox.Show("Título obligatorio"); return; }

    // Validar año: vacío + número con TryParse
    if (string.IsNullOrEmpty(txtAnio.Text))
    { MessageBox.Show("El año es obligatorio"); return; }

    int anio;
    if (!int.TryParse(txtAnio.Text, out anio))
    { MessageBox.Show("Año inválido"); return; }

    // Crear objeto con inicializador
    Libro nuevo = new Libro
    {
        Titulo = txtTitulo.Text,
        Autor = txtAutor.Text,
        Anio = anio
    };

    Datos.Libros.Add(nuevo); // agregar a la lista compartida
    CargarLista();           // refrescar el ListBox
    LimpiarCampos();         // limpiar los TextBox
}

Explicación:

  • El inicializador de objeto new Libro { ... } crea el objeto y asigna sus propiedades en una sola expresión.
  • Datos.Libros.Add(nuevo) agrega el objeto al final de la lista compartida (porque Libros es static).
  • CargarLista() y LimpiarCampos() son métodos auxiliares que veremos abajo.
  • Si prefieres usar Parse en lugar de TryParse, envuélvelo en try/catch (FormatException) y valida el vacío antes.

Leer / listar (R)

private void CargarLista()
{
    lstLibros.Items.Clear();           // borra lo que había
    foreach (Libro l in Datos.Libros)  // recorre la lista
    {
        lstLibros.Items.Add(l);        // agrega cada objeto al ListBox
    }
}

private void Form1_Load(object sender, EventArgs e)
{
    CargarLista(); // carga al abrir el formulario
}

Explicación:

  • Items.Clear() vacía el ListBox para no duplicar elementos al recargar.
  • foreach (Libro l in Datos.Libros) recorre cada elemento de la lista. l es de tipo Libro.
  • Items.Add(l) agrega el objeto. El ListBox llama automáticamente a ToString() para mostrarlo.

Actualizar (U)

private void btnEditar_Click(object sender, EventArgs e)
{
    if (lstLibros.SelectedIndex == -1)
    { MessageBox.Show("Seleccione un libro"); return; }

    // Validar el año antes de convertir
    if (string.IsNullOrEmpty(txtAnio.Text))
    { MessageBox.Show("El año es obligatorio"); return; }

    int anio;
    if (!int.TryParse(txtAnio.Text, out anio))
    { MessageBox.Show("Año inválido"); return; }

    // Convertir SelectedItem (object) a Libro
    Libro seleccionado = (Libro)lstLibros.SelectedItem;
    seleccionado.Titulo = txtTitulo.Text;
    seleccionado.Autor = txtAutor.Text;
    seleccionado.Anio = anio;

    CargarLista(); // refrescar para ver los cambios
}

// Al seleccionar en la lista, cargar los datos en los TextBox
private void lstLibros_SelectedIndexChanged(object sender, EventArgs e)
{
    if (lstLibros.SelectedIndex == -1) return;
    Libro l = (Libro)lstLibros.SelectedItem;
    txtTitulo.Text = l.Titulo;
    txtAutor.Text = l.Autor;
    txtAnio.Text = l.Anio.ToString(); // ToString convierte int a string
}

Explicación:

  • (Libro)lstLibros.SelectedItem: conversión explícita (cast) de object a Libro. Necesaria porque SelectedItem devuelve object.
  • l.Anio.ToString(): convierte un entero a texto para asignarlo a txtAnio.Text.
  • Al modificar las propiedades del objeto seleccionado, cambias el objeto real de la lista (no una copia), porque los objetos son referencias.

Eliminar (D)

private void btnEliminar_Click(object sender, EventArgs e)
{
    if (lstLibros.SelectedIndex == -1)
    { MessageBox.Show("Seleccione un libro"); return; }

    DialogResult r = MessageBox.Show(
        "¿Eliminar este libro?", "Confirmar",
        MessageBoxButtons.YesNo, MessageBoxIcon.Question);

    if (r == DialogResult.Yes)

Explicación:

  • RemoveAt(indice): elimina el elemento en esa posición. El índice del ListBox coincide con el de la lista porque ambos se cargan en el mismo orden.

private void LimpiarCampos()

Manejo de errores básico con try/catch

private void btnConvertir_Click(object sender, EventArgs e)
{
    try
    {
        // Código que puede fallar
        int n = int.Parse(txtNumero.Text);
        lblResultado.Text = "Doble: " + (n * 2);
    }
    catch (FormatException)
    {
        // Se ejecuta si Parse no pudo convertir (texto no numérico)
        MessageBox.Show("Debe escribir un número válido");
    }
    catch (Exception ex)
    {
        // Se ejecuta ante cualquier otra excepción.
        // ex.Message contiene la descripción del error.
        MessageBox.Show("Error inesperado: " + ex.Message);
    }
    finally
    {
        // (Opcional) Se ejecuta siempre, haya error o no
        // Ideal para liberar recursos
    }
}

Explicación:

  • try: bloque con el código que puede lanzar una excepción.
  • catch (TipoException): bloque que se ejecuta si ocurre ese tipo de excepción. Se pueden poner varios catch, del más específico al más general.
  • FormatException: se lanza cuando Parse recibe texto que no es un número.
  • Exception ex: captura cualquier excepción. ex.Message es la descripción; ex.StackTrace muestra dónde ocurrió.
  • finally: se ejecuta siempre, haya o no error. Útil para cerrar archivos o conexiones.
Para la defensa oral: ten claro por qué elegiste cada control, dónde guardas los datos, cómo eliminas un registro y dónde usaste validación. Esas son las preguntas típicas.

Errores comunes y cómo resolverlos

Error Causa probable Solución
"No se ha declarado el nombre..." Control renombrado en el diseñador pero el código usa el nombre viejo Verifica el Name del control en Propiedades y actualiza el código
NullReferenceException Usar un control u objeto que no fue inicializado (está en null) Revisa que el control exista y que la lista no sea null
FormatException Convertir texto vacío o no numérico con Parse Valida el vacío antes y usa TryParse o try/catch
Bucle infinito en TextChanged Modificas el mismo TextBox dentro de su propio evento Modifica otro control o usa una bandera
Se pierden los datos al volver al menú Creaste una nueva instancia del formulario con new Form1() Usa una clase estática Datos o Show/Hide
Los RadioButton se desmarcan entre sí Están en el mismo contenedor (Form, Panel) Colócalos en GroupBox distintos
InvalidOperationException al modificar la lista mientras la recorres Eliminas dentro de un foreach Usa un for inverso o recarga la lista después
InvalidCastException Haces un cast a un tipo incorrecto (ej. (Libro)lst.SelectedItem cuando guardaste strings) Verifica qué tipo de objeto guardaste en la colección
