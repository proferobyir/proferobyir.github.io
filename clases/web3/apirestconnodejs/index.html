Guía Práctica: API REST con Express y MySQL

Construcción paso a paso de una API REST funcional, segura y lista para producción (CORS + Remote Binding + Subida de Archivos).

Node.js Express MySQL2 CORS dotenv Multer

1. Configuración del Entorno

Crea el proyecto e instala las dependencias base en tu terminal:

mkdir api-express-mysql
cd api-express-mysql
npm init -y
npm install express mysql2 cors dotenv multer
⚠️ ¡Atención con la carpeta 'uploads'!

Debes crear manualmente la carpeta uploads/ en la raíz de tu proyecto para que la librería Multer pueda almacenar allí las imágenes subidas por los usuarios.

2. Esquema de Base de Datos

Para esta práctica utilizaremos una base de datos con un catálogo de 100 productos de computación. Descarga o abre el script SQL listo para ejecutar:

📄 Descargar Script SQL (schema.sql)

Si prefieres ejecutar los comandos manualmente en MySQL Workbench o phpMyAdmin, asegúrate de importar el archivo completo o usar el siguiente comando desde tu terminal:

mysql -u root -p < schema.sql
📌 Nota sobre el script:

El archivo incluye la creación automática de la base de datos tienda, la estructura de la tabla productos y la inserción de 100 registros para pruebas de filtrado y búsqueda.

3. Código Principal (index.js)

Copia el servidor ejecutable completo:

// Cargamos las variables de entorno desde el archivo .env si existe
require('dotenv').config();

// ============================================================================
// CONCEPTO CLAVE: 'process.env'
// ----------------------------------------------------------------------------
// En Node.js, 'process' es un objeto global del proceso activo.
// La propiedad 'process.env' almacena las VARIABLES DE ENTORNO.
// Sirven para:
//   1. SEGURIDAD: Guardar contraseñas o claves sin escribirlas en el código.
//   2. FLEXIBILIDAD: Usar puertos o servidores distintos en desarrollo y nube.
// ============================================================================

// Módulo nativo de Node.js para gestionar rutas de archivos en el sistema operativo
const path = require('path');

// Framework principal para la creación de la API y manejo de rutas HTTP
const express = require('express');

// Conector de base de datos MySQL con soporte nativo de Promises (async/await)
const mysql = require('mysql2/promise');

// Middleware para permitir peticiones HTTP desde orígenes/dominios cruzados
const cors = require('cors');

// Middleware para gestionar el procesamiento y subida de archivos (multipart/form-data)
const multer = require('multer');

// Instanciamos la aplicación principal de Express
const app = express();

// ============================================================================
// 1. CONFIGURACIÓN DE MIDDLEWARES Y ARCHIVOS ESTÁTICOS
// ============================================================================

// Habilitamos CORS globalmente para permitir peticiones desde React, Postman, etc.
app.use(cors());

// Permite a Express procesar cuerpos de petición (body) en formato JSON
app.use(express.json());

// Servimos la carpeta 'uploads' de manera pública como archivos estáticos.
// Esto permite acceder a las imágenes subidas directo desde el navegador o frontend:
// Ejemplo: http://localhost:3000/uploads/1700000000000-foto.jpg
app.use('/uploads', express.static(path.join(__dirname, 'uploads')));

// ============================================================================
// 2. CONFIGURACIÓN DE MULTER (Subida y Almacenamiento de Archivos)
// ============================================================================

// Definimos el motor de almacenamiento de archivos en el disco duro
const storage = multer.diskStorage({
    // Definimos la carpeta de destino donde se guardarán los archivos
    destination: (req, file, cb) => {
        cb(null, 'uploads/'); // Asegúrate de tener creada la carpeta 'uploads'
    },
    // Personalizamos el nombre del archivo guardado para evitar sobreescrituras/duplicados
    filename: (req, file, cb) => {
        // Concatenamos un Timestamp actual (Date.now()) + el nombre original del archivo
        const nombreUnico = Date.now() + '-' + file.originalname;
        cb(null, nombreUnico);
    }
});

// Inicializamos la instancia de Multer pasando la configuración de almacenamiento
const upload = multer({ storage: storage });

// ============================================================================
// 3. CONEXIÓN A LA BASE DE DATOS (Connection Pool)
// ============================================================================

// Creamos un Pool de Conexiones para optimizar las consultas simultáneas
const db = mysql.createPool({
    // Aplicamos el patrón Fallback (Plan B) con process.env
    host: process.env.DB_HOST || 'localhost',
    user: process.env.DB_USER || 'root',
    password: process.env.DB_PASSWORD || '',
    database: process.env.DB_NAME || 'tienda',
    port: process.env.DB_PORT || 3306,
    waitForConnections: true, // Espera si no hay conexiones libres en el pool
    connectionLimit: 10       // Límite de conexiones simultáneas en la piscina
});

// ============================================================================
// 4. ENDPOINTS Y RUTAS
// ============================================================================

// ----------------------------------------------------------------------------
// ENDPOINT 1: GET /productos (Obtener todo el catálogo)
// ----------------------------------------------------------------------------
app.get('/productos', async (req, res) => {
    try {
        // Ejecutamos la consulta y desestructuramos las filas retornadas
        const [rows] = await db.query('SELECT * FROM productos');
        res.json(rows);
    } catch (error) {
        res.status(500).json({ error: error.message });
    }
});

// ----------------------------------------------------------------------------
// ENDPOINT 2: GET /productos/:id (Obtener por ID recibido en la URL)
// ----------------------------------------------------------------------------
app.get('/productos/:id', async (req, res) => {
    try {
        const { id } = req.params;

        // Validamos que el ID exista y sea un valor numérico válido
        if (!id || isNaN(id)) {
            return res.status(400).json({ 
                error: "El parámetro 'id' en la URL es requerido y debe ser un número válido." 
            });
        }

        // Consulta parametrizada con '?' para prevenir ataques de inyección SQL
        const [rows] = await db.query('SELECT * FROM productos WHERE id = ?', [id]);
        
        if (rows.length === 0) {
            return res.status(404).json({ mensaje: 'Producto no encontrado' });
        }
        
        res.json(rows[0]);
    } catch (error) {
        res.status(500).json({ error: error.message });
    }
});

// ----------------------------------------------------------------------------
// ENDPOINT 3: GET /productos/buscar/filtro (Búsqueda por Query String)
// ----------------------------------------------------------------------------
app.get('/productos/buscar/filtro', async (req, res) => {
    try {
        const { nombre } = req.query;

        // Validamos que el parámetro de búsqueda no venga vacío o solo con espacios
        if (!nombre || nombre.trim() === '') {
            return res.status(400).json({ 
                error: "Debes proporcionar el parámetro de búsqueda 'nombre' en la URL (ej: ?nombre=Lapiz)." 
            });
        }

        // Búsqueda parcial de texto utilizando el comodín SQL '%'
        const [rows] = await db.query('SELECT * FROM productos WHERE nombre LIKE ?', [`%${nombre}%`]);
        res.json(rows);
    } catch (error) {
        res.status(500).json({ error: error.message });
    }
});

// ----------------------------------------------------------------------------
// ENDPOINT 4: POST /productos (Insertar registro desde Body JSON)
// ----------------------------------------------------------------------------
app.post('/productos', async (req, res) => {
    try {
        const { nombre, precio } = req.body;

        // Validamos la existencia y tipo de dato de los campos recibidos en el JSON
        if (!nombre || precio === undefined || precio === null || isNaN(precio)) {
            return res.status(400).json({ 
                error: "Los campos 'nombre' y 'precio' (número) son obligatorios." 
            });
        }

        const [result] = await db.query(
            'INSERT INTO productos (nombre, precio) VALUES (?, ?)',
            [nombre, precio]
        );
        
        res.status(201).json({ id: result.insertId, nombre, precio });
    } catch (error) {
        res.status(500).json({ error: error.message });
    }
});

// ----------------------------------------------------------------------------
// ENDPOINT 5: POST /productos/con-imagen (Crear producto con subida de archivo)
// ----------------------------------------------------------------------------
// Interceptamos la petición con 'upload.single('imagen')' para procesar el archivo.
// El cliente debe enviar los datos mediante 'multipart/form-data'.
app.post('/productos/con-imagen', upload.single('imagen'), async (req, res) => {
    try {
        // En multipart/form-data, los campos de texto siguen estando en req.body
        const { nombre, precio } = req.body;

        // Validación de los campos de texto requeridos
        if (!nombre || precio === undefined || isNaN(precio)) {
            return res.status(400).json({ error: "Los campos 'nombre' y 'precio' son requeridos." });
        }

        // Validamos que el usuario haya seleccionado y adjuntado un archivo
        if (!req.file) {
            return res.status(400).json({ error: "Debes adjuntar un archivo de imagen en el campo 'imagen'." });
        }

        // Construimos la URL pública accesible del archivo guardado en el servidor
        // req.protocol = 'http', req.get('host') = 'localhost:3000', req.file.filename = nombre único
        const imagenUrl = `${req.protocol}://${req.get('host')}/uploads/${req.file.filename}`;

        // Insertamos el registro en la base de datos incluyendo la URL de la imagen
        const [result] = await db.query(
            'INSERT INTO productos (nombre, precio, imagen) VALUES (?, ?, ?)',
            [nombre, precio, imagenUrl]
        );

        res.status(201).json({
            id: result.insertId,
            nombre,
            precio,
            imagen: imagenUrl
        });

    } catch (error) {
        res.status(500).json({ error: error.message });
    }
});

// ----------------------------------------------------------------------------
// ENDPOINT 6: POST /categorias/:categoriaId/productos (Combinado Path + Body)
// ----------------------------------------------------------------------------
app.post('/categorias/:categoriaId/productos', async (req, res) => {
    try {
        const { categoriaId } = req.params;
        const { nombre, precio } = req.body;

        // Validamos tanto el parámetro recibido por la URL como el cuerpo JSON
        if (!categoriaId || isNaN(categoriaId)) {
            return res.status(400).json({ 
                error: "El parámetro 'categoriaId' en la URL es requerido y debe ser un número." 
            });
        }

        if (!nombre || precio === undefined || isNaN(precio)) {
            return res.status(400).json({ 
                error: "Los campos 'nombre' y 'precio' (número) son obligatorios." 
            });
        }

        const [result] = await db.query(
            'INSERT INTO productos (nombre, precio) VALUES (?, ?)',
            [nombre, precio]
        );

        res.status(201).json({
            id: result.insertId,
            categoriaId: Number(categoriaId),
            nombre,
            precio
        });
    } catch (error) {
        res.status(500).json({ error: error.message });
    }
});

// ============================================================================
// 5. ARRANQUE DEL SERVIDOR
// ============================================================================

// Obtenemos el puerto asignado por las variables de entorno o usamos 3000 por defecto
const PORT = process.env.PORT || 3000;

// Escuchamos en '0.0.0.0' para permitir conexiones locales y desde la red externa
app.listen(PORT, '0.0.0.0', () => {
    console.log(`Servidor activo y escuchando en el puerto ${PORT}`);
});

4. Ejecución del Servidor

Una vez creados los archivos y configurada la base de datos, abre tu terminal en la carpeta del proyecto y ejecuta el siguiente comando para poner en marcha la API REST:

node index.js

Si todo está correcto, verás el mensaje de confirmación en la consola:

Servidor activo y escuchando en el puerto 3000
💡 Tip de Desarrollo:

Recuerda que si realizas cambios en el archivo index.js, debes detener el servidor en la terminal presionando Ctrl + C y volver a ejecutar node index.js para que los cambios surtan efecto.

5. Referencia de Endpoints

Método Endpoint Parámetro Uso
GET /productos Ninguno Obtener todo el catálogo.
GET /productos/:id Path (req.params) Buscar un producto por su ID.
GET /productos/buscar/filtro Query (req.query) Filtrar por coincidencia de nombre.
POST /productos Body (req.body JSON) Crear un producto sin imagen.
POST /productos/con-imagen form-data (File + Text) Crear producto adjuntando un archivo de imagen.
POST /categorias/:categoriaId/productos Path + Body Crear relacionando parámetro en URL.
Notas Clave de Arquitectura:
  • CORS: Habilitado globalmente para evitar fallos cuando el cliente (React, Vue, Flutter, Postman) hace peticiones desde dominios distintos.
  • Archivos Estáticos: Se utiliza express.static para servir la carpeta de subidas públicamente.
  • Multer: Intercepta peticiones de tipo multipart/form-data para procesar la carga de archivos al disco.
  • IP Binding (`0.0.0.0`): Permite escuchar peticiones de cualquier interfaz de red local o pública.
  • Seguridad SQL: Las consultas parametrizadas evitan inyecciones destructivas.
