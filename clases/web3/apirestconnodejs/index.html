Guía Práctica: API REST con Express y MySQL

Construcción paso a paso de una API REST funcional, segura y lista para producción (CORS + Remote Binding).

Node.js Express MySQL2 CORS dotenv

1. Configuración del Entorno

Crea el proyecto e instala las dependencias base en tu terminal:

mkdir api-express-mysql
cd api-express-mysql
npm init -y
npm install express mysql2 cors dotenv
⚠️ ¡Atención con el paquete de MySQL!

Asegúrate de instalar mysql2 (con el número 2 al final) y NO el paquete heredado mysql. La versión 2 incluye soporte nativo para Promises e integraciones con async/await necesarias para este proyecto.

2. Esquema de Base de Datos

Para esta práctica utilizaremos una base de datos con un catálogo de 100 productos de computación. Descarga o abre el script SQL listo para ejecutar:

📄 Descargar Script SQL (schema.sql)

Si prefieres ejecutar los comandos manualmente en MySQL Workbench o phpMyAdmin, asegúrate de importar el archivo completo o usar el siguiente comando desde tu terminal:

mysql -u root -p < schema.sql
📌 Nota sobre el script:

El archivo incluye la creación automática de la base de datos tienda, la estructura de la tabla productos y la inserción de 100 registros para pruebas de filtrado y búsqueda.

3. Código Principal (index.js)

Copia el servidor ejecutable completo:

// Cargamos las variables de entorno desde el archivo .env si existe
require('dotenv').config();

// ============================================================================
// ¿QUÉ ES Y DÓNDE ESTÁ 'process.env'? (CONCEPTO CLAVE)
// ----------------------------------------------------------------------------
// En Node.js, 'process' es un objeto global que representa el proceso activo
// de tu programa. La propiedad 'process.env' (Environment Variables) almacena
// las VARIABLES DE ENTORNO de tu sistema operativo o del servidor en la nube.
//
// Viven FUERA del código de JavaScript (en tu sistema o en un archivo .env).
// Sirven para dos cosas fundamentales:
//   1. SEGURIDAD: Guardar contraseñas o claves sin escribirlas en el código.
//   2. FLEXIBILIDAD: Usar puertos o servidores distintos en desarrollo y nube.
// ============================================================================

// ============================================================================
// LÍNEA 1: Importamos la librería 'express' que instalamos con npm.
// Express es un "framework" (herramienta) que nos ayuda a crear servidores web
// de forma fácil y rápida sin necesidad de escribir código HTTP de bajo nivel.
// ============================================================================
const express = require('express');

// ============================================================================
// LÍNEA 2: Importamos 'mysql2/promise'. Es el conector que nos permite
// comunicarnos desde Node.js con nuestra base de datos MySQL.
// La barra '/promise' es vital: nos da acceso a 'async/await', permitiendo
// que JavaScript "espere" las respuestas de la base de datos limpiamente.
// ============================================================================
const mysql = require('mysql2/promise');

// ============================================================================
// LÍNEA 3: Importamos 'cors'. CORS es un mecanismo de seguridad.
// Por defecto, los navegadores bloquean peticiones entre dominios distintos.
// Esta librería habilita los permisos para que Postman, React, Flutter o web
// puedan hacerle consultas a nuestra API sin ser bloqueados.
// ============================================================================
const cors = require('cors');

// ============================================================================
// LÍNEA 4: Instanciamos la aplicación principal ejecutando la función de Express.
// La variable 'app' representa a nuestro servidor web, donde definiremos todas
// las rutas, reglas y filtros de nuestra API REST.
// ============================================================================
const app = express();

// ============================================================================
// 1. CONFIGURACIÓN DE MIDDLEWARES (Aduana o Filtros de la API)
// Un Middleware es un código que se ejecuta SIEMPRE ANTES de que la petición
// sea procesada por una ruta.
// ============================================================================

// Permite peticiones de origen cruzado (CORS) desde cualquier cliente.
app.use(cors());

// Le enseña a Express a entender información enviada en formato JSON.
// Transforma el cuerpo de las peticiones (Body) para poder leerlo en 'req.body'.
app.use(express.json());

// ============================================================================
// 2. CONEXIÓN A LA BASE DE DATOS (Connection Pool y Fallbacks)
// ============================================================================

// Creamos una "Piscina de Conexiones" (Connection Pool) compartida.
// Mantiene conexiones abiertas para prestárselas a las consultas de forma eficiente.
const db = mysql.createPool({
    // AQUÍ USAMOS process.env CON EL PATRÓN FALLBACK (Plan B):
    // 'process.env.DB_HOST || 'localhost'' le dice a Node:
    // "Busca en el sistema la variable DB_HOST; si no existe (undefined),
    // usa por defecto 'localhost'".
    host: process.env.DB_HOST || 'localhost',
    user: process.env.DB_USER || 'root',
    password: process.env.DB_PASSWORD || '',
    database: process.env.DB_NAME || 'tienda',
    port: process.env.DB_PORT || 3306,
    waitForConnections: true, // Si las conexiones están ocupadas, la petición espera
    connectionLimit: 10       // Máximo de conexiones simultáneas abiertas
});

// ============================================================================
// 3. ENDPOINTS Y RUTAS
// Usamos 'async (req, res)' en las rutas:
// - 'req' (Request): Trae la información que envía el cliente.
// - 'res' (Response): Objeto que usamos para responderle al cliente.
// - 'async/await': Le dice a Node que espere a MySQL sin congelar el servidor.
// ============================================================================

// ----------------------------------------------------------------------------
// ENDPOINT 1: GET /productos (Obtener todo el catálogo)
// ----------------------------------------------------------------------------
app.get('/productos', async (req, res) => {
    try {
        // Ejecutamos la consulta SQL y esperamos el resultado
        const [rows] = await db.query('SELECT * FROM productos');
        
        // Respondemos al cliente con la lista en JSON y status 200 (OK)
        res.json(rows);
    } catch (error) {
        // En caso de fallar la base de datos, enviamos status 500 (Server Error)
        res.status(500).json({ error: error.message });
    }
});

// ----------------------------------------------------------------------------
// ENDPOINT 2: GET /productos/:id (Obtener por ID en la URL)
// ----------------------------------------------------------------------------
app.get('/productos/:id', async (req, res) => {
    try {
        // Extraemos el ID del parámetro de ruta (Path Parameter)
        const { id } = req.params;

        // VALIDACIÓN: Verificamos si no enviaron ID o si no es un número
        if (!id || isNaN(id)) {
            return res.status(400).json({ 
                error: "El parámetro 'id' en la URL es requerido y debe ser un número válido." 
            });
        }

        // Consulta parametrizada con '?' para prevenir ataques de Inyección SQL
        const [rows] = await db.query('SELECT * FROM productos WHERE id = ?', [id]);
        
        if (rows.length === 0) {
            return res.status(404).json({ mensaje: 'Producto no encontrado' });
        }
        
        res.json(rows[0]);
    } catch (error) {
        res.status(500).json({ error: error.message });
    }
});

// ----------------------------------------------------------------------------
// ENDPOINT 3: GET /productos/buscar/filtro (Búsqueda por Query String)
// ----------------------------------------------------------------------------
app.get('/productos/buscar/filtro', async (req, res) => {
    try {
        // Extraemos la variable enviada en la URL (?nombre=...)
        const { nombre } = req.query;

        // VALIDACIÓN: Verificamos que el parámetro exista y no sean solo espacios
        if (!nombre || nombre.trim() === '') {
            return res.status(400).json({ 
                error: "Debes proporcionar el parámetro de búsqueda 'nombre' en la URL (ej: ?nombre=Lapiz)." 
            });
        }

        // Búsqueda con comodín '%': Encuentra coincidencias parciales de texto
        const [rows] = await db.query('SELECT * FROM productos WHERE nombre LIKE ?', [`%${nombre}%`]);

        res.json(rows);
    } catch (error) {
        res.status(500).json({ error: error.message });
    }
});

// ----------------------------------------------------------------------------
// ENDPOINT 4: POST /productos (Insertar registro desde el Body JSON)
// ----------------------------------------------------------------------------
app.post('/productos', async (req, res) => {
    try {
        // Leemos las propiedades enviadas dentro del cuerpo del JSON
        const { nombre, precio } = req.body;

        // VALIDACIÓN: Campos obligatorios
        if (!nombre || precio === undefined || precio === null) {
            return res.status(400).json({ 
                error: "Los campos 'nombre' y 'precio' son obligatorios en el JSON del body." 
            });
        }

        // VALIDACIÓN: Tipo de dato del precio
        if (isNaN(precio)) {
            return res.status(400).json({ 
                error: "El campo 'precio' debe ser un valor numérico." 
            });
        }

        const [result] = await db.query(
            'INSERT INTO productos (nombre, precio) VALUES (?, ?)',
            [nombre, precio]
        );
        
        // Respondemos con status 201 (Created) e incluimos el ID generado
        res.status(201).json({ 
            id: result.insertId, 
            nombre, 
            precio 
        });
    } catch (error) {
        res.status(500).json({ error: error.message });
    }
});

// ----------------------------------------------------------------------------
// ENDPOINT 5: POST /categorias/:categoriaId/productos (Combinado Path + Body)
// ----------------------------------------------------------------------------
app.post('/categorias/:categoriaId/productos', async (req, res) => {
    try {
        const { categoriaId } = req.params;
        const { nombre, precio } = req.body;

        // VALIDACIÓN: Parámetro de URL
        if (!categoriaId || isNaN(categoriaId)) {
            return res.status(400).json({ 
                error: "El parámetro 'categoriaId' en la URL es requerido y debe ser un número." 
            });
        }

        // VALIDACIÓN: Campos del JSON
        if (!nombre || precio === undefined || precio === null) {
            return res.status(400).json({ 
                error: "Los campos 'nombre' y 'precio' son obligatorios en el JSON del body." 
            });
        }

        if (isNaN(precio)) {
            return res.status(400).json({ 
                error: "El campo 'precio' debe ser un valor numérico." 
            });
        }

        const [result] = await db.query(
            'INSERT INTO productos (nombre, precio) VALUES (?, ?)',
            [nombre, precio]
        );

        res.status(201).json({
            id: result.insertId,
            categoriaId: Number(categoriaId),
            nombre,
            precio
        });
    } catch (error) {
        res.status(500).json({ error: error.message });
    }
});

// ============================================================================
// 4. ARRANQUE DEL SERVIDOR
// ============================================================================

// Leemos el puerto desde process.env (por si la nube asigna uno) o usamos 3000
const PORT = process.env.PORT || 3000;

// Escuchamos en '0.0.0.0' para permitir conexiones desde la red local/laboratorio
app.listen(PORT, '0.0.0.0', () => {
    console.log(`Servidor activo y escuchando en el puerto ${PORT}`);
});

4. Ejecución del Servidor

Una vez creados los archivos y configurada la base de datos, abre tu terminal en la carpeta del proyecto y ejecuta el siguiente comando para poner en marcha la API REST:

node index.js

Si todo está correcto, verás el mensaje de confirmación en la consola:

Servidor activo y escuchando en el puerto 3000
💡 Tip de Desarrollo:

Recuerda que si realizas cambios en el archivo index.js, debes detener el servidor en la terminal presionando Ctrl + C y volver a ejecutar node index.js para que los cambios surtan efecto.

5. Referencia de Endpoints

Método Endpoint Parámetro Uso
GET /productos Ninguno Obtener todo el catálogo.
GET /productos/:id Path (req.params) Buscar un producto por su ID.
GET /productos/buscar/filtro Query (req.query) Filtrar por coincidencia de nombre.
POST /productos Body (req.body) Crear un producto nuevo.
POST /categorias/:categoriaId/productos Path + Body Crear relacionando parámetro en URL.
Notas Clave de Arquitectura:
  • CORS: Habilitado globalmente para evitar fallos cuando el cliente (React, Vue, Flutter, Postman) hace peticiones desde dominios distintos.
  • IP Binding (`0.0.0.0`): Permite escuchar peticiones de cualquier interfaz de red local o pública.
  • Seguridad SQL: Las consultas parametrizadas evitan inyecciones destructivas.
