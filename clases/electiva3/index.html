Tema 1 Introducción a las Bases de Datos

Importancia en aplicaciones web, tipos de BD y su rol en el backend.

Una base de datos (BD) es un conjunto organizado de información que se puede almacenar, consultar y modificar de forma eficiente. En una aplicación web, la BD es el corazón del backend: guarda usuarios, productos, pedidos, sesiones, etc.

¿Por qué es importante en aplicaciones web?

  • Persistencia: los datos sobreviven al cierre del navegador o del servidor.
  • Organización: permite consultar grandes volúmenes sin recorrer archivos.
  • Integridad: reglas que evitan datos duplicados o inconsistentes.
  • Concurrencia: muchos usuarios acceden a la vez sin corromper datos.
  • Seguridad: control de acceso por usuarios y roles.

Relacionales vs. NoSQL

AspectoRelacionales (SQL)NoSQL
EstructuraTablas con filas y columnasDocumentos, clave-valor, grafos, columnas
LenguajeSQLAPIs propias / JSON
EsquemaRígido (definido antes)Flexible
IntegridadFuerte (FK, transacciones)Eventual (según motor)
EjemplosMySQL, PostgreSQL, SQL ServerMongoDB, Redis, Cassandra
Uso típicoDatos estructurados y relacionesDatos semiestructurados y escalado horizontal

Tema 2 Modelo Relacional y Claves

Diseñar tablas, relaciones y claves correctamente desde el inicio.

Tabla (relación)
Conjunto de filas (registros) con las mismas columnas (atributos).
Clave primaria (PK)
Columna que identifica de forma única cada fila.
Clave foránea (FK)
Columna que referencia la PK de otra tabla.
Índice
Estructura que acelera búsquedas sobre una o varias columnas.
Relación 1:N
Un registro se relaciona con muchos de otra tabla.
Relación N:M
Muchos con muchos; requiere una tabla intermedia.

Diagrama entidad-relación del ejemplo

Crear la base de datos y las tablas en MySQL

schema.sql 
-- Crear la base de datos
CREATE DATABASE tienda_web
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

USE tienda_web;

-- Tabla de usuarios: PK autoincremental
CREATE TABLE usuarios (
  id        INT AUTO_INCREMENT PRIMARY KEY,
  nombre    VARCHAR(100) NOT NULL,
  email     VARCHAR(150) NOT NULL UNIQUE,
  password  VARCHAR(255) NOT NULL,
  creado_en DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Tabla de categorías
CREATE TABLE categorias (
  id     INT AUTO_INCREMENT PRIMARY KEY,
  nombre VARCHAR(80) NOT NULL UNIQUE
);

-- Tabla de productos con FK a categorías (relación 1:N)
CREATE TABLE productos (
  id            INT AUTO_INCREMENT PRIMARY KEY,
  nombre        VARCHAR(120) NOT NULL,
  precio        DECIMAL(10,2) NOT NULL,
  stock         INT NOT NULL DEFAULT 0,
  categoria_id  INT,
  FOREIGN KEY (categoria_id) REFERENCES categorias(id)
    ON DELETE SET NULL
    ON UPDATE CASCADE
);

-- Tabla de etiquetas
CREATE TABLE etiquetas (
  id     INT AUTO_INCREMENT PRIMARY KEY,
  nombre VARCHAR(50) NOT NULL UNIQUE
);

-- Tabla intermedia para relación N:M (producto - etiqueta)
CREATE TABLE producto_etiqueta (
  producto_id INT NOT NULL,
  etiqueta_id INT NOT NULL,
  PRIMARY KEY (producto_id, etiqueta_id),
  FOREIGN KEY (producto_id) REFERENCES productos(id) ON DELETE CASCADE,
  FOREIGN KEY (etiqueta_id) REFERENCES etiquetas(id) ON DELETE CASCADE
);
Buenas prácticas: usa utf8mb4 para soportar emojis y caracteres especiales; nombra tablas en plural y columnas en singular; define siempre PK y FK explícitas.

Tema 3 Normalización de Bases de Datos

Aplicar las formas normales para evitar redundancia y anomalías.

La normalización es un proceso de organización de las tablas para reducir la redundancia y evitar anomalías de inserción, actualización y borrado.

FormaReglaEjemplo de violación
1FNValores atómicos, sin listas en una columna.telefonos = "555-123, 555-456"
2FNSin dependencias parciales respecto a la PK compuesta.En (pedido_id, producto_id), guardar nombre_producto que solo depende de producto_id.
3FNSin dependencias transitivas (columnas que dependen de otras no clave).Guardar ciudad y codigo_postal en clientes cuando ciudad depende del CP.

Comparación visual: antes y después

normalizacion.sql 
-- ✅ Solución normalizada (3FN)
CREATE TABLE clientes (
  id     INT AUTO_INCREMENT PRIMARY KEY,
  nombre VARCHAR(100) NOT NULL,
  email  VARCHAR(150) NOT NULL UNIQUE
);

CREATE TABLE pedidos (
  id         INT AUTO_INCREMENT PRIMARY KEY,
  cliente_id INT NOT NULL,
  fecha      DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (cliente_id) REFERENCES clientes(id)
);

CREATE TABLE pedido_detalle (
  pedido_id   INT NOT NULL,
  producto_id INT NOT NULL,
  cantidad    INT NOT NULL,
  PRIMARY KEY (pedido_id, producto_id),
  FOREIGN KEY (pedido_id) REFERENCES pedidos(id),
  FOREIGN KEY (producto_id) REFERENCES productos(id)
);
Ojo: la normalización excesiva puede requerir muchas uniones (JOIN). En la práctica se busca el equilibrio. Para esta unidad, aplica al menos hasta 3FN.

Consultar datos (SELECT)

select.sql 
-- Todos los registros y columnas
SELECT * FROM productos;

-- Columnas específicas
SELECT nombre, precio FROM productos;

-- Filtrar con WHERE
SELECT * FROM productos
WHERE precio > 3
  AND stock > 0;

-- Ordenar resultados
SELECT nombre, precio FROM productos
ORDER BY precio DESC;

-- Limitar resultados
SELECT nombre, precio FROM productos
ORDER BY precio DESC
LIMIT 5;

Actualizar (UPDATE) y eliminar (DELETE)

update_delete.sql 
-- ⚠️ Actualizar SIEMPRE con WHERE para no modificar toda la tabla
UPDATE productos
SET precio = 4.75, stock = stock - 5
WHERE id = 1;

-- Eliminar un registro específico
DELETE FROM productos
WHERE id = 99;

-- Eliminar solo si cumple condición de stock
DELETE FROM productos
WHERE stock = 0;
¡Cuidado! Un UPDATE o DELETE sin WHERE afecta a toda la tabla. Verifica con un SELECT el mismo WHERE antes de ejecutar.

Tema 5 SQL Avanzado · JOINs, Agregados y Subconsultas

Combinar tablas y generar reportes con GROUP BY, HAVING y funciones de agregación.

Tipos de JOIN

Ejemplos de JOIN

joins.sql 
-- INNER JOIN: solo productos con categoría válida
SELECT p.nombre AS producto,
       c.nombre AS categoria,
       p.precio
FROM productos p
INNER JOIN categorias c ON p.categoria_id = c.id;

-- LEFT JOIN: todos los productos, tengan o no categoría
SELECT p.nombre, c.nombre AS categoria
FROM productos p
LEFT JOIN categorias c ON p.categoria_id = c.id;

-- JOIN de tres tablas: productos + categorías + etiquetas
SELECT p.nombre, c.nombre AS categoria, e.nombre AS etiqueta
FROM productos p
INNER JOIN categorias c ON p.categoria_id = c.id
INNER JOIN producto_etiqueta pe ON pe.producto_id = p.id
INNER JOIN etiquetas e ON e.id = pe.etiqueta_id;

Funciones de agregación y GROUP BY

agregados.sql 
-- Contar productos
SELECT COUNT(*) AS total_productos FROM productos;

-- Precio promedio y máximo
SELECT AVG(precio) AS promedio,
       MAX(precio) AS maximo,
       MIN(precio) AS minimo
FROM productos;

-- Agrupar por categoría
SELECT c.nombre AS categoria,
       COUNT(p.id) AS cantidad,
       SUM(p.stock) AS stock_total
FROM categorias c
LEFT JOIN productos p ON p.categoria_id = c.id
GROUP BY c.id, c.nombre
ORDER BY cantidad DESC;

-- HAVING filtra DESPUÉS de agrupar
SELECT categoria_id, COUNT(*) AS total
FROM productos
GROUP BY categoria_id
HAVING total > 3;

Subconsultas

subconsultas.sql 
-- Productos con precio mayor al promedio
SELECT nombre, precio
FROM productos
WHERE precio > (
  SELECT AVG(precio) FROM productos
);

-- Usuarios que han hecho pedidos (EXISTS)
SELECT u.nombre
FROM usuarios u
WHERE EXISTS (
  SELECT 1 FROM pedidos p WHERE p.cliente_id = u.id
);
Recuerda: WHERE filtra filas antes de agrupar; HAVING filtra después de agrupar. No confundas ambos.

Tema 6 Concepto de API · REST y JSON

Qué es una API, tipos, endpoints, métodos HTTP y cómo consumirlas.

Una API (Application Programming Interface) es un conjunto de reglas que permite que dos sistemas se comuniquen. Una API REST expone recursos a través de endpoints (URLs) y usa los métodos HTTP para indicar la acción.

Métodos HTTP y su uso en un CRUD

MétodoAcciónEjemplo endpoint
GETLeer (Read)GET /api/productos
POSTCrear (Create)POST /api/productos
PUT / PATCHActualizar (Update)PUT /api/productos/5
DELETEEliminar (Delete)DELETE /api/productos/5

Flujo de una petición a una API REST

Consumir una API desde JavaScript (fetch)

fetch.js 
// GET: obtener lista de productos desde una API
async function cargarProductos() {
  try {
    const resp = await fetch('https://api.ejemplo.com/productos');

    // fetch NO lanza error en 404/500: hay que revisar resp.ok
    if (!resp.ok) throw new Error('HTTP ' + resp.status);

    const datos = await resp.json();   // convierte respuesta a objeto JS
    console.log(datos);
    datos.forEach(p => console.log(p.nombre, p.precio));
  } catch (err) {
    console.error('Error al consumir API:', err.message);
  }
}

// POST: enviar datos (crear un producto)
async function crearProducto(nuevo) {
  const resp = await fetch('https://api.ejemplo.com/productos', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(nuevo),
  });
  return resp.json();
}

cargarProductos();

Consumir una API desde PHP con cURL

api.php 
<?php
// cURL permite hacer peticiones HTTP desde PHP
$url = 'https://api.ejemplo.com/productos';
$ch = curl_init($url);

curl_setopt($ch, CURLOPT_RETURNTRANSFER, true);
curl_setopt($ch, CURLOPT_TIMEOUT, 10);
curl_setopt($ch, CURLOPT_HTTPHEADER, ['Accept: application/json']);

$respuesta = curl_exec($ch);
$codigo    = curl_getinfo($ch, CURLINFO_HTTP_CODE);
curl_close($ch);

if ($codigo === 200) {
    $datos = json_decode($respuesta, true);
    foreach ($datos as $p) {
        echo "Producto: " . $p['nombre'] . " - $" . $p['precio'] . "<br>";
    }
} else {
    echo "Error al consultar API (HTTP " . $codigo . ")";
}

Tema 7 Conexión entre PHP y MySQL (PDO)

Conectar de forma segura, con consultas preparadas y manejo de errores.

En PHP moderno se recomienda usar PDO (PHP Data Objects) frente a mysqli: soporta varios motores de BD y permite sentencias preparadas que evitan inyección SQL.

Archivo de conexión reutilizable

db.php 
<?php
// Parámetros de conexión (ajusta a tu servidor local)
$host = 'localhost';
$db   = 'tienda_web';
$user = 'root';
$pass = '';
$charset = 'utf8mb4';

$dsn = "mysql:host=$host;dbname=$db;charset=$charset";
$opciones = [
    PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION, // lanza excepciones
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,        // arrays asociativos
    PDO::ATTR_EMULATE_PREPARES   => false,               // preparadas reales
];

try {
    $pdo = new PDO($dsn, $user, $pass, $opciones);
} catch (PDOException $e) {
    // En producción NO mostrar el mensaje real al usuario.
    die('Error de conexión: ' . $e->getMessage());
}

Consultas preparadas: evitar inyección SQL

prepared.php 
<?php
require 'db.php';

// Placeholders con ? (posicionales)
$stmt = $pdo->prepare(
    'SELECT id, nombre, precio FROM productos WHERE precio > ? AND stock > ?'
);
$stmt->execute([3, 0]);
$productos = $stmt->fetchAll();   // array asociativo

foreach ($productos as $p) {
    echo htmlspecialchars($p['nombre']) . ' - $' . $p['precio'] . '<br>';
}

// Placeholders con nombre (más legible)
$stmt2 = $pdo->prepare(
    'SELECT * FROM usuarios WHERE email = :email'
);
$stmt2->execute([':email' => $email]);
$usuario = $stmt2->fetch();
Nunca concatenes datos del usuario en el SQL. Siempre usa prepare() + execute(). Y al mostrar en HTML, aplica htmlspecialchars() para evitar XSS.

Update y Delete

editar_eliminar.php 
<?php
require 'db.php';

// ----- UPDATE -----
if ($_SERVER['REQUEST_METHOD'] === 'POST' && isset($_POST['id'])) {
    $stmt = $pdo->prepare(
        'UPDATE productos SET nombre = ?, precio = ?, stock = ? WHERE id = ?'
    );
    $stmt->execute([
        trim($_POST['nombre']),
        (float)$_POST['precio'],
        (int)$_POST['stock'],
        (int)$_POST['id'],
    ]);
    header('Location: listar.php');
    exit;
}

// ----- DELETE -----
if (isset($_GET['eliminar'])) {
    $id = (int)$_GET['eliminar'];
    $stmt = $pdo->prepare('DELETE FROM productos WHERE id = ?');
    $stmt->execute([$id]);
    header('Location: listar.php');
    exit;
}
Buena práctica: tras un POST exitoso, redirige con header('Location: ...') + exit. Así evitas que al recargar se dupliquen registros (patrón PRG: Post/Redirect/Get).

Tema 9 Validación de Formularios

Validar en frontend (HTML/JS) y en backend (PHP) siempre en conjunto.

Doble validación: cliente y servidor

validar.php 
<?php
$errores = [];
$nombre = $email = $edad = '';

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $nombre = trim($_POST['nombre'] ?? '');
    $email  = trim($_POST['email'] ?? '');
    $edad   = trim($_POST['edad'] ?? '');

    // 1) Nombre: mínimo 3 caracteres
    if (mb_strlen($nombre) < 3) {
        $errores[] = 'El nombre debe tener al menos 3 caracteres.';
    }

    // 2) Email: formato válido
    if (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
        $errores[] = 'El email no es válido.';
    }

    // 3) Edad: entero entre 1 y 120
    $edadInt = filter_var($edad, FILTER_VALIDATE_INT);
    if ($edadInt === false || $edadInt < 1 || $edadInt > 120) {
        $errores[] = 'La edad debe ser un número entre 1 y 120.';
    }

    if (empty($errores)) {
        echo '<p class="ok">Datos válidos: '
           . htmlspecialchars($nombre) . '</p>';
    }
}
?>

  <input name="nombre" value="<?= htmlspecialchars($nombre) ?>" required>

Tema 10 Sesiones y Autenticación Básica

Login con contraseña hasheada y protección de páginas privadas.

Flujo de login

Registro con contraseña hasheada

registro.php 
<?php
require 'db.php';

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $nombre = trim($_POST['nombre']);
    $email  = trim($_POST['email']);
    $clave  = $_POST['password'];

    // NUNCA guardar la contraseña en texto plano
    $hash = password_hash($clave, PASSWORD_DEFAULT);

    $stmt = $pdo->prepare(
        'INSERT INTO usuarios (nombre, email, password) VALUES (?, ?, ?)'
    );
    $stmt->execute([$nombre, $email, $hash]);

    exit;
}

Login y cierre de sesión

login.php 
<?php
session_start();          // SIEMPRE al inicio del archivo
require 'db.php';

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $email = trim($_POST['email']);
    $clave = $_POST['password'];

    $stmt = $pdo->prepare('SELECT id, nombre, password FROM usuarios WHERE email = ?');
    $stmt->execute([$email]);
    $u = $stmt->fetch();

    if ($u && password_verify($clave, $u['password'])) {
        session_regenerate_id(true);   // evita fijación de sesión
        $_SESSION['usuario_id'] = $u['id'];
        $_SESSION['usuario']    = $u['nombre'];
        header('Location: panel.php');
        exit;
    }
    $error = 'Credenciales incorrectas';
}
?>

Tema 11 Introducción a MVC

Separar Modelo, Vista y Controlador para mantener el código ordenado.

MVC (Modelo–Vista–Controlador) es un patrón de arquitectura que divide la aplicación en tres responsabilidades. No es obligatorio, pero facilita el mantenimiento y el trabajo en equipo.

Ejemplo mínimo de estructura MVC

estructura.txt 
proyecto/
├── index.php               ← front controller (enruta)
├── config/
│   └── db.php              ← conexión PDO
├── models/
│   └── Producto.php        ← acceso a datos
├── controllers/
│   └── ProductoController.php
└── views/
    └── productos/
        ├── lista.php
        └── form.php
models/Producto.php 
<?php
class Producto {
    private $pdo;

    public function __construct(PDO $pdo) {
        $this->pdo = $pdo;
    }

    public function todos(): array {
        return $this->pdo
            ->query('SELECT * FROM productos ORDER BY id DESC')
            ->fetchAll();
    }

    public function crear(string $nombre, float $precio): void {
        $stmt = $this->pdo->prepare(
            'INSERT INTO productos (nombre, precio) VALUES (?, ?)'
        );
        $stmt->execute([$nombre, $precio]);
    }
}
controllers/ProductoController.php 
<?php
require_once __DIR__ . '/../models/Producto.php';

class ProductoController {
    private $modelo;

    public function __construct(PDO $pdo) {
        $this->modelo = new Producto($pdo);
    }

    public function index(): void {
        $productos = $this->modelo->todos();
        require __DIR__ . '/../views/productos/lista.php';
    }

    public function guardar(): void {
        $nombre = trim($_POST['nombre'] ?? '');
        $precio = (float)($_POST['precio'] ?? 0);

        if ($nombre !== '' && $precio > 0) {
            $this->modelo->crear($nombre, $precio);
        }
        header('Location: index.php?accion=lista');
        exit;
    }
}
index.php 
<?php
require 'config/db.php';
require 'controllers/ProductoController.php';

$ctrl   = new ProductoController($pdo);
$accion = $_GET['accion'] ?? 'lista';

switch ($accion) {
    case 'guardar': $ctrl->guardar(); break;
    default:          $ctrl->index();   break;
}
Ventajas de MVC: código reutilizable, separación de responsabilidades, facilita pruebas y trabajo en equipo. Frameworks como Laravel o Symfony lo implementan de forma más completa, pero entender el patrón desde cero es clave.

Tema 12 Proyecto Final · Sistema Web para PYME

Ejemplo integrador: guardar cotización de una API en la BD

cotizacion.php 
<?php
require 'config/db.php';

// 1) Consumir API de cotización (ejemplo público)
$url = 'https://api.exchangerate.host/latest?base=USD&symbols=EUR';
$ch  = curl_init($url);
curl_setopt($ch, CURLOPT_RETURNTRANSFER, true);
$json = curl_exec($ch);
curl_close($ch);

$datos = json_decode($json, true);

if (isset($datos['rates']['EUR'])) {
    $eur = (float)$datos['rates']['EUR'];

    // 2) Guardar en BD local
    $stmt = $pdo->prepare(
        'INSERT INTO cotizaciones (par, valor, fecha) VALUES (?, ?, NOW())'
    );
    $stmt->execute(['USD/EUR', $eur]);

    echo "Cotización guardada: 1 USD = $eur EUR";
} else {
    echo 'No se pudo obtener la cotización.';
}
