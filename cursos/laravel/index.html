Creamos las migraciones interconectadas para Clientes, Productos, Facturas y Detalles de Factura:

php artisan make:model Cliente -m
php artisan make:model Producto -m
php artisan make:model Factura -m
php artisan make:model DetalleFactura -m

Esquema transaccional para la tabla facturas:

public function up(): void
{
    Schema::create('facturas', function (Blueprint $table) {
        $table->id();
        $table->foreignId('cliente_id')->constrained();
        $table->string('numero_factura', 30)->unique();
        $table->decimal('total', 12, 2);
        $table->timestamps();
    });
}

3.2. Lógica del Negocio (Controlador con Transacciones)

Implementación segura garantizando descuento automático de inventario al facturar:

use App\Models\Factura;
use App\Models\DetalleFactura;
use App\Models\Producto;
use Illuminate\Support\Facades\DB;

public function store(Request $request)
{
    return DB::transaction(function () use ($request) {
        $factura = Factura::create([
            'cliente_id' => $request->cliente_id,
            'numero_factura' => 'FACT-' . time(),
            'total' => $request->total
        ]);

        foreach ($request->items as $item) {
            DetalleFactura::create([
                'factura_id' => $factura->id,
                'producto_id' => $item['producto_id'],
                'cantidad' => $item['cantidad'],
                'precio' => $item['precio']
            ]);

            // Descontar stock en inventario
            $producto = Producto::find($item['producto_id']);
            $producto->decrement('stock', $item['cantidad']);
        }

        return response()->json(['message' => 'Factura emitida con éxito'], 201);
    });
}
💡 Acotación MySQL
El uso de DB::transaction asegura la atomicidad: si ocurre un fallo al descontar stock, toda la operación de facturación se revierte automáticamente.
API REST Parte 1 (CRUD Completo)

4. API REST Completa con Métodos GET, POST, PUT y DELETE (MySQL)

Registramos un controlador de recursos dedicado en routes/api.php:

use App\Http\Controllers\Api\ProductoApiController;

Route::apiResource('productos', ProductoApiController::class);

Implementación completa del controlador ProductoApiController.php abarcando todas las operaciones HTTP para la gestión de inventario:

namespace App\Http\Controllers\Api;

use App\Http\Controllers\Controller;
use App\Models\Producto;
use Illuminate\Http\Request;

class ProductoApiController extends Controller
{
    // GET /api/productos (Listar todos los productos)
    public function index()
    {
        return response()->json([
            'status' => 'success',
            'data' => Producto::all()
        ], 200);
    }

    // POST /api/productos (Crear un nuevo producto - Método POST)
    public function store(Request $request)
    {
        $validated = $request->validate([
            'nombre' => 'required|string|max:255',
            'precio' => 'required|numeric|min:0',
            'stock' => 'required|integer|min:0'
        ]);

        $producto = Producto::create($validated);

        return response()->json([
            'status' => 'success',
            'message' => 'Producto creado exitosamente',
            'data' => $producto
        ], 201);
    }

    // GET /api/productos/{id} (Mostrar un producto específico)
    public function show(Producto $producto)
    {
        return response()->json([
            'status' => 'success',
            'data' => $producto
        ], 200);
    }

    // PUT /api/productos/{id} (Actualizar un producto existente - Método PUT)
    public function update(Request $request, Producto $producto)
    {
        $validated = $request->validate([
            'nombre' => 'sometimes|required|string|max:255',
            'precio' => 'sometimes|required|numeric|min:0',
            'stock' => 'sometimes|required|integer|min:0'
        ]);

        $producto->update($validated);

        return response()->json([
            'status' => 'success',
            'message' => 'Producto actualizado exitosamente',
            'data' => $producto
        ], 200);
    }

    // DELETE /api/productos/{id} (Eliminar un producto - Método DELETE)
    public function destroy(Producto $producto)
    {
        $producto->delete();

        return response()->json([
            'status' => 'success',
            'message' => 'Producto eliminado exitosamente'
        ], 200);
    }
}
💡 Acotación didáctica sobre API REST
El uso de validaciones previas ($request->validate()) en los métodos POST y PUT garantiza que la API devuelva una respuesta uniforme y estructurada en formato JSON ante cualquier dato erróneo enviado por el cliente.

5.1. Migración Avanzada con JSONB para Auditoría de Facturas

En PostgreSQL incorporamos campos JSONB para almacenar metadatos dinámicos del sistema de facturación (como historial de cambios de estatus o impuestos personalizados):

public function up(): void
{
    Schema::create('auditorias_facturacion', function (Blueprint $table) {
        $table->id();
        $table->foreignId('factura_id')->constrained();
        $table->jsonb('detalles_fiscales'); // Estructura nativa Postgres JSONB
        $table->timestamps();
    });
}
API REST Parte 2 (CRUD y JSONB)

6. API REST Avanzada con Métodos POST, PUT y Manipulación JSONB (PostgreSQL)

Registramos el controlador para las auditorías fiscales en routes/api.php:

use App\Http\Controllers\Api\AuditoriaApiController;

Route::apiResource('auditorias', AuditoriaApiController::class);

Implementación completa del controlador AuditoriaApiController.php manipulando campos nativos jsonb mediante operaciones completas de API REST:

namespace App\Http\Controllers\Api;

use App\Http\Controllers\Controller;
use App\Models\AuditoriaFacturacion;
use Illuminate\Http\Request;

class AuditoriaApiController extends Controller
{
    // GET /api/auditorias (Listar registros de auditoría)
    public function index()
    {
        return response()->json([
            'status' => 'success',
            'data' => AuditoriaFacturacion::all()
        ], 200);
    }

    // POST /api/auditorias (Crear registro con estructura JSONB - Método POST)
    public function store(Request $request)
    {
        $validated = $request->validate([
            'factura_id' => 'required|exists:facturas,id',
            'detalles_fiscales' => 'required|array' // Recibe array asociativo para JSONB
        ]);

        $auditoria = AuditoriaFacturacion::create($validated);

        return response()->json([
            'status' => 'success',
            'message' => 'Auditoría fiscal registrada en PostgreSQL',
            'data' => $auditoria
        ], 201);
    }

    // PUT /api/auditorias/{id} (Actualizar campos o metadatos JSONB - Método PUT)
    public function update(Request $request, AuditoriaFacturacion $auditoria)
    {
        $validated = $request->validate([
            'detalles_fiscales' => 'sometimes|required|array'
        ]);

        $auditoria->update($validated);

        return response()->json([
            'status' => 'success',
            'message' => 'Auditoría actualizada correctamente',
            'data' => $auditoria
        ], 200);
    }

    // DELETE /api/auditorias/{id} (Eliminar registro - Método DELETE)
    public function destroy(AuditoriaFacturacion $auditoria)
    {
        $auditoria->delete();

        return response()->json([
            'status' => 'success',
            'message' => 'Auditoria eliminada exitosamente'
        ], 200);
    }
}
💡 Acotación didáctica final
Con esta implementación completa cubrimos rigurosamente los métodos GET, POST, PUT y DELETE tanto en arquitecturas relacionales puras (MySQL) como en esquemas orientados a documentos y analítica avanzada (PostgreSQL).
