PostgreSQL de Básico a Avanzado

Manual práctico desde consola (psql): comandos esenciales, arquitectura de objetos y ejemplos listos para ejecutar.

1. Nivel Básico: Consola, Tablas y CRUD
Básico

Conexión y Gestión de Bases de Datos

Conéctate a psql, crea una base de datos y muévete hacia ella.

-- Desde la terminal del sistema operativo:
psql -U postgres -h localhost -p 5432

-- Dentro de psql:
CREATE DATABASE empresa_db;
\c empresa_db

-- Metacomandos de inspección rápida:
\l      -- Listar bases de datos
\dt     -- Listar tablas
\dn     -- Listar esquemas
\dv     -- Listar vistas
\df     -- Listar funciones
\q      -- Salir
Básico

Creación de Tablas y Llaves Foráneas

Define entidades relacionadas con tipos de datos estrictos y restricciones de integridad.

CREATE TABLE departamentos (
  id SERIAL PRIMARY KEY,
  nombre VARCHAR(80) UNIQUE NOT NULL
);

CREATE TABLE empleados (
  id SERIAL PRIMARY KEY,
  nombre VARCHAR(100) NOT NULL,
  email VARCHAR(120) UNIQUE NOT NULL,
  salario NUMERIC(10, 2) CHECK (salario > 0),
  departamento_id INT REFERENCES departamentos(id) ON DELETE SET NULL,
  fecha_ingreso DATE DEFAULT CURRENT_DATE
);
Básico

Operaciones CRUD (Create, Read, Update, Delete)

Manipulación fundamental de registros con retorno inmediato mediante RETURNING.

-- CREATE
INSERT INTO departamentos (nombre) VALUES ('Ingeniería'), ('Ventas');

INSERT INTO empleados (nombre, email, salario, departamento_id) VALUES
  ('Ana Torres', 'ana@empresa.com', 3200.00, 1),
  ('Luis Pérez', 'luis@empresa.com', 2800.00, 1),
  ('Carla Gómez', 'carla@empresa.com', 2500.00, 2)
RETURNING id, nombre;

-- READ
SELECT id, nombre, salario FROM empleados WHERE salario >= 2800 ORDER BY salario DESC;

-- UPDATE
UPDATE empleados SET salario = salario * 1.10 WHERE id = 2 RETURNING nombre, salario;

-- DELETE
DELETE FROM empleados WHERE id = 3;
2. Nivel Intermedio: Consultas Relacionales e Índices
Intermedio

Consultas Multitabla (JOINs)

Combina registros entre tablas relacionadas.

-- INNER JOIN: Solo empleados con departamento asignado
SELECT e.nombre AS empleado, d.nombre AS departamento, e.salario
FROM empleados e
INNER JOIN departamentos d ON e.departamento_id = d.id;

-- LEFT JOIN: Todos los departamentos, incluso si no tienen empleados
SELECT d.nombre AS departamento, e.nombre AS empleado
FROM departamentos d
LEFT JOIN empleados e ON d.id = e.departamento_id;
Intermedio

Agregación y Agrupamiento (GROUP BY / HAVING)

Calcula métricas resumidas por grupo y filtra resultados agregados.

SELECT
  d.nombre AS departamento,
  COUNT(e.id) AS total_empleados,
  ROUND(AVG(e.salario), 2) AS salario_promedio,
  SUM(e.salario) AS nomina_total
FROM departamentos d
LEFT JOIN empleados e ON d.id = e.departamento_id
GROUP BY d.nombre
HAVING COUNT(e.id) >= 1;
Intermedio

Índices (Indexes)

Aceleran las búsquedas y ordenamientos en columnas frecuentemente consultadas.

-- Crear índice B-Tree estándar
CREATE INDEX idx_empleados_departamento ON empleados(departamento_id);

-- Crear índice parcial (solo indexa registros que cumplen una condición)
CREATE INDEX idx_salarios_altos ON empleados(salario) WHERE salario > 3000;

-- Analizar el plan de ejecución de una consulta
EXPLAIN ANALYZE SELECT * FROM empleados WHERE departamento_id = 1;
3. Objetos de PostgreSQL (Creación y Uso)
Objeto · Schema

Esquemas (Namespaces lógicos)

Permiten organizar tablas y objetos en grupos lógicos dentro de una misma base de datos (por defecto todo se crea en public).

-- Crear esquema
CREATE SCHEMA auditoria;

-- Crear tabla dentro del esquema
CREATE TABLE auditoria.logs_acceso (
  id SERIAL PRIMARY KEY,
  usuario VARCHAR(50),
  fecha TIMESTAMPTZ DEFAULT NOW()
);

-- Uso:
INSERT INTO auditoria.logs_acceso (usuario) VALUES ('ana@empresa.com');
SELECT * FROM auditoria.logs_acceso;
Objeto · Sequence

Secuencias (Sequences)

Generadores de números únicos incrementales útiles para folios, facturas o códigos personalizados.

-- Crear secuencia que inicia en 1000 y avanza de 5 en 5
CREATE SEQUENCE seq_factura START 1000 INCREMENT 5;

-- Uso:
SELECT nextval('seq_factura'); -- Devuelve 1000
SELECT nextval('seq_factura'); -- Devuelve 1005
SELECT currval('seq_factura'); -- Consulta el valor actual (1005)
Objeto · Type

Tipos de Datos Personalizados (ENUM y Compuestos)

Restringen valores permitidos a nivel de tipo de dato en toda la base de datos.

-- Crear tipo ENUM
CREATE TYPE estado_pedido AS ENUM ('pendiente', 'procesando', 'enviado', 'entregado');

-- Uso en una tabla:
CREATE TABLE pedidos (
  id SERIAL PRIMARY KEY,
  codigo VARCHAR(20),
  estado estado_pedido DEFAULT 'pendiente'
);

INSERT INTO pedidos (codigo, estado) VALUES ('PED-01', 'enviado');
Objeto · View

Vistas Estándar (Views)

Consultas guardadas que actúan como tablas virtuales; no almacenan datos físicos, sino que ejecutan la consulta al ser llamadas.

-- Crear o reemplazar vista
CREATE OR REPLACE VIEW vw_directorio_empleados AS
SELECT
  e.id,
  e.nombre AS empleado,
  e.email,
  COALESCE(d.nombre, 'Sin asignar') AS departamento
FROM empleados e
LEFT JOIN departamentos d ON e.departamento_id = d.id;

-- Uso (se consulta exactamente igual que una tabla):
SELECT * FROM vw_directorio_empleados WHERE departamento = 'Ingeniería';
Objeto · Materialized View

Vistas Materializadas (Materialized Views)

Almacenan físicamente el resultado de una consulta pesada en disco para lecturas instantáneas. Deben refrescarse manualmente.

-- Crear vista materializada
CREATE MATERIALIZED VIEW mv_resumen_nomina AS
SELECT
  d.nombre AS departamento,
  COUNT(e.id) AS empleados,
  SUM(e.salario) AS total_salarios
FROM departamentos d
LEFT JOIN empleados e ON d.id = e.departamento_id
GROUP BY d.nombre;

-- Uso:
SELECT * FROM mv_resumen_nomina;

-- Actualizar datos cuando cambian las tablas base:
REFRESH MATERIALIZED VIEW mv_resumen_nomina;
Objeto · Function

Funciones (PL/pgSQL Functions)

Encapsulan lógica reutilizable que recibe parámetros, realiza cálculos o consultas y devuelve un valor o tabla.

-- Crear función para calcular bono anual (15%)
CREATE OR REPLACE FUNCTION calcular_bono(p_salario NUMERIC, p_porcentaje NUMERIC DEFAULT 0.15)
RETURNS NUMERIC AS $$
BEGIN
  RETURN ROUND(p_salario * p_porcentaje, 2);
END;
$$ LANGUAGE plpgsql;

-- Uso dentro de un SELECT:
SELECT nombre, salario, calcular_bono(salario) AS bono FROM empleados;
Objeto · Procedure

Procedimientos Almacenados (Stored Procedures)

A diferencia de las funciones, no devuelven un valor directamente, se ejecutan con CALL y permiten controlar transacciones (COMMIT / ROLLBACK).

-- Crear procedimiento para aumentar salario por departamento
CREATE OR REPLACE PROCEDURE aumentar_salario_depto(p_depto_id INT, p_incremento NUMERIC)
LANGUAGE plpgsql AS $$
BEGIN
  UPDATE empleados
  SET salario = salario + p_incremento
  WHERE departamento_id = p_depto_id;
  COMMIT;
END;
$$;

-- Uso:
CALL aumentar_salario_depto(1, 250.00);
Objeto · Trigger

Disparadores (Triggers)

Ejecutan automáticamente una función especial antes (BEFORE) o después (AFTER) de un evento INSERT, UPDATE o DELETE.

-- 1. Crear tabla de historial
CREATE TABLE historial_salarios (
  id SERIAL PRIMARY KEY,
  empleado_id INT,
  salario_anterior NUMERIC,
  salario_nuevo NUMERIC,
  fecha_cambio TIMESTAMPTZ DEFAULT NOW()
);

-- 2. Crear la función del trigger
CREATE OR REPLACE FUNCTION registrar_cambio_salario()
RETURNS TRIGGER AS $$
BEGIN
  IF NEW.salario <> OLD.salario THEN
    INSERT INTO historial_salarios (empleado_id, salario_anterior, salario_nuevo)
    VALUES (OLD.id, OLD.salario, NEW.salario);
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 3. Vincular el trigger a la tabla empleados
CREATE TRIGGER trg_auditar_salario
AFTER UPDATE ON empleados
FOR EACH ROW
EXECUTE FUNCTION registrar_cambio_salario();

-- Uso (se dispara solo al actualizar un salario):
UPDATE empleados SET salario = 4000.00 WHERE id = 1;
SELECT * FROM historial_salarios;
4. Nivel Avanzado: Transacciones, Analítica, JSONB y Seguridad
Avanzado

Transacciones y Puntos de Guardado (Savepoints)

Garantizan que un bloque de operaciones se ejecute por completo o se revierta sin dejar datos corruptos. 

BEGIN;
UPDATE empleados SET salario = salario - 200 WHERE id = 1;
SAVEPOINT punto_seguro;

-- Operación errónea o que deseamos deshacer parcialmente:
DELETE FROM empleados WHERE id = 2;
ROLLBACK TO SAVEPOINT punto_seguro;

-- Confirmar los cambios válidos:
COMMIT;
Avanzado

CTEs (WITH) y Funciones de Ventana (Window Functions)

Permiten escribir consultas complejas legibles y realizar rankings o cálculos sobre particiones sin colapsar las filas.

WITH ranking_salarios AS (
  SELECT
    e.nombre,
    d.nombre AS departamento,
    e.salario,
    RANK() OVER (PARTITION BY d.nombre ORDER BY e.salario DESC) AS posicion
  FROM empleados e
  JOIN departamentos d ON e.departamento_id = d.id
)
SELECT * FROM ranking_salarios WHERE posicion = 1;
Avanzado

Almacenamiento y Consulta de JSONB

PostgreSQL permite almacenar documentos JSON binarios indexables y consultar sus claves directamente en SQL.

CREATE TABLE perfiles_tecnicos (
  empleado_id INT PRIMARY KEY REFERENCES empleados(id),
  habilidades JSONB
);

INSERT INTO perfiles_tecnicos VALUES
  (1, '{"lenguajes": ["Python", "SQL"], "remoto": true, "experiencia": 5}');

-- Consultar claves dentro del JSONB y crear índice GIN
CREATE INDEX idx_habilidades_gin ON perfiles_tecnicos USING GIN (habilidades);

SELECT empleado_id, habilidades->>'experiencia' AS anios
FROM perfiles_tecnicos
WHERE habilidades @> '{"remoto": true}';
Avanzado

Administración de Roles y Permisos (DCL)

Control granular de seguridad siguiendo el principio de mínimo privilegio.

-- Crear usuario de solo lectura
CREATE ROLE analista_lectura WITH LOGIN PASSWORD 'ClaveSegura2026!';

-- Otorgar acceso a la base de datos y permisos SELECT
GRANT CONNECT ON DATABASE empresa_db TO analista_lectura;
GRANT USAGE ON SCHEMA public TO analista_lectura;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO analista_lectura;

-- Revocar permisos
REVOKE INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public FROM analista_lectura;
